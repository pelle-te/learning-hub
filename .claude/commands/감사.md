`$ARGUMENTS`(비면 **허브 전체**)를 "수석 아키텍처 리뷰 위원회" 관점으로 다각도 감사한다.
얕은 린트·오타가 아니라 **구조적 결함·중복·개선기회·최적화·규약 드리프트·확장 방향**을 찾는다.

> **이 명령이 진단 계열의 단일 창구다** — 옛 `/리뷰`(결함)·`/평가`(점수)는 여기 **모드로 흡수**됐다
> (2026-07-25 통합). 발전 계열(향상·새 아이디어)은 `/개선`, 게이트 실행은 `/게이트`가 각각 맡는다.
> 세 명령의 경계: **감사=지금 어떤가 · 개선=다음에 뭘 · 게이트=통과인가.**

**인자는 축 셋이다** — `범위` × `깊이` × `산출`. **순서는 상관없고** 조합만 맞으면 된다:
`/감사 빠른 diff`(방금 변경분만 싸게) · `/감사 근본 sync`(동기화 코어를 전제부터) ·
`/감사 deep`(전체를 전제부터 — `근본`과 `deep` 은 **같은 말**이다) · `/감사 features/today 점수`(채점).

| 축 | 값 | 뜻 |
| --- | --- | --- |
| **범위** | 비움=허브 전체 · `web` · `server` · `sync` · 경로 · `diff` | §1 이 해석 |
| **깊이** | **`빠른`**(=옛 `/리뷰`) · 기본(17렌즈) · **`근본`/`deep`**(§0 · 전제 재검증 + F1~F6) | 아래 §0.5·§0 |
| **산출** | 발견(기본) · **`점수`**(=옛 `/평가` · 루브릭 채점 + 추세 기록) | §0.5 |

깊이 기본값은 **기본(17렌즈)** 이다. `근본`은 현 설계를 전제하지 않고 메커니즘 자체를 재설계 후보로
올린다(§3 재지적 금지가 꺼진다). `빠른`은 그 반대 끝 — 좁은 범위를 싸게 훑는다.

**실행 순서 (건너뛰지 말 것 · 각 단계가 다음 단계의 입력이다)**

```
① 범위 확정 + 지난 감사 델타(§1)   ← 안 하면 같은 발견을 재발행하고 회귀를 놓친다
② 실물 읽기 + 17렌즈 팬아웃(§2)     ← web 은 에이전트 동시, 접점·시제 렌즈는 메인
③ 교차검증: 중복병합·실물확인·상충판정(§2.5)  ← 여기서 거짓 양성이 걸러진다
④ 리포트(§4) — 0번 커버리지 표부터   ← 안 본 축을 눈에 보이게
⑤ 착지(§4-9)·완료 계약(§5)          ← 승인 없이 끝난 발견도 문서로 보낸다
```

## 0. 🏗️ 근본(deep) 모드 — 인자에 `근본`/`deep` 이 있을 때만 발동

기본 모드는 "현 설계 안에서 뭐가 틀렸나"만 본다. 근본 모드는 전제를 뒤집어 **"이 설계·메커니즘이
애초에 맞나, 더 단순한/옳은 게 있나"**를 묻는다.

⚠ **근본 모드는 기본 모드의 *대체*가 아니라 *덧셈*이다.** §1(범위·지난 감사 델타) · §2(17렌즈) ·
**§2.5(교차검증)** · §3(증거 등급 — 근본 모드에서 특히 중요하다: 재설계 제안은 `[추정]` 이 섞이기
가장 쉬운 종류다) · §4-0(커버리지 표) · §4-9(착지) · §5(게이트)를 **전부 그대로 수행한 뒤** 아래를
더한다. 아래는 기본 모드와 **다른 점만** 적은 것이다:

- **§3 재지적 금지를 끈다 — 대신 "전제 재검증"으로 바꾼다.** 결정로그·설계서가 반박한 결정도
  다시 도마에 올린다. 단 **근거를 무시하는 게 아니라** *그 반박이 지금도 유효한지*를 검증한다
  (기기 수·데이터 규모·호스트·사용자 요구가 그동안 바뀌었을 수 있다). "옛날엔 맞았는데 전제가
  변했다"를 명시적으로 찾는 것이 이 모드의 핵심 산출물이다.
- **기존 메커니즘 = 제약이 아니라 가설.** "왜 이렇게?"가 아니라 "이게 필요한가 / 대체 가능한가"를
  묻는다. 다음 근본 렌즈를 추가로 돌린다:
  - **(F1) 메커니즘 필요성** — 이 기계가 존재해야 하나? 1인·소수기기 앱에 **과설계**된 하위
    시스템은? (예: 저장 백엔드 3분할·엔트리 2개·추상 계층의 실이득)
  - **(F2) 대안 설계** — 근본적으로 더 단순하거나 옳은 모델이 있나? (예: 동기화 모델·데이터 모델·
    상태 관리·경계 구조를 통째로 바꾸면?)
  - **(F3) 우발적 복잡도** — 역사적 경로 때문에 남은 복잡도(마이그레이션 잔재·이중 경로·죽은 유연성).
  - **(F4) 전제 재검증** — 설계서의 "결정과 근거"들을 오늘의 제약으로 다시 채점. 유효/무효 판정.
  - **(F5) 컴포넌트 재설계 후보 (책임 이전)** — F1~F4 가 *시스템 기계*라면 이건 *컴포넌트/함수* 단위다.
    큰 컴포넌트 안에 **자기완결 상호작용 상태기계**(키보드 네비·드래그드롭·팝오버 셀렉션·위저드 스텝)나
    **순수 로직 다책임**이 엉켜 있나? 작은 인터페이스(**≤8, 불투명 콜백**)로 자기 상태·이벤트를
    **소유하는** 컴포넌트/훅으로 뺄 수 있으면 후보다(실제 성공례: `FlowRail`·`ReaderVocab`·`useTimeboxDnd`).
    ⚠ **판별의 핵심**: 옮길 것이 **부모 지역변수를 참조하지 않아야** 한다 — 참조하면 = prop-drilling =
    응집을 결합으로 바꿔 **더 나빠짐**(후보 아님). 인라인 조건부 위젯 렌더(`{x && <W/>}` ×N, 지역변수
    10+ 의존)·공유 가변상태를 나눠 쓰는 명령형(스케줄러 페이즈 등)·이미 분해된 것은 후보가 아니다.
  - **(F6) 검증 체계 자체의 재배치** — 렌즈 17 의 근본 버전. 어떤 검사가 **정당화되는 층보다 비싼 층에**
    있나? 실사고: 트랙 B 가 16개까지 불어나 있었는데 대부분은 GUI 가 필요해서가 아니라 *실물*이
    필요해서였다 — GUI 를 테스트 하네스로 쓰다 회당 앱 기동 19번을 냈고, `cargo test` 로 내리자
    초 단위가 됐다. 같은 질문을 지금의 게이트 전 단계에 다시 던진다(무엇이 어느 층에 있어야 하나).
- **17렌즈를 근본 질문으로 뒤집는다** — F1~F6 은 *렌즈에 없는 각도*를 더하는 것이고, 이 표는 *있는
  렌즈를 다른 시제로 다시 묻는 것*이다. 근본 모드에서는 둘 다 돈다:

  | 기본 렌즈 | 근본 질문(전제를 뒤집으면) |
  | --- | --- |
  | 1 정합성 | LWW+툼스톤+fence 가 옳은 모델인가? 시계를 믿는 대신 **논리시계·서버권위·CRDT** 는? 충돌이 애초에 생기는 데이터 모델인가? |
  | 2 성능 | 지금 최적화하는 대상이 병목이 맞나? 1인 규모에서 **재계산·캐시 층 자체가 불필요**한 곳은? |
  | 3 설계 | 레이어 5분할·features **N개**(세고 시작하라 — `ls web/src/features`)가 이 규모에 맞나? 경계가 **문제를 나눈** 건가 **파일을 나눈** 건가? |
  | 4 보안 | 인증 모델(PSK·토큰·기기 등록)이 1인 앱에 맞는 형태인가? 노출면을 **없애는** 대안(로컬 전용 경로)은? |
  | 5 UX | 탭 로스터(**정본 = `web/src/shell/tabs.ts`** · 수를 여기 적지 않는다)라는 **정보구조 자체**가 "한눈에"와 모순되나? |
  | 7 테스트 | 6겹 검증이 전부 값을 하나? **어느 겹을 지워도** 실사고가 안 늘 것 같은가(F6 의 짝) |
  | 10 스키마 | 전진 전용 마이그레이션이 맞나? 다운그레이드를 **지원할 것인가 포기를 명시할 것인가**(지금은 미정의다) |
  | 11 실패 | 실패를 경로마다 처리하는 대신 **한 층에서 표면화**하는 모델은? 오프라인 우선이면 "실패"가 아닌 것이 있나 |
  | 12 수명 | 장기 실행을 전제로 만들 것인가, **주기적 재시작을 전제**로 단순화할 것인가 |
  | 13 시간 | "하루"가 앱 전역 개념인데 왜 유틸 함수인가? **도메인 타입(DayKey)** 으로 올려 오용을 컴파일에서 막을 수 있나 |
  | 14 디자인 | 토큰·유틸 2층이 맞나? 파생 규칙(OKLCH)을 **더 밀어** 하드코딩 여지를 원천 제거할 수 있나 |
  | 15 제품 | 이 앱이 하나의 앱이어야 하나, 아니면 **덜 하는 앱**이어야 하나(죽은 탭 은퇴는 기능 추가만큼 값어치 있다) |
  | 16 프라이버시 | 이 데이터가 **애초에 기기 밖으로 나가야 하나**(텔레메트리·AI·클라우드 각각) |
  | 6·8·9·17 | 규약·검증·관측 체계 자체 → **F6** 이 담당 |

- **핵심 기계를 통째로 재설계 후보로 올린다** — 동기화 모델(LWW+툼스톤+fence)·데이터 모델·엔트리
  분할·저장 백엔드 구성·레이어 구조 어느 것도 성역이 아니다.
- **정직 계약**: 재작성을 위한 재작성 금지. **모든 걸 도마에 올린 뒤**, 기존이 실은 옳으면
  "옳다 + 그 근거가 지금도 유효"라고 판정한다(그게 §5 로 간다). 차이는 *결론*이 아니라 *전부
  의심했다는 과정*이다.
- **⚠ 복잡도 지표를 오라클로 착각하지 말 것 (2026-07-24 실측 교훈, F5 전용)**: SonarJS 인지복잡도는
  **함수 단위**다. 추출이 그 숫자를 내리는 건 옮긴 것이 컴포넌트의 **직접 본체**(상태·effect·인라인
  조건부 렌더)에 있었을 때뿐이고, **중첩 함수**(이벤트 핸들러·콜백·map 본체)는 애초에 부모 숫자에
  안 잡혀 빼도 **안 내려간다**(FlowRail 77→77·useTimeboxDnd 41→41 vs ReaderVocab 77→45 로 실증).
  ① **지표가 안 내려가도 재설계는 실개선일 수 있다**(응집·테스트성·가독성) — 지표만으로 성패를 판정 말 것.
  ② 측정은 반드시 **전체-src**(`eslint src --rule '{"sonarjs/cognitive-complexity":[...]}'`)로 — **파일
  단독**(`eslint <file> --rule`)은 sonarjs 플러그인이 안 올라와 **거짓 음성(룰 미실행)**을 낸다(한 번 물림).
  ③ 재설계는 **렌더 동일(트랙A)**로 검증하고, 스냅샷이 못 보는 상호작용(키보드·드래그·선택)엔
  **오라클 테스트**를 붙인다 — 이게 F5 착수의 완료 계약이다.
- **유일하게 유지하는 가드레일(CLAUDE.md #4 의 축소판)**: **되돌리기 힘든/유실 위험 있는 코어**
  (데이터 이관·동기화 정합·스키마 마이그레이션)의 재설계는 **"제안 → 승인 → 실행"**. 사용자
  결정이 신성해서가 아니라, *리뷰 없는 동기화 코어 재작성*이 이 저장소가 반복해 물린 실패 계열이라서.
  그 외(리팩터·추상 제거·구조 개편)는 승인 후 자유롭게 실행한다.
- **서브에이전트**: `web-improver`(단순화·능력확장 렌즈가 근본 질문에 가장 가깝다)를 근본 프롬프트로
  돌리고, 메커니즘 대안은 **메인이 직접** 설계한다(에이전트는 파일 단위라 크로스-서브시스템 재설계엔
  약하다). 필요하면 `Plan` 에이전트로 대안 설계안을 병렬 생성해 비교한다.

## 0.5 `빠른` 모드 · `점수` 모드 — 옛 `/리뷰`·`/평가` 흡수분

### `빠른` (=옛 `/리뷰`) — 좁게, 싸게
- **언제**: 방금 쓴 변경분·feature 하나. 17렌즈 전수가 과할 때. 기본 짝은 `/감사 빠른 diff`.
- **렌즈 4종만**: 1 정확성 · 2 성능 · 3 설계/레이어 경계 · 5 UX/a11y. 팬아웃은 `web-reviewer`
  4관점을 **한 메시지 동시**(옛 `/리뷰` 그대로).
- **생략**: §1 지난 감사 델타 · §4-0 커버리지 표(대신 "본 렌즈 4종" 한 줄) · §4-4 원장/패리티 ·
  §4-6 넥스트 스텝 · §4-8 검증 사각(범위가 좁아 값이 안 나온다).
- ⚠ **생략하면 안 되는 것**: §2.5 교차검증 · §3 증거 등급 · §4-2 Critical · §4-9 착지.
  이 넷을 빼면 *싼* 리포트가 아니라 **틀린** 리포트가 된다(에이전트 발견을 검증 없이 싣게 된다).
- **출력**: 심각도순 짧은 목록 `[파일:라인 → 실패 시나리오 → 처방]` + 증거 등급. 본문 덤프 금지.
- ⚠ 빠른 모드에서 **Critical 이 나오면 그 자리에서 기본 모드 승격을 제안한다** — 좁게 봐서 놓친
  접점이 있을 수 있다(이 저장소의 결함은 대개 접점에 있다).

### `점수` (=옛 `/평가`) — 채점과 추세
- `web/docs/평가루브릭.md` 를 읽고 분기: `features/<탭>`=**A(7차원/35)** · `lib/<모듈>`=**B(5차원/25)** ·
  `diff`=변경된 대상을 각각 그 종류로.
- **독립 채점(작업자≠검사자)**: `web-evaluator` 를 **차원별 병렬 팬아웃**. 각 에이전트에는
  **대상 경로 + 해당 차원 정의만** 준다 — 한 차원만 깊게 봐야 다각도가 서로 오염되지 않는다.
  대상이 여럿이면 (대상 × 차원)으로.
- **증거 한 줄 필수.** 실행·측정 없이 판단한 정확성·성능·테스트 차원은 **N/A** 로 돌려받는다(만점 금지).
  필요하면 `npm run test`·`npm run budget` 을 **실제로 돌려** 증거를 남긴다(§3 등급 `[측정]`).
- **집계**: 차원별 점수(N/A 는 분모에서 제외)·총점 %·**약한 차원**을 표로. 착지처는
  `web/docs/평가기록.md`(날짜·범위·커밋 SHA·최신이 위) — 추가 여부는 사용자 확인(§4-9).
- ⚠ **점수는 모델 판단이라 공유 맹점이 있다.** 절대 등급이 아니라 **추세 진단**으로 쓰고, 사람
  교차검증을 권한다. **점수를 위한 과적합 금지** · 자기 코드 자기 채점 금지를 리포트에 재확인한다.
- `점수` 는 깊이 축과 **함께** 쓴다: `빠른 점수` = 옛 `/평가` 와 동등 · 기본+`점수` = 발견과 채점 동시.

   **정적·합성 검증의 맹점**을 매 감사가 명시적으로 센다. 6종 taxonomy:
   ① **상태 의존 시각** — 스냅샷은 기본/닫힌 상태만 찍는다(팝오버 위치·선택 하이라이트·드롭 프리뷰·

     타겟·관성 스크롤을 못 본다.
   ③ **실 백엔드 IO** — 모킹된 AI·네트워크·파일 왕복(응답 형태·타임아웃·부분 실패·스트리밍 순서).
   ④ **WebView2(셸) vs Chromium** — 트랙A는 Chromium이라 feature 탭의 키보드·선택·DnD·폰트·CSP가
     실 셸에서 다를 수 있다(트랙B는 창·라우팅·IPC만 보고 feature 렌더는 안 본다).
   ⑤ **실 브라우저 API** — jsdom 목업 ≠ 실물(getSelection range·다중노드·IntersectionObserver·
     ResizeObserver·`scrollIntoView`·포커스 순서·matchMedia 라이브 갱신).
   ⑥ **비결정 타이밍** — 레이스·경합·순서 의존(병합 중 편집, 디바운스↔플러시 겹침). 로직은 테스트가
     잠그지만 **실 동시성 창은 재현 불가** — 방어 *논리*로만 확인된다.
   → 각 발견·각 변경이 이 6종 중 어디에 걸리는지 표시하고, **닫는 법(사람 눈/실기기/원리적 불가)**을 병기한다.
9. **배포 후 (시제) — 관측·전달·기한부 판단 (2026-07-25 신설)** — 이 저장소의 최대 비대칭은 코드 품질이
   아니라 **시제**였다: 배포 *전* 검증은 여섯 겹인데(정적·유닛·컴포넌트·트랙A·트랙B·실 workerd 왕복)
   배포 *후* 관측은 0 이었다. 렌즈 8 이 "게이트가 못 보는 것"이라면 이건 **"게이트가 끝난 뒤"**다.

   - **관측** — 에러가 어디에 기록되나(`web/src/lib/telemetry.ts` ↔ server `/api/log`)? `ErrorBoundary`·
     전역 훅(`error`·`unhandledrejection`)이 폴백만 그리고 **조용히 삼키는** 자리는? catch 후
     아무 데도 안 알리는 경로는? 로그가 실제로 서버에 닿는지(경로가 살아 있는지) 확인한다.
   - **전달** — 결함을 *알게 됐을 때* 사용자에게 갈 경로가 있나(`src-tauri/src/updater.rs`·설정 UI·
     서명키 절차 `web/docs/릴리스.md`). **관측 없는 전달·전달 없는 관측은 반쪽이다**(둘은 짝이다).
   - **기한부 판단 원장** — `web/audit-allowlist.json` · `server/audit-allowlist.json` ·
     `web/e2e/a11y.spec.ts` 의 `알려진위반`. 각 항목을 **만료일 전에도** 본다:
     ① 만료 임박/경과 ② **사문화**(이미 해소됐는데 남아 있음) ③ **사유가 코드와 어긋남**
     (예: "취약 경로가 존재하지 않는다"고 적었는데 그 경로가 생김 · "peer 하나가 막는다"의 그 peer 가 풀림).
     ⚠ 게이트는 **만료일에만** 반응한다 — ②③ 은 원리적으로 못 본다. **원장을 읽는 것은 감사뿐이다.**
     판단에 유효기간이 없으면 그건 판단이 아니라 방치다.

## 2.5 교차검증 — 팬아웃 결과를 그대로 싣지 않는다 (거짓 양성 필터)

서브에이전트는 파일 일부만 보고 판단한다 → **존재하지 않는 결함**·이미 다른 층이 막고 있는 결함·
같은 것을 다른 이름으로 부른 중복을 낸다. 리포트 신뢰도는 여기서 결정된다. 순서:

1. **중복 병합** — 같은 파일·같은 원인은 한 건으로. 렌즈가 달라도 원인이 같으면 한 건이다.
2. **실물 확인** — 각 발견의 **파일을 메인이 직접 열어** 라인·조건·주변 가드를 확인한다. 못 열어 봤으면
   싣지 말거나 `[추정]` 으로 강등한다. ⚠ 특히 "이 검사가 없다"류 주장은 **다른 층에 있는 경우가 잦다**
   (린트 룰·zod 스키마·Rust 쪽·CI). 없다고 말하기 전에 그 층들을 grep 한다.
3. **상충 판정** — 에이전트끼리 반대되는 처방을 냈으면(예: 추출하라 ↔ 응집 유지) **메인이 근거로 판정**하고
   진 쪽도 한 줄로 남긴다(다음 감사가 같은 논쟁을 반복하지 않게).
4. **§3 재지적 필터** — 결정로그·설계서·머리주석이 이미 근거와 함께 반박한 건은 여기서 걸러 §4-5 로 보낸다.

## 3. 반드시 지킬 규칙
- **이미 주석·결정로그·설계서에 근거와 함께 반박된 결정은 재지적 금지.** 그건 "왜 이미 충분한가"로만 짚고 진짜 새 발견에 지면을 쓴다(이 저장소의 최대 함정).
- 각 발견은 **[파일:라인 → 실패 시나리오(구체적 입력→잘못된 결과) → 처방(스니펫/방향)]**. 추상 조언·본문 덤프 금지.
- **증거 등급을 매 건에 붙인다** — `[측정]`(수치·명령 출력 있음) · `[재현]`(테스트·실행으로 확인) ·
  `[읽음]`(코드를 직접 열어 확인) · `[추정]`(미확인 — **검증 방법 병기 필수**). 등급 없는 단정은 금지.
  이 한 글자가 "리포트가 다 맞는 것처럼 읽히는" 문제를 막는다.
- **CLAUDE.md 절대규칙 준수** — 특히 #4(명시 결정 임의변경 금지)·레이어 경계·색 파생·인덱스 위생.
- 규약/문서 수정은 **의미가 바뀌는 편집**이라 반드시 착수 전 승인. SSOT가 갈리지 않게 "어느 문서가 정본인가"를 먼저 밝힌다.
- **게이트·테스트를 돌린다면 팬아웃이 전부 끝난 뒤에.** 서브에이전트가 파일을 쓰는 동안 돌린 게이트는
  시점에 의존해 **flaky 를 결함으로, 결함을 flaky 로** 읽는다(실측: `verify` 4건 실패 → 재실행 전량 통과).
- **복잡도 측정은 전체-src 로**(`eslint src --rule …`) — 파일 단독은 sonarjs 가 안 올라와 **거짓 음성**을 낸다.

## 5. 완료 계약
읽기 전용으로 발견을 먼저 보고한다. 착수는 **범위 승인 후** — 해당 protocol(기능추가·재설계 등)을 따르고,
아래가 **녹색이어야만** "됐다"고 말한다. ⚠ **게이트 목록을 기억으로 적지 말 것** — 2026-07-25 에 층이
늘었고(SCA·a11y), 옛 목록(`verify`+`build`+`budget`+`e2e`)은 그 둘을 빠뜨린다:
- **`cd web && npm run gate`** — **단계 목록의 정본은 `web/scripts/gate.mjs` 의 `ALL` 배열이다.**
  ⚠⚠ **여기에 단계를 베껴 적지 말 것.** 이 자리가 실제로 두 번 낡았다(2026-08-07 실측):
  옛 문구가 `cargo test` 를 _"gate 가 안 돌려준다"_, `server verify` 를 _"gate 밖이다"_ 라 적고
  있었는데 **둘 다 이미 `ALL` 안**이다(F6 · 2026-07-31 / 패리티 사고 · 2026-08-01), `server audit`
  은 2026-08-06 에 더 들어왔다. 즉 완료 계약이 **완료의 정의를 축소 보고**하고 있었다 —
  이 저장소가 게이트 문서에서 반복해 물린 바로 그 형태이고, `gate.mjs` 자신이 같은 이유로
  목록을 데이터로 만들었다(H-23).
  ⚠ **`verify` 만 녹색인 건 완료가 아니다**(SCA·a11y·시각회귀·실물 왕복이 그 밖이다).
- **단독 실행이 필요한 자리**(게이트에 들었어도 빨리 돌려 보고 싶을 때):
  `cargo test --manifest-path src-tauri/Cargo.toml --lib`(실물 통합 — **개수를 적지 않는다**) ·
  `cd server && npm run verify`(실 workerd·D1 왕복). 둘 다 지금은 `gate` full 이 이미 돈다.
- 동기화 코어를 만졌으면 릴리스 exe 로 **트랙 B 1회**(dev 는 CSP·오리진 결함을 못 본다).
  개발 루프는 `tauri:build:fast`(NSIS 생략), 배포본 낼 때만 `tauri:build`.
- **착지 마감**: 승인 없이 끝난 발견도 휘발시키지 않는다 — §4-9 대로 로드맵/결정로그/원장 중 어디로
  보낼지 확인받고 실제로 넣는다. 넣지 않기로 했으면 그 이유까지 리포트에 남긴다.

**근본 모드 착수 규율**: 재설계 판정 항목은 **되돌리기 힘든/유실 위험 코어**(데이터 이관·동기화 정합·
스키마)면 반드시 **제안 → 승인 → 실행**(그 하나만 CLAUDE.md #4 를 유지). 그 외 리팩터·추상 제거·구조
개편은 승인 후 자유 실행. 재설계는 결정로그에 `[메커니즘 → 옛 근거 → 무효화된 전제 → 새 설계]` 로 승격한다.
