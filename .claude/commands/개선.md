`$ARGUMENTS`의 **개선 기회**를 발굴한다. 버그는 `/리뷰`, 점수는 `/평가` — 여긴 "이걸 어떻게 더 좋게?"에 답한다.

1. `web/docs/개선루브릭.md`를 읽는다(가치·노력·정합성·리스크 4축).
2. **`web-improver`를 렌즈별로 병렬 팬아웃**(한 메시지 동시 실행): UX·능력확장·성능·디테일(delight)·단순화. 각 렌즈는 대상만 보고 **구체·실행가능한 향상안**을 낸다(막연한 "개선하면 좋다" 금지, 본문 덤프 금지).
3. 취합·중복제거 후 각 안을 개선루브릭 4축으로 채점하고 **티어**(Now/Next/Later/Someday)를 매긴다. **정합성 게이트**: 목적 밖·금도금은 스스로 걸러 Later/Someday로.
4. 상위 후보를 표로 제시하고 `web/docs/로드맵.md`에 추가할지 확인한다.
5. 읽기 전용 — 코드 미수정. 착수는 별도 승인 후 해당 protocol(기능추가·재설계 등) + 게이트.
