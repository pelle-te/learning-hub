# migrations/ — 스키마의 단일 원천 (SSOT)

이 폴더의 `.sql` 이 **로컬 SQLite 와 클라우드 D1 양쪽의 원천**이다.

- **로컬(Tauri)**: `src/db.rs` 가 `include_str!` 로 읽어 `tauri-plugin-sql` 에 넘긴다. 버전·설명·순서는 거기서 선언한다.
- **클라우드(Cloudflare D1)**: wrangler 가 `migrations_dir` 로 이 폴더를 본다. D1 이 SQLite 라 **같은 DDL 이 그대로 간다.**

두 벌을 만들지 않는 이유는 이 저장소가 `rows.ts` ↔ `rows.rs` 쌍둥이로 **이미 두 번 물렸기** 때문이다. 생성기 + `codegen:check` 를 쓰지 않은 이유는 **원본을 공유할 수 있으면 생성하지 않는다**는 것 — 생성은 원본 공유가 불가능할 때의 차선책이다(`web/scripts/gen-artifacts.mjs` 가 그 경우다. 원본이 부모 저장소에 있다).

---

## ⚠⚠ 이미 적용된 파일은 **절대 수정하지 마라**

sqlx 마이그레이터가 각 마이그레이션의 **SHA-384 를 `_sqlx_migrations.checksum` 에 저장하고 매 부팅에 대조**한다. 텍스트가 **1바이트라도** 달라지면 _"적용된 마이그레이션이 수정됐다"_ 로 판정해 **기존 DB 를 아예 열지 못한다.**

깨뜨리는 데 필요한 것: 들여쓰기 한 칸 · 주석 한 줄 · 줄 끝 공백 · CRLF 변환 · 파일 끝 개행 추가. 포매터를 한 번 돌리는 것으로 충분하다.

**가장 위험한 성질은 새 DB 에선 재현되지 않는다는 것이다.** 고친 사람은 정상 동작을 보고 커밋하고, 터지는 것은 **데이터를 가진 사람뿐**이다.

### 그래서 스키마를 바꾸려면

**새 버전을 추가한다.** 기존 파일은 손대지 않는다.

1. `NNN_이름.sql` 을 새로 만든다 (LF · 편집기 자동 포맷 주의)
2. `src/db.rs` 의 `migrations()` 에 `Migration { version: N, … include_str!(…) }` 을 추가한다
3. `web/test/dbMigrations.test.ts` 를 돌린다 — 새 버전은 핀이 없어 통과하고, **기존 파일을 건드렸다면 여기서 잡힌다**
4. 배포 후에는 그 버전도 핀에 추가한다

### 방어 2겹

| | |
| --- | --- |
| `.gitattributes` `*.sql text eol=lf` | `core.autocrlf=true` 라 이게 없으면 **새로 클론할 때** CRLF 로 바뀐다(작업 트리에선 재현 안 됨) |
| `dbMigrations.test.ts` 체크섬 핀 | 실 DB 에 저장된 SHA-384 를 고정. 텍스트가 바뀌면 **CI 에서** 빨간불 — 사용자 앞에서 터지기 전에 |

> 이 폴더가 만들어질 때(C-3) 네 파일 전부 **실 DB 의 체크섬과 일치**함을 확인하고 옮겼다. 즉 `db.rs` 인라인 문자열 시절과 바이트 동일하다.

## ⚠⚠ 제거는 **앱 → DB** 순서다 (Expand / Migrate / Contract · D021)

지금 이 폴더의 마이그레이션 **11개가 전부 «확장»** 이다(표·열을 더하기만 했다). 그건 규율이
있어서가 아니라 **아직 아무것도 안 지웠기 때문**이고, 첫 제거가 오는 날 지킬 것이 없으면
그날이 사고다. 순서를 여기 못박는다:

| 단계 | 무엇 | 왜 |
| --- | --- | --- |
| **Expand** | 새 열·표를 **옵셔널로** 더한다. 옛 코드가 그대로 돈다 | 구버전 앱이 새 DB 를 열어도 죽지 않는다 |
| **Migrate** | 새 자리에 쓰고 **양쪽을 읽는다**. 배포가 다 퍼질 때까지 둘 다 유지 | 클라이언트 배포는 **동시에 안 일어난다**(C2 다운그레이드 가드가 그 사실의 기록이다) |
| **Contract** | **앱에서 먼저** 옛 자리를 안 읽게 하고, 그 배포가 퍼진 **뒤에** DB 에서 지운다 | 반대로 하면 아직 안 올라온 앱이 없는 열을 읽는다 |

⚠⚠ **한 커밋에서 「앱이 안 읽는다」와 「DB 에서 지운다」를 같이 하지 마라.** 이 저장소는
**사용자가 구버전으로 되돌아갈 수 있다**(`updater`·`db_version_guard` 가 그 경로를 전제로 있다) —
DB 는 앞서 갔는데 앱이 뒤로 가면, 지워진 열을 읽는 코드가 그 순간 살아난다.

⚠ `docs` 표가 이 순서의 살아 있는 예다: 세입자가 0이 됐는데(`web/src/lib/db/docs.ts`) **배관은
남겼다**. 그 파일이 근거를 적는다 — 표를 걷으면 «스키마 마이그레이션 + 서버 계약 + 왕복 테스트»가
한 벌 더 필요하고, 되돌리기도 비싸다. 즉 Contract 는 **비용이 확인된 뒤에** 하는 단계다.

⚠ 기계 집행자는 **없다**(의도). 제거가 아직 0건이라 잠글 대상이 없고, 없는 것을 막는 린트는
다음 사람에게 «이런 일이 있다»고 거짓말한다(이 저장소가 반복해 지운 형태). 첫 Contract 가
올 때 그 커밋이 집행자를 함께 가져오는 것이 맞다 — 그때 이 표가 무엇을 잠글지 말해 준다.
