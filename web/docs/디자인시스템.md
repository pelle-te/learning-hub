# 러닝 허브 — 디자인 시스템 SSOT

> 토큰·테마·액센트·컴포넌트 규격의 단일 진리. 새 스타일은 **여기 토큰을 쓰고**, 전역 클래스를 만들지 말고 `*.module.css` + `ds` 조합으로.

## 1. 토큰 (`src/styles/tokens.css`)

`:root`에 정의, `<html data-theme>`로 통째 스왑. `:root` 기본=다크(JS 부팅 전에도 다크 렌더 → FOUC 방지).

| 그룹          | 변수                                                                                 |
| ------------- | ------------------------------------------------------------------------------------ |
| 배경/패널     | `--bg` `--bg2` `--panel` `--panel2`                                                  |
| 라인/헤어라인 | `--line` `--line-soft`(=`--line2`) `--hairline`                                      |
| 텍스트        | `--txt`(=`--ink`) `--mut`                                                            |
| 액센트        | `--acc` `--acc2` `--on-acc` · 파생 `--acc-soft`(14%) `--acc-glow`(40%) `--glow`(55%) |
| 상태          | `--warn` `--bad` `--good`                                                            |
| 반경          | `--r`(12px) `--r-lg` `--r-md` `--r-sm`                                               |
| 그림자/이징   | `--shadow-{sm,md,lg}` `--ease`(cubic-bezier(.22,.61,.36,1))                          |

- **액센트 파생 규칙:** `--acc` 하나만 바꾸면 soft/glow/glow가 color-mix로 따라온다. 액센트 노브의 근거.
- 색/반경/그림자는 테마별 재정의, 이징/반경 같은 테마 무관 값은 `:root`에서만.

## 2. 테마 · 액센트

- **테마:** `data-theme='dark'`(기본) / `'light'`. `ThemeProvider`가 토글. 세피아 폐기, 2테마.
- **액센트 노브(4색):** `violet` · `lime` · `cyan` · `amber` (`src/lib/uiState.ts` `AccentSchema`). `<html data-accent>` 프리셋 ↔ 1:1. **기본 = `lime`**(확정). `useUI.setAccent`로 변경, 즉시 persist.

## 3. 과목 색 팔레트 (`src/lib/utils.ts`)

```ts
export const PALETTE = ['#9be83f', '#22d6a4', '#63f0c8', '#1fb89a', '#3fe06a', '#22cdd6', '#5fe8a8', '#1f9b8a']; // ⑧ 라임 가족
```

- **과목 색은 저장값이 아니라 팔레트의 파생물** — 부팅마다 항목 인덱스(`i % PALETTE.length`)로 재유도. 수동 색 선택 UI 없음.
- **한 줄(PALETTE) 교체 → 전 탭·모든 저장 데이터가 다음 부팅에 전부 갱신.** 임의 색 하드코딩 금지(절대규칙 3). 순서 변경 시 과목별 배정 색이 바뀜.

## 4. 공용 컴포넌트 (`src/styles/ds.module.css`)

CSS Module로 스코프된 공유 클래스(`card` · `pill` · `muted` …). `:root` 토큰·리셋·요소 스타일은 전역 base 레이어 유지(모듈은 클래스만 스코프).

```tsx
import ds from '@/styles/ds.module.css';
<div className={ds.card}>…</div>;
// 또는 feature 모듈에서:  composes: card from '@/styles/ds.module.css';
```

- **클래스 정의 순서 = 원본(components.css→features.css) 유지.** 같은 특이도면 소스 순서가 승자(예: `pill tiny`는 tiny가 이김) → 순서 보존해야 전역과 픽셀 동일.
- 카드 등장 모션은 마운트 1회(스태거), reduced-motion은 `motion.css` 전역 백스톱이 처리.
- 빈 상태는 공용 `components/EmptyState`(1급 지원).

### 4-1. `ds.module.css` ↔ `components/ui/*` — 둘의 관계

두 층이 **병존**한다. 오래 모호했던 지점이라 규칙으로 못박는다.

| 층                | 무엇                                                 | 언제 쓰나                                                   |
| ----------------- | ---------------------------------------------------- | ----------------------------------------------------------- |
| `ds.module.css`   | 스타일만 있는 공유 클래스(`card`·`pill`·`bar`·`kpi`) | 대부분. 마크업이 제각각이고 룩만 공유하면 될 때             |
| `components/ui/*` | 스타일 **+ 마크업/동작**을 함께 갖는 컴포넌트        | 구조가 반복될 때(`<Card title>`·`<Kpi>`·`<NumberField>` 등) |

**철칙: 룩의 SSOT는 언제나 `ds`다.** `components/ui`가 같은 룩을 쓰면 값을 베끼지 말고 `composes`로 가져온다.

```css
/* components/ui/Card.module.css */
.card {
  composes: card from '@/styles/ds.module.css';
}
```

예전엔 `Card.module.css`가 `ds.card`를 손으로 미러링하면서 _"바꿀 땐 둘을 함께 고쳐 드리프트를 막는다"_ 는 주석을 달고 있었다 — 손 동기화 계약은 반드시 깨진다. 지금은 `Card`·`Pill`·`ProgressBar`·`Kpi`가 전부 `composes`로 실제 재사용한다.

예외는 **의도적으로 갈라진** 경우뿐이고, 그때는 파일 주석에 _왜_ 갈랐는지 남긴다(현재 유일한 예외: `Table` — `ds.chaptbl`에서 출발했으나 머리글 대문자·행 hover 등으로 개선돼 되돌리면 퇴행).

## 5. 규칙 요약

- 새 색·간격은 토큰 참조. 새 전역 클래스 ✗ → `*.module.css` + `ds` 조합.
- **룩을 베끼지 말고 `composes`.** 값 복제는 드리프트의 씨앗 — §4-1 참조.
- 생 hex ✗ · 브레이크포인트는 560/700/900 3종만 — `npm run lint:css`(stylelint)가 강제한다.
- 발광/모션은 `fxLite` 토글·reduced-motion 백스톱 존중.
- 시각 변경 후 `npm run e2e:update`(스냅샷)·`npm run build`.
  - ⚠ **6단계(Tailwind 전환) 중에는 이 지시를 따르지 말 것.** 전환의 핵심 안전망이 "feature 1개씩 → **그 feature 스냅샷만** 재생성 → diff를 눈으로 확인"인데, `e2e:update`는 전체를 한꺼번에 덮어 **"픽셀이 변했다"가 더 이상 신호가 아니게 만든다.** 전환 중엔 `npx playwright test -g <name> --update-snapshots=all`로 대상만. (`플랫폼개편-설계.md` §4-6단계)
