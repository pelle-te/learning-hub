# 클라우드 전환 설계 v1 — 여러 기기에서 보고, 편집한다

> **트리거**(2026-07-19): 사용자가 폰에서 **할일을 편집**하고 싶다고 했고, 이어서 _"근본이 꽤 많이 변경됐잖아? 여러 기기에서 접속하면서 편집까지 할 수 있게 구현하려던 거니까 이거에 맞춰 대대적으로 재설계해야 하지 않아?"_ 라고 물었다. 옳은 물음이었다.
>
> **이 문서가 `플랫폼개편-설계.md` 를 대체한다.** 저 문서는 **지우지 않는다** — 0~5단계 결정 근거, 특히 "실행이 뒤집은 진술 10건"과 §11 작업 규율 7가지가 거기 있고, 그건 이 문서가 **승계할 자산**이다. 다만 저 문서는 v1→v7 로 다섯 번 개정되며 **폐기된 층과 살아있는 층이 뒤섞여** 더는 설계서로 기능하지 않는다(§10 이 "원격 서버 탈락"이라 적은 채로 v7 이 원격 서버를 채택했다). 그래서 새로 쓴다.
>
> **수치는 전부 실측**이며 출처를 파일:줄로 남긴다. 근거는 2026-07-19 의 6렌즈 전수 감사다(§2).

## 0. 한 문단 요약

러닝허브는 **로컬 자원에 깊이 묶인 데스크톱 앱**이다 — 볼트 파일, 파이썬 도구, Ollama, Anki. 그런데 사용자가 폰에서 편집하고 싶은 것은 그중 **아무것도 아니고**, `AppState`(계획·할일·완료·일정) 하나다. 그래서 앱을 통째로 옮기지 않는다. **앱 데이터만 클라우드로 올리고, 로컬 자원은 PC 에 남긴다.** 이관 대상은 실측 **약 800KB** 이며, 진짜 비용은 용량이 아니라 **인증·입력검증·오프라인 큐**에 있다.

## 1. 목표 · 비목표

### 1-1. 목표 (G)

- **G1.** 폰에서 **캘린더(일/주) 조회 + 할일 편집**이 된다. PC 가 꺼져 있어도.
- **G2.** PC 와 폰의 편집이 **서로 덮어쓰지 않는다.** 특히 **삭제가 부활하지 않는다.**
- **G3.** 로컬 자원 기능(볼트·파이썬·AI·Anki)은 **하나도 잃지 않는다.**
- **G4.** 클라우드가 사라져도 **내보내기 JSON 하나로 복구**된다(I1 승계).

### 1-2. 비목표 (N)

- **N1. `features/` 재작성 금지.** 실측 17,149줄. 스케줄러 엔진·간격반복·일편집기 좌표·학위요건에 수년치 디버깅이 박혀 있다. **갈아엎기가 고점을 내리는 유일한 경로.** — 이전 문서에서 승계, 무변경.
- **N2. 프런트 프레임워크 교체 금지.** React 19 + Vite + zustand. ⚠ **근거를 갱신했다** — §5-1 참조. 이전 근거 4개 중 하나("렌더할 데이터가 서버에 없다")가 이 전환으로 **거짓이 됐고**, 틀린 근거를 남겨 두면 다음 세션이 그걸 빌미로 전체를 다시 연다.
- **N3. Python 파이프라인 재작성 금지.** 실측으로 재확인: `pipeline/pyproject.toml:28` 이 `dependencies = []` — 핵심 경로가 stdlib only 다. 건드릴 이유가 없다.
- **N4 (재정의).** ~~"다중 사용자·인증은 범위 밖"~~ → **"다중 *사용자*는 범위 밖. 단일 사용자의 *다중 기기*는 범위 안이고, 그에 필요한 인증은 세운다."**
  > ⚠ 이 재정의가 **필수**다. 옛 N4 를 문자 그대로 읽으면 **N4 가 클라우드 단계를 금지한다.** 이전 문서는 v7 에서 클라우드를 채택하고도 N4 를 안 고쳐 자기모순 상태로 남았다(감사 지적).
- **N5 (신설). 볼트·교재를 클라우드로 옮기지 않는다.** 근거는 §3-2 실측.

## 2. 실측 (2026-07-19 · 6렌즈 전수 감사)

### 2-1. 용량은 제약이 아니다

| 자원                         | 크기          | 클라우드 대상                  |
| ---------------------------- | ------------- | ------------------------------ |
| 앱 SQLite(`learning-hub.db`) | **106 KB**    | ✅ 정본                        |
| 산출물 8종(실재 6종)         | **약 300 KB** | ✅ 읽기 전용                   |
| 볼트 인덱스 `_index.json`    | **348 KB**    | △ 폰 볼트 조회의 **최소 집합** |
| 볼트 노트 597개 본문         | 6.5 MB        | ✗                              |
| `knowledge/` 전체            | 37.7 MB       | ✗                              |
| `sources/` 교재              | **498.6 MB**  | ✗ (hub 코드 경로 **0건**)      |

> **총 이관 대상 ≈ 800KB.** 무료 티어(수 GB) 기준 반올림 오차다. 하루 1회 스냅샷을 1년 쌓아도 300MB 수준.
>
> ⚠ **이 사실이 결정 하나를 되열었다** — §9-2 참조.

### 2-2. 백엔드는 분리를 절반 이상 해뒀다

규율 11-2(순수/IO 분리)가 실제로 지켜졌다. `rows.rs` 는 `tauri` 참조가 **0회**이고, `artifact.rs:93 read_at(&Path)` · `anki_scan.rs:98 scan_at(&Path)` · `server.rs:368 start_with(...)` 가 이미 인자 주입형이다. Tauri 플러그인 결합은 4곳뿐이며 그중 `dialog` 는 **Rust 코드가 한 줄도 안 쓴다**(`lib.rs:51` 등록뿐).

**남은 벽 3가지** — 성격이 다르다:

| 벽                                                           | 성격                                                                                          | 비용                 |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------- | -------------------- |
| `workspace::resolve(&AppHandle)` 가 커맨드 9개 중 6개를 관통 | **기계적** — 전부 "워크스페이스 경로 한 줄" 때문. `&Path` 주입으로 뒤집으면 6개가 즉시 풀린다 | 낮음, **가성비 1위** |
| `ollama.rs:400` Webview 채널 스트리밍                        | **국소적** — 그 위 `build()` 까지 전부 순수. 송신 sink 를 trait 으로 추상화                   | 중간                 |
| 쓰기 경로가 아직 프런트 소유                                 | **설계 선행 필요**                                                                            | 높음                 |

### 2-3. 프런트는 이미 낙관적이다 (좋은 소식)

`useApp.ts:118-124` 의 쓰기가 `void` fire-and-forget 이라 **네트워크 왕복이 끼어도 happy path 가 안 바뀐다.** 그리고 `pending` 이 immer 레시피의 **의미론적 연산 큐**이고 `onSync` 에 rebase 재적용 루프가 이미 있다 — 멀티탭용으로 만든 것이 **다기기에 그대로 일반화된다.**

작업이 한 곳에 모여 있다: **`useApp.ts:103-190`, 함수 4개 약 90줄.**

### 2-4. 슬라이스 단위 분할은 성립하지 않는다

`items` 를 5개 탭이 쓰고 사실상 전 탭이 읽는다. 스케줄러(`engine.ts` 493줄)가 `items`+`routine`+`weekAlloc`+`dayOverrides`+`events`+`completions` 를 **한 번에** 받아 파생물 `res` 를 만들고, 캘린더·오늘·통계가 전부 그걸 소비한다. 게다가 `alloc`·`items` 는 **그 파생물을 쓰기 인자로 되먹인다**(`AllocBoard.tsx:88` `setAllocCell(st, res, …)`).

프런트 감사가 독립적으로 같은 결론에 도달했다 — 부분 로딩은 `present` 배열에 **세 번째 상태("아직 안 불러옴")** 를 만드는데, 그건 "없음"과 구분되지 않아 `writeRows` 가 미로딩 슬라이스를 삭제로 보고 툼스톤을 찍는다. 그리고 `schedule()` 하나가 **22개 슬라이스를 상주 요구**한다.

> **→ 동기화 단위는 `AppState` 전체 하나다.** 잘라낼 수 있는 건 주변부 3개(`degree`·`weekly`·`retentionLog`)뿐이고 그걸 위해 복잡도를 살 이유가 없다.

### 2-5. 사용자가 원한 것은 이미 만들어져 있다

"캘린더 일/주/월 + 할일 편집"은 정확히 **`schedule` 탭**(2,015줄)이다. 세 뷰와 할일 편집이 같은 파일에 있고, **백엔드 import 가 0건**이며, 모바일 CSS 가 이 저장소에서 가장 두껍다(700px 규칙 4파일).

**폰에서 완전히 동작 가능한 탭이 11개**다: `today` `schedule` `alloc` `degree` `items` `journal` `review` `review-run` `guide` `plan-host` `routine`.

### 2-6. 데이터는 가볍지 않다

| 무엇                                                   | 민감도                        |
| ------------------------------------------------------ | ----------------------------- |
| **성적·학점·GPA**(`CourseSchema.grade`·`DegreeSchema`) | 학적부에 준함                 |
| **일정**(`PlanEventSchema` — 날짜+시각+제목+메모)      | 쌓이면 **생활 패턴 프로파일** |
| **자유 서술**(요약·주간노트·일과노트·일정메모)         | 내용을 스키마가 제약하지 않음 |
| **진로 메모·독후감**(`docs`)                           | 개인적 서술                   |

없는 것(정확히 하기 위해): 비밀번호·결제정보·주민번호·건강정보·위치좌표 — **전부 없다.**

> **정직한 판정**: 특수 카테고리 개인정보는 아니다. 그러나 **성적 + 일정 + 자유 서술 3종의 조합**은 한 개인의 학업 능력·생활 리듬·내면 고민을 상당히 정확히 재구성한다. **"학습 앱이니 별거 없다"는 판단은 틀렸다.** 비밀번호는 바꿀 수 있지만 성적 이력은 못 바꾼다.

### 2-7. 부수 실측 — AI 5종은 지금도 안 돈다

`~/.ollama` 가 **10KB**로 측정됐다. 모델이 이 기계에 설치돼 있지 않다. 즉 코치·어휘·브리핑·회고·임베딩은 **현재 동작하지 않는 상태**이고, 클라우드 이행에서 잃을 것이 없다. `OLLAMA_BASE_URL`(`ollama.rs:47`) 한 줄로 원격 추론 서버로 갈 수 있고, 프롬프트 빌더·파서는 전부 순수라 재사용된다.

## 3. 분할선

### 3-1. 클라우드로 가는 것

- **`AppState` 전량**(106KB) — 정본이 여기로 이동. 폰이 편집하는 대상.
- **`docs`**(내 요약·독후감·진로 메모) — 사용자 저작물. 정본이 따로 없다.
- **산출물 8종**(300KB) — 읽기 전용. 폰이 `goals`·`reads`·`markets` 등을 보려면 필요.
- **`_index.json`**(348KB) — 폰에서 볼트 **목록** 조회용. ⚠ 노트 본문은 안 옮긴다 — `vault_scan` 의 정본 경로가 본문을 아예 안 읽는다(subject·folder·kind·status 만).

### 3-2. PC 에 남는 것 (이관 **불가**)

| 무엇                       | 왜 원리적으로 불가한가                                                                                                                     |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **Anki 전부**              | `anki_io.py:31` 이 `%APPDATA%/Anki2/*/collection.anki2` 를 글롭하고 `anki.rs:32` 가 `127.0.0.1:8765` 하드코딩. 원료가 사용자 머신에만 있다 |
| **볼트 파일 감시**         | 파일시스템 이벤트는 원격에 없다                                                                                                            |
| **볼트 쓰기(Obsidian)**    | 정본이 로컬 마크다운 파일                                                                                                                  |
| **파이프라인 실행**        | `knowledge/CLAUDE.md` 가 "(과목)(챕터) 돌려줘 → 단계별 격리 서브에이전트"로 규정 — **크론잡이 아니라 대화형 Claude Code 세션**이다         |
| **워크스페이스 경로 추론** | `workspace.rs:69` `current_exe()` 상향 탐색. 클라우드엔 "부모 폴더"가 없다                                                                 |

> ⚠ **추론이 3벌 있다** — Rust `workspace.rs:68-85` · `vault_const.py:46` · 수집기 2종의 `HERE.parents[2]`. 전부 명시 설정으로 바뀌어야 한다. 그리고 `hub/` 는 서브모듈이라 **hub 만 클론하면 `parents[2]` 가 어긋나고 `pipeline/` 도 없다.**

### 3-3. 판단이 갈리는 것

- **`reads-collect`·`markets-collect`** — RSS/Yahoo 수집이라 네트워크만 필요하다. **클라우드에서 도는 게 오히려 이득**(PC 가 꺼져 있어도 최신). 단 스키마가 `knowledge/_meta/contract/schemas/` 를 참조하므로(81KB, 추적됨) 그 폴더는 있어야 한다.
- **`ledger-build`** — ⚠ **조용히 열화한다.** 입력 JSON 이 없어도 예외 없이 기본값으로 진행해 **exit 0 인데 0챕터**가 나온다. 클라우드에서 돌린다면 이 실패 모드를 먼저 막아야 한다.

## 4. 아키텍처

```
        ┌──────────────── 클라우드(항상 켜짐) ────────────────┐
        │  AppState 정본 · docs · 산출물 · _index.json        │
        │  인증(기기 단위) · 입력검증(.strict()) · TLS        │
        └────────▲───────────────────────────▲───────────────┘
                 │ HTTPS                     │ HTTPS
     ┌───────────┴──────────┐      ┌─────────┴──────────┐
     │  PC 데스크톱(Tauri)  │      │   폰 웹앱(PWA)     │
     │  로컬 캐시 SQLite    │      │  로컬 캐시         │
     │  + 볼트·파이썬·AI·Anki│      │  캘린더 일/주+할일 │
     └──────────────────────┘      └────────────────────┘
```

**정본은 클라우드, 두 클라이언트는 각자 로컬 캐시를 둔다.** 로컬 캐시가 있어야 ① 오프라인에서 뜨고 ② 기존 동기 읽기 전제(§2-3)를 안 깨고 ③ 데스크톱이 인터넷 없이도 로컬 자원 기능을 유지한다(G3).

**병합**: 레코드별 `updated_at` + 툼스톤 + last-write-wins(5-D 에서 이미 스키마 완료). CRDT 는 **쓰지 않는다** — 여러 명이 같은 텍스트를 동시에 고칠 때 필요한 물건이고, 단일 사용자는 같은 레코드를 같은 순간 두 기기에서 고칠 일이 사실상 없다.

**폰 앱은 `features/` 가 아니라 `lib/` 을 재사용한다.**

> 이게 가능한 **유일한 이유가 절대규칙 #2**(`eslint-plugin-boundaries` 단방향 강제)다. `lib/` 이 React 무관으로 유지된 덕에 `rows.ts`(순수 매퍼)와 `lib/scheduler` 가 그대로 폰에서 돈다. **경계 규율에 대한 투자가 여기서 회수된다** — 기록해 둘 가치가 있다.

## 5. 프레임워크·도구 재검토 결론

전수 재평가 결과 **프레임워크 층은 전부 유지가 맞고, 근거가 오히려 강해졌다.** 청구서는 전부 **데이터·계약·검증 층**에 있다.

### 5-1. 유지 (근거와 함께)

- **React 19 + Vite SPA (N2).** 이전 문서 §10 의 Next.js 탈락 근거 4개 중 **하나만 뒤집힌다**("렌더할 데이터가 서버에 없다"). 나머지 3개(SEO 없음·낯선 방문자 없음·사용자 1명이라 TTFB 이득 없음)는 그대로다. 그리고 **새 반대 근거가 더 강하다**: `tauri.conf.json:6` 이 `frontendDist` 로 정적 파일을 물리는데, SSR/RSC 는 요청마다 HTML 을 만들 런타임을 요구한다 → 셸 안에 런타임을 또 안거나(ⓐ) 클라우드에서 HTML 을 받아오거나(ⓑ). **ⓑ는 로컬 자원 앱을 인터넷 의존으로 만든다** — 명백한 퇴행이다. ⓐ를 피하려면 프런트를 두 벌 빌드해야 한다.
- **zustand + immer.** rebase 큐가 이미 낙관적 업데이트 기계다(§2-3). TanStack Query 는 **현 역할 유지**(읽기 전용 산출물 10종, mutation 0개) — 사용자 저작 상태로 확장하면 `features/` 소비처 전량을 건드려 N1 위반.
- **`eslint-plugin-boundaries`.** §4 의 이유로 값이 더 커졌다.
- **트랙 A/B 분리 · GPU 핀 · 커버리지 래칫 · CI OS 분리.** 근거가 전부 실측이고 전제 변경에 영향받지 않는다.
- **Tauri 셸의 로컬 자원 모듈 ≈3,100줄.** §3-2 가 확정.

### 5-3. 6단계 Tailwind — 순서를 바꾼다

**폰 웹앱을 Tailwind 파일럿으로 삼는다.** "6단계는 1~5와 겹치지 마라"의 실제 보호 대상은 **기존 스냅샷 59장의 churn** 인데, 폰 웹앱은 베이스라인도 CSS Modules 레거시도 픽셀 결정도 없는 **완전 그린필드**라 **한 장도 건드리지 않는다**. 그리고 §6단계가 이미 "더 작은 feature 로 규약을 먼저 굳혀라"로 전환 순서를 뒤집어 놨다 — 이건 계획 위반이 아니라 **그 지침의 가장 좋은 실행**이다.

대가: Tailwind 툴링 결정(`@theme static` · 임의값 룰 · 반픽셀 예외 · 런타임 CSS 변수 주입 예외 7곳)을 6단계가 아니라 **여기서** 확정해야 한다.

## 6. 보안 — 인터넷 노출 전 필수

> 이전 문서 §10 이 _"네트워크 노출은 인증·세션·CSRF·TLS·백업 운영을 **사용자 1명을 위해** 세우게 한다"_ 고 적었다. **그 문장은 여전히 맞다.** 사용자가 "어디서나 편집"을 명시적으로 결정했으므로 진행하되, **대가를 축소해서 적지 않는다.**

### P0 — 없으면 노출해선 안 된다

1. **TLS 전 구간.** `/api/state` 가 DB 전량을 뱉으므로 **도청 1회 = 영구 전량 유출 + 토큰 탈취**. 비용은 거의 0(관리형 호스트는 기본 제공) — **진짜 요구사항은 평문 HTTP 폴백 경로를 절대 남기지 않는 것.**
2. **토큰을 URL 에서 빼고 수명·~~회전~~·폐기를 붙일 것.** (⚠ **회전은 하지 않기로 정했다** —
   근거는 §12-2. 이득은 탈취 *탐지*인데 대가는 **응답 유실 시 영구 잠금**이고, 이 앱에서는
   짧은 액세스 수명 + 폐기 조합이 실효 대응을 이미 준다.) 현재 모델(`server.rs:330`)은 **만료 없는 단일 PSK 를 URL 에 실어** 나른다. LAN 온보딩 편의로는 합리적이지만 인터넷에선 **유출을 알아도 대응 수단이 "앱 재시작"뿐**이다. `history.replaceState`(`mobile/index.html:86`)는 주소창만 지우지 프록시 로그·Referer·히스토리 동기화는 못 막는다.
3. **서버 측 입력 검증.** ⚠ **`AppStateSchema` 는 런타임에서 한 번도 실행되지 않는다** — `schema.ts:117` 이 스스로 그렇게 적어 뒀다. 실제 방어는 손코딩 `validShape()` **5줄**(`persistence.ts:193-204`)이고 배열 내부는 완전 무검증이다. 로컬에선 "내 파일만 연다"라 수용 가능했지만 **클라우드는 정의상 신뢰할 수 없는 입력을 받는다.**
   > ⚠ 기존 스키마를 **그대로 쓰면 안 된다.** `ItemSchema`·`AppStateSchema` 가 `.passthrough()`(`schema.ts:33,215`)인데 이건 백업 호환(I1)용 **의도된** 선택이고, 신뢰 경계에서는 정확히 반대로 작동한다. **`.strict()` 수신 전용 파생**을 만들 것. 스키마가 이미 있어 지금이 가장 싸다.

### P1 — 노출 직후 필요

4. **주체(principal) — 최소한 기기 단위.** `authed()` 가 `bool` 을 돌려준다(`server.rs:116`). 누가 접근했는지 모르면 **폰을 잃었을 때 모든 기기를 끊는 것 외에 방법이 없다.** 이건 다중 사용자가 아니라 **단일 사용자의 여러 기기 구분**이라 N4(재정의) 안에 있다.
5. **CSP 도입** — 5-2 표 참조.
6. **인증 응답에 `Cache-Control: no-store` + CORS 명시 설정.** 후자가 중요한 이유: axum 기본값(헤더 없음)이 지금 유리하게 작동하지만 그건 **의도가 아니라 우연**이다. 호스트나 프레임워크를 바꾸면 조용히 열린다.
7. **요청 크기 상한 + 레이트 리밋.** 인증 우회 위험은 낮지만(192비트 토큰) DoS 와 무료 티어 쿼터 폭주는 실재한다. `server.rs:446` 이 쓰기 라우트가 없는데도 상한을 건 선례를 그대로 승계.

### P2 — 운영 책임

8. **백업·복구 경로 검증.** G4 는 보안 요구사항이기도 하다 — 랜섬웨어·계정 탈취·호스트 폐업이 전부 같은 복구 경로를 쓴다.
9. **접근 로그.** 4번에 의존. 침해를 **알아차릴** 수단이 현재 0이다.

### 부활하는 HTTP 방어

이전 문서 4단계-G 가 "불필요"로 닫은 13건을 인터넷 기준으로 재판정: **불필요 유지 0 · 부활 10 · 조건부 2 · 프레임워크 흡수 1.** 원표는 틀리지 않았다 — _"IPC 에서는"_ 이라고 정확히 한정했다. 다만 되살아나는 비율이 이전 문서 v4 가 예상한 "상당수"보다 **높다(사실상 전부)**. 그리고 원표에 **없던 항목이 새로 생긴다**: 인증 응답 `no-store` · CORS 명시 · TLS · 토큰 수명 관리.

#### C-3 이행 결과 (2026-07-19) ✅

**CSP** — `tauri.conf.json` 의 `csp: null` → `default-src 'self'` 기반 정책. 설계서 §5-2 가 지목한 XSS→`sql:allow-execute`+`run_tool`→**원격 코드 실행** 경로를 끊는다. 조사 결과 셸에서 외부로 나가는 연결이 **하나도 없어**(뉴스·Ollama·Anki 전부 Rust 중계, 사전 링크는 `<a target="_blank">` 라 내비게이션) `connect-src 'self' ipc:` 로 충분했다. `devCsp` 는 따로 둔다 — Vite HMR 이 `ws://localhost:5173` 과 인라인 스크립트를 쓰므로 운영 정책을 그대로 적용하면 `tauri:dev` 가 죽는다.

> ⚠ **CSP 는 정적으로 검증할 수 없다.** 1단계 교훈("띄워보지 않으면 모른다") 그대로 트랙 B 로 확인했다 — 15/15 통과.

**스키마 SSOT** — 마이그레이션 SQL 을 `src-tauri/migrations/*.sql` 로 내리고 `db.rs` 는 `include_str!` 로 가리킨다. wrangler 가 `migrations_dir` 로 같은 폴더를 보면 **로컬과 D1 이 한 파일을 공유**한다. 생성기를 쓰지 않은 이유: **원본을 공유할 수 있으면 생성하지 않는다**(생성은 원본 공유가 불가능할 때의 차선책이고, `gen-artifacts.mjs` 가 그 경우다).

> ## ⚠⚠ 이 작업에서 발견한 것 — 옮기는 것 자체가 위험했다
>
> sqlx 마이그레이터는 **SHA-384 체크섬**을 `_sqlx_migrations` 에 저장하고 매 부팅에 대조한다(실 DB 에서 확인). 텍스트가 1바이트만 달라져도 **기존 DB 를 못 연다.** 그리고 **새 DB 에선 재현되지 않아** 개발자는 정상 동작을 보고 커밋한다 — 터지는 것은 데이터를 가진 사람뿐이다.
>
> 그래서 옮기기 전에 **실 DB 의 체크섬과 대조**해 바이트 동일함을 먼저 증명하고 옮겼다(4개 전부 일치). 덤으로 C-1 의 v4 가 실 DB 에 이미 정상 적용된 것도 확인됐다.
>
> **그리고 이 조사가 기존 잠재 결함을 하나 드러냈다**: `core.autocrlf=true` 인데 `.gitattributes` 가 `web/` 에만 있어서 **`src-tauri/*.rs` 는 새로 클론하면 CRLF 로 바뀐다.** 즉 같은 커밋에서 만든 빌드끼리 체크섬이 갈릴 수 있었다 — 내 변경과 무관하게 원래 있던 문제다. 루트 `.gitattributes` 로 못박았다.
>
> 방어 2겹: `.gitattributes` `*.sql text eol=lf` + `dbMigrations.test.ts` 의 **체크섬 핀**(실 DB 값 고정 → 텍스트가 바뀌면 사용자 앞이 아니라 **CI 에서** 빨간불).

> **이 판단이 실제로 값을 했다(2026-07-19).** 호스트를 Oracle → Cloudflare 로 **통째로 바꿨는데 C-1 은 한 줄도 안 버렸다** — D1 이 SQLite 라 데이터 모델이 동형이기 때문이다. 반대로 C-4 를 먼저 했다면 그 전량이 폐기됐을 것이다.

**⚠ 상한을 넣으려면 분할 규칙을 같이 넣어야 했다.** 런북이 CPU 10ms 벽 때문에 배치 상한을 요구했는데, 상한만 넣으면 **첫 전량 동기화가 자기 스키마를 못 통과해 영구 교착**이다. 그래서 `capBatch` 를 함께 만들었고, 여기서 두 번째 발견이 나왔다:

**스탬프 그룹 한가운데를 자르면 안 된다.** `diffRows` 는 한 flush 가 만든 행·툼스톤 **전부에 같은 스탬프**를 찍는다. 그룹을 쪼개고 `upto` 를 그 스탬프로 잡으면 빠진 나머지가 `updated_at > since` 에서 **같은 값이라 제외**되어 영영 안 올라간다. 자를 수 있는 곳은 스탬프가 **바뀌는 지점**뿐이고, 행·툼스톤이 스탬프 공간을 공유하므로 **합쳐서** 센다. 한 그룹이 혼자 상한을 넘으면 통째로 보낸다 — **정확성이 상한보다 우선**이고(상한은 성능 장치이지 안전 장치가 아니다), 안 그러면 빈 배치가 나와 또 교착이다.

**빠진 것**: `AppStateSchema` 의 `.strict()` 수신 파생은 **하지 않았다.** 지금 유선으로 나가는 것은 `OutboxBatch` 뿐이고 `AppState` 전량이 오가는 경로는 아직 없다 — 쓰이지 않을 스키마를 미리 만들면 갱신되지 않는 쌍둥이가 하나 더 생긴다. **전량 pull 을 설계하는 C-5 에서 그때 필요한 모양으로 만든다.**

### ⚠ C-1 정정 — "직렬화 불가"는 잘못 잡은 문제였다

감사가 _"`pending` 이 immer 레시피(함수)라 직렬화 불가 → 오프라인 큐의 최대 비용"_ 이라 지적했고 §5-2 가 그걸 그대로 받아 적었다. **다시 보니 전제가 틀렸다 — 레시피를 직렬화할 이유가 없다.**

`pending` 이 지금 하는 일과 오프라인 큐가 해야 할 일은 **다른 문제**다:

|         | 현재 `pending`                                                                   | 오프라인 큐                                           |
| ------- | -------------------------------------------------------------------------------- | ----------------------------------------------------- |
| 무엇    | 400ms 디바운스 **도중** 다른 탭 저장 알림이 오면, 아직 DB 에 안 간 편집을 재적용 | 인터넷이 없는 동안 쌓인 편집을 나중에 서버로 밀어올림 |
| 수명    | 수백 ms                                                                          | 시간·일 단위                                          |
| 유실 시 | 디바운스 창만큼(오늘과 동일)                                                     | **사용자 편집 전부**                                  |

**핵심: 오프라인 큐의 내용물은 "의도"가 아니라 "행"이다.** 우리는 이미 행 단위 LWW 로 병합하기로 했으므로(§4), 서버에 보낼 것은 **`updated_at` 이 찍힌 dirty 행**이지 그걸 만든 레시피가 아니다. 그리고 행은 이미 JSON 이다.

**게다가 그 큐가 이미 존재한다.** 5-D 가 넣은 `updated_at` + 툼스톤이 곧 아웃박스다:

```
밀어올릴 것 = updated_at > last_pushed_at 인 행 ∪ deleted_at > last_pushed_at 인 툼스톤
```

**별도 outbox 테이블이 필요 없다.** 로컬 SQLite 가 이미 내구성 있는 기록이고(앱이 죽어도 남는다), watermark 하나만 두면 "아직 안 보낸 것"이 유도된다. `pending` 레시피 큐는 **원래 목적 그대로 인메모리로 남긴다** — 크래시 시 유실 창은 디바운스 400ms 로 오늘과 같고, 그건 이미 수용된 계약이다.

> ⚠ **남은 진짜 위험은 시계다.** watermark 를 벽시계 `updated_at` 으로 잡으면, 기기 시계가 뒤로 점프했을 때 새 편집의 `updated_at` 이 watermark 보다 작아져 **영영 안 밀려 올라간다**(조용히). → C-1 은 **단조 증가 로컬 시퀀스**를 `updated_at` 과 **별도로** 둘지, 아니면 밀어올릴 때 `max(watermark)` 를 재계산할지를 정하는 것이 실제 설계 내용이다. LWW 비교용 타임스탬프와 "보냈나" 표시를 **같은 값으로 겸하게 하면 안 된다**는 것이 교훈이다.

**→ C-1 의 실제 범위**: watermark/시퀀스 설계 + 밀어올림 대상 질의 + 재시도·백오프 + `whenSettled()` 축소(§5-2). 레시피 직렬화는 **범위에서 빠진다.**

#### C-1 이행 결과 (2026-07-19) ✅

**watermark 는 재계산 방식을 택했다**(사용자 결정) — 별도 시퀀스 열을 만들지 않고 밀어올린 뒤 `watermark = 배치 상한선`. 마이그레이션이 싼 대신, 위 ⚠ 가 경고한 시계 역행 실패 모드를 **다른 방법으로** 막아야 했다. 두 장치로 막았다:

| 장치              | 어디                  | 무엇을 막는가                                                                                                                                                                        |
| ----------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **단조 스탬프**   | `lib/db/stamp.ts`     | 발급을 한 지점으로 모으고 `max(Date.now(), 직전+1)` 로 강제. 시계가 뒤로 가도 발급값이 안 줄어 편집이 워터마크 아래로 묻히지 않는다. 부팅 시 DB 최대값으로 씨앗을 심어야 성립한다    |
| **상한선(fence)** | `lib/cloud/outbox.ts` | 스캔 **전에** 스탬프를 하나 발급해 `updated_at <= fence` 로 자른다. 테이블마다 별도 질의라 스캔 도중 flush 가 끼어들 수 있는데, 그걸 안 자르면 **수집 안 된 행이 워터마크에 묻힌다** |

> 두 번째는 설계 중에 나온 것이지 원문서가 예상한 항목이 아니다. "수집한 것들의 최대값"으로 워터마크를 잡으면 `records 스캔(빔) → A 행 쓰기(101) → settings 스캔(105 수집) → 워터마크 105` 순서에서 **A 가 조용히 유실된다.** 과다 포함은 LWW 라 무해하고 과소 포함만 위험하다는 비대칭에 맞춘 설계다.

**남은 한계 — `whenSettled()`**: 동작을 바꾸지 않고 **경계를 주석으로 못박는 데 그쳤다**. 현재도 로컬만 기다리고 있어(원격 전송이 아직 없다) 고칠 것이 없었고, 타임아웃을 다는 절충은 _느리지만 성공했을 로컬 쓰기를 버리는_ 쪽이라 막으려던 유실을 스스로 저지른다. **실제 위험은 C-5 가 `_inflight` 체인에 push 를 끼워 넣는 순간 생긴다** — 그 지점에 경고를 남겼다(`db/write.ts`).

**남은 갭 — `docs` 툼스톤**: 밀어올림 *대상*에는 넣었다(빼면 내 요약·독후감이 다른 기기에 아예 안 간다). 하지만 `docs` 는 `rows.ts` 의 `TABLES` 밖이라 여전히 **삭제가 전파되지 않는다**. 저작물 삭제는 드물어 지금은 실害가 없지만 **C-5(병합) 전에 정해야 한다.**

**부수 확인**: v4 인덱스가 실제로 타는지 `EXPLAIN QUERY PLAN` 으로 확인했다 — 7테이블 전부 `SEARCH … USING INDEX`(풀스캔 아님).

**추가 (호스트 재결정 직후)** — §9-3b 로 Cloudflare 를 고르면서 **VM 에는 없던 축**이 생겼다: 일일 한도(D1 행 쓰기 · Worker 요청). 한도를 소진하면 서버가 계속 거부하는데 백오프 상한이 60초라 **하루 종일 1분마다 헛친다.** 나쁜 것은 낭비가 아니라 **침묵**이다 — 앱은 "동기화 중"으로 보이고 사용자는 멈춘 걸 모른다. → `PermanentPushError` + `blocked` 상태를 넣어 **재시도가 무의미한 실패를 즉시 끊는다**(한도·인증 만료·페이로드 거부). 네트워크 오류·5xx·타임아웃은 그대로 재시도한다 — 거기선 재시도가 정확한 처방이다.

사용자는 앞서 "PC 꺼진 상태 조회"에 **ⓑ 클라우드 스냅샷 푸시**를 골랐다. 그런데 §2-1 실측이 그 선택의 전제를 바꿨다: **폰이 필요로 하는 전량이 800KB** 라 PWA 캐시 한계(보통 수십 MB)에 한참 못 미친다.

즉 **ⓐ만으로도 생각보다 훨씬 멀리 간다** — 데이터 외부 유출 0 · 무료 · 무유지보수 · P0 3건과 §6 운영 부담 전부 불필요. 한계는 "마지막 접속 시점의 데이터"와 **"폰에서 편집할 수 없다"** 두 가지다.

> **다만 G1(폰에서 편집)이 목표인 한 ⓐ 단독으로는 부족하다.** 이건 "결정을 뒤집자"가 아니라 **"조회만으로 충분한지 한 번 더 확인할 값이 있다"** 는 실측 보고다. 편집이 정말 필요하면 ⓑ 로 간다.

## 11. C-4 · C-5 이행 결과 (2026-07-19)

### C-4 — Worker 본체 ✅

**⚠ 실측이 결함을 잡았다 — 삭제가 부활했다(G2 위반).**

첫 구현의 push 는 `INSERT … ON CONFLICT(key) DO UPDATE … WHERE excluded.updated_at > t.updated_at` 였다. 행이 **남아 있을 때**는 맞게 돈다. 그런데 툼스톤이 행을 지운 뒤에는 **충돌 자체가 없어서 WHERE 가 평가되지 않고**, 오래된 편집이 새 행으로 조용히 들어왔다. 실사용으로 치면 _"폰에서 지운 할일이 PC 동기화 때 돌아온다"_ — §1-1 G2 가 명시적으로 금지한 것이다.

> **타입도 zod 도 못 잡는 부류였다.** SQL 의미론에 달려 있어서 로컬 wrangler 로 실제 요청을 쏴 보고서야 드러났다. 1단계의 _"띄워보지 않으면 모른다"_ 가 그대로 재현됐고, 이번엔 **정적 검사가 전부 녹색인 상태에서** 나왔다는 점이 같다.

해법은 `INSERT … SELECT … WHERE NOT EXISTS(더 새 툼스톤)` 이다. 두 경로를 모두 막는다 — 행이 남아 있으면 `ON CONFLICT` 가 LWW 로 판정하고, 지워졌으면 이 `WHERE` 가 삽입을 거부한다. 동점(`>=`)에서는 삭제가 이긴다: **부활보다 삭제가 안전한 선택**이다.

**인증** — ⚠ **CPU 10ms 가 설계를 강제했다.** bcrypt·argon2 는 의도적으로 느린 KDF 라 예산을 넘겨 **비밀번호 로그인이 원천 배제**된다. 그래서 PC 발급 1회용 등록코드 → 기기 레코드 + 리프레시 토큰 → 짧은 수명 HMAC 액세스 토큰 구조가 됐다. 액세스 토큰은 **어디에도 저장하지 않고**(자기기술 + 서명), 리프레시·등록코드는 **해시만** 저장한다. 고엔트로피 난수(192비트)라 느린 KDF 가 불필요하다 — **보안 요구와 CPU 예산이 충돌하지 않는다.**

**⚠ 컴파일러가 두 번째를 잡았다.** Worker 가 `cloud/schema.ts` 를 import 하니 `outbox.ts → db/sqlite.ts → tauri.ts → window` 사슬이 딸려왔다. 런북 §4-2 가 요구한 import 화이트리스트가 **컴파일 타임에** 끊었다 — 없었다면 **타입은 통과하고 런타임에 죽었을** 것이다(가장 나쁜 실패 모드). 그 결과 순수 계약을 `cloud/contract.ts` 로 분리했고, 서버의 `TABLE_COLS` 도 손코딩에서 계약 파생으로 바뀌었다.

### C-5 — 데스크톱 ↔ 클라우드 배선 🔶

**⚠ 워터마크가 둘이라는 것이 이 단계의 발견이다.** C-1 의 `watermark` 는 "내가 어디까지 **보냈나**", C-5 의 `cloud:pullMark` 는 "내가 어디까지 **받았나**"다. 두 방향의 진행이 서로 다르므로 같은 값으로 겸하게 하면 한쪽이 다른 쪽 기록을 덮어 **받지 않은 변경을 받았다고 표시**한다. C-1 이 _"LWW 타임스탬프와 '보냈나' 표시를 겸직시키지 마라"_ 고 적은 것과 같은 종류의 실수다.

**⚠ 병합의 어려움은 SQL 이 아니라 순서다.** 같은 데이터의 사본이 셋 있다 — SQLite(정본) · `sqlite.ts` 의 `_last` 기준선 · zustand 메모리. 하나만 갱신하면 나머지가 되돌린다:

| 빠뜨리면       | 결과                                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------------------- |
| `_last` 기준선 | 다음 저장의 diff 가 **받아온 변경을 되돌리는 문장**을 만든다                                                   |
| 메모리 상태    | 낡은 메모리가 다음 flush 에서 정본을 덮는다 — **0단계-E 에서 이미 물린 부류**(_낡은 메모리가 복원본을 덮는다_) |
| 스탬프 씨앗    | 원격 스탬프가 로컬 최대값보다 크면, 다음 로컬 편집이 그보다 작은 값을 받아 **워터마크 아래로 묻힌다**          |

그래서 `applyPull()` 이 ①②를 하고 **상태를 돌려주며**, `loadState()` 는 호출부(`StorageGuard`)가 부른다 — `lib/` 은 zustand 를 모른다(I2). 기준선을 먼저 세우므로 `loadState` 안의 flush 는 diff 가 비어 **아무것도 쓰지 않고**, 받아온 행에 새 스탬프가 찍혀 서버로 되돌아가는 **에코가 생기지 않는다**.

**온보딩 UI ✅** — 설정 탭의 `CloudCard`. `MobileServerCard` 의 규약을 그대로 따른다(셸 전용 렌더 · 상태 pill · 되돌리기 어려운 동작은 확인). 화면 문구가 **무엇이 올라가고 무엇이 안 올라가는지 명시**한다 — §2-6 이 _"학습 앱이니 별거 없다는 판단은 틀렸다"_ 고 실측한 데이터라, 화면이 하는 말이 정확해야 한다.

⚠ 리프레시 토큰은 **화면에 표시하지 않는다.** `MobileServerCard` 는 주소에 토큰이 박혀 있어 '보기' 토글을 뒀지만 저건 LAN 한정 **읽기 전용**이다. 이쪽은 인터넷 너머 **쓰기 권한**이라 성격이 다르고, 노출할 이유가 없다.

연결 직후 동기화를 1회 즉시 돌린다 — 5분 주기를 기다리게 하면 _"연결했는데 아무 일도 안 난다"_ 로 보이고 사용자는 실패로 읽는다.

**동기화 주기는 5분**으로 잡았다. Workers 무료 플랜의 **일일 요청 한도**(VM 엔 없던 축)를 고려한 보수적 값이고, 실사용 후 조정 대상이다.

### ⚠⚠ 전송 경로 — 웹뷰는 외부로 못 나간다(배포 직전 실측으로 잡음)

C-5 는 `client.ts` 에서 생 `fetch` 로 워커를 불렀다. **셸에선 한 요청도 못 나갔다** — C-3 이 CSP 를 `connect-src 'self' ipc:` 로 잠갔기 때문이다. 트랙 B 프로브가 확정했다:

```
violations: ["connect-src :: https://cloudflare.com/cdn-cgi/trace"]
```

**게이트가 못 잡은 이유가 구조적이다** — 트랙 A 는 Chromium 이라 CSP 가 없고, 유닛 테스트는 전송을 목으로 대체하며, 트랙 B 는 클라우드 경로를 안 탔다. 전량 녹색으로 통과했다. 2단계의 _"빌드 녹색인데 아무것도 저장 안 됨"_ 과 같은 계열이고, 교훈도 같다: **정적 검사로는 원리적으로 안 걸리는 부류가 있다.**

**판정: CSP 를 푸는 대신 요청을 Rust 로 내렸다**(`src-tauri/src/cloud.rs` 의 `cloud_http`). 근거는 편의가 아니라 이 앱의 **기존 규약**이다 — 뉴스·Ollama·Anki 가 전부 Rust 중계이고, 그래서 CLAUDE.md 가 _"셸에서 외부로 나가는 연결이 하나도 없다"_ 고 적을 수 있었다. C-5 만 예외가 되면 다음 사람이 그걸 선례로 삼는다.

|                | CSP 에 `https://*.workers.dev` 추가      | **Rust 중계(채택)**          |
| -------------- | ---------------------------------------- | ---------------------------- |
| CSP            | 푼다(되돌려지지 않는다)                  | **한 글자도 안 푼다**        |
| CORS(데스크톱) | 필요 — Tauri 오리진을 허용목록에         | **사라진다**(Origin 이 없다) |
| 성능           | 약간 유리(IPC 한 단계 없음)              | 약간 불리(직렬화 1회 추가)   |
| 공격면         | 웹뷰가 **임의** workers.dev 로 연결 가능 | Rust 가 대상·스킴을 강제     |

⚠ **성능을 근거로 고르지 않았다** — 방향은 오히려 중계가 손해다(5분 주기라 체감 0). 근거는 CSP 속성 보존과 규약 일관성이다.

**방어 3종**(`cloud.rs`): ① **https 강제**, 예외는 루프백뿐(`wrangler dev`) ② **리다이렉트 추적 금지** — reqwest 기본은 10회 따라가는데 그러면 3xx 하나로 `Authorization` 이 **다른 호스트로 실려 간다** ③ 응답 크기 상한.

**분기는 `client.ts` 의 `send()` 하나**다(`api.ts` 의 사상). ⚠ **C-6 폰은 진짜 브라우저라 같은 파일이 `fetch` 쪽으로 간다** — 그쪽엔 CSP 도 IPC 도 없다. 즉 이 분기는 C-6 의 전제이기도 하다.

**회귀 방어**: 유닛 테스트는 응답 큐를 두 전송이 **공유**해 기존 케이스 전부가 양쪽에서 돌고, 더해 _"셸에선 `fetch` 가 불리면 안 된다"_ 를 명시적으로 잠갔다. 트랙 B 는 커맨드 등록 + 평문 원격 거부를 본다(네트워크엔 안 나간다 — CI 에서 흔들리면 안 되므로). _"실제로 인터넷에 닿는가"_ 는 수동 프로브로 확인했다: 막혔던 그 URL 이 중계로는 200.

### 12-1. 조용한 유실 — pull 페이지네이션 (가장 심각)

`upto` 를 **"받은 것의 최대값"** 으로 잡았는데 `LIMIT` 은 **테이블마다 따로** 걸려 있었다.

```
A 가 200 에서 잘림 · B 는 5000 까지 전부 반환 → upto = 5000 → pullMark = 5000
→ A 의 201~5000 은 다음 질의 `updated_at > 5000` 에 **영영 안 걸린다**
```

**C-1 이 fence 로 막은 것과 완전히 같은 실패 모드의 수신 측 거울상**이다. C-1 이 _"과다 포함은 LWW 라 무해하고 과소 포함만 위험하다"_ 는 비대칭을 명시해 뒀는데, **그 규율이 받는 방향에는 적용되지 않았다.** 규율을 한쪽에만 적용하는 것이 이 저장소의 반복 패턴이다(`rows.ts`↔`rows.rs`, 경계 파서 둘).

**고침**: 각 소스가 `limit + 1` 을 읽어 잘렸는지 보고 "여기까지는 완전하다"를 돌려주며, 전역 `upto` 는 그 값들의 **최솟값**이다. 스탬프 그룹은 절대 쪼개지 않고(`capBatch` 와 같은 규칙), 그룹 하나가 상한을 넘으면 통째로 준다 — 안 그러면 진행이 0 이 되어 **영구 교착**이다.

> ⚠ **그리고 `capBatch` 를 `outbox.ts` → `contract.ts` 로 옮겼다.** 순수 함수인데 IO 모듈에 갇혀 있어 **서버가 import 할 수 없었고**, 그래서 pull 이 같은 규칙을 손으로 다시 쓸 뻔했다. 이제 **push 와 pull 이 같은 자르기 함수를 쓴다.** 이 저장소가 두 번 물린 divergence 를 세 번째로 사기 직전이었다.

같은 라우트에서 나온 부수 결함 둘: 소스별 `limit` 합계가 클라이언트의 `MAX_BATCH_ITEMS` 를 넘어 **첫 전량 동기화가 자기 응답을 거절**할 수 있었고(push 쪽 `capBatch` 가 막은 함정의 거울상), `limit=abc` 가 `NaN` 인 채 `LIMIT ?` 에 바인딩됐다.

### 12-2. 폐기 경로가 **없었다** (P0-2)

`revoked_at` 열은 005 에 있고 `/api/token` 이 **읽고 있었는데, 그 값을 쓰는 코드가 어디에도 없었다.** 즉 폐기는 **스키마와 검사만 있고 실행 경로가 0** 이었다 — 폰을 잃었을 때 실제로 할 수 있는 일은 **D1 에 손으로 SQL 을 치는 것**뿐. 런북은 폐기를 구현된 기능처럼 서술하고 있었다.

**넣은 것**: `GET /api/devices`(비밀 미노출) · `POST /api/devices/revoke` · 설정 탭 UI · `disconnectCloud` 가 **서버 폐기를 먼저 시도**하고 실패를 삼키지 않음.

⚠ **`requireDevice` 가 매 요청 폐기 여부를 확인한다.** 액세스 토큰은 무상태 서명이라 그 자체로는 폐기를 모른다 — DB 를 안 보면 폐기 후에도 **최대 15분간 계속 통과**한다. 도난 시점에 15분은 짧지 않다. D1 조회가 하나 늘지만 폐기의 실효가 "15분 뒤"에서 "즉시"가 된다.

**회전(rotation)은 넣지 않기로 정했다.** 이득은 탈취 *탐지*인데 대가는 **응답 유실 시 영구 잠금**이다(서버는 회전했는데 클라이언트가 새 토큰을 못 받으면 그 기기는 죽고, 복구는 관리 비밀로 재등록). 유예 창으로 완화하면 탐지력이 그만큼 준다. 이 앱은 사용자 1명·기기 2대이고 리프레시는 192비트 난수라 추측 불가이며, 현실적 유출 시나리오는 "기기를 잃음"이 사실상 전부인데 **그건 폐기가 정확히 처방**한다. → **문서를 코드에 맞췄다**(§6 P0-2 정정). 넣지 않은 것을 넣었다고 적어 두는 편이 훨씬 위험하다.

### 12-4. ⚠⚠ 만든 층 — 실 workerd 왕복 테스트

**이 감사에서 가장 값나가는 산출물은 결함 수정이 아니라 이 층이다.**

`server/test/roundtrip.test.ts` + `vitest.roundtrip.config.ts` — `@cloudflare/vitest-pool-workers` 로 **진짜 workerd + 진짜 D1** 을 인프로세스로 띄워 온보딩 → 토큰 → push → pull → 폐기를 **끝에서 끝까지** 왕복한다. 12케이스 **1.7초**.

왜 이게 필요했나: 기존 검사망은 이 부류를 **원리적으로** 못 잡는다 — 유닛은 전송을 목으로 대체하고, 트랙 A 는 Chromium(CSP 없음), 트랙 B 는 클라우드 경로를 안 탄다. 그래서 네 번의 사고가 전부 **전량 녹색인 상태에서** 났다. 마이그레이션은 `readD1Migrations` 로 **공유 폴더에서** 읽어 스키마 사본이 안 생긴다.

특히 §12-2 의 폐기 결함은 이 층이 아니면 잡기 어렵다: _"폐기된 기기가 **이미 들고 있던** 액세스 토큰으로도 못 들어온다"_ 는 명제는 무상태 서명·미들웨어 순서·DB 조회가 **동시에** 맞아야 참이고, 그건 실물에서만 확인된다.

> ⚠ `wrangler dev` 를 spawn 하지 않았다 — 부팅이 느리고 포트 경합으로 흔들린다. 그리고 **`isolatedStorage` 가 0.18 에서 사라져** 케이스 간 D1 이 유지된다(처음 돌렸을 때 앞 케이스 행이 흘러들어 가짜 실패가 났다). 격리를 런타임 옵션에 기대지 않고 `beforeEach` 에서 **명시적으로** 만든다.

**그리고 `server/` 는 CI 가 전혀 안 돌던 폴더였다** — 워크플로 `paths` 에 `server/**` 가 없었고 잡도 없었다. 인터넷에 노출되고 인증을 다루는 코드가 **로컬에서만** 검증되고 있었다. `cloud-server` 잡을 추가했다.

### 12-5. 후속 이행 (같은 날 마감)

- **`docs` 툼스톤** — **판정 완료**: `db/docs.ts` 에 **삭제 함수가 아예 없어** 제품에 삭제 경로가 존재하지 않는다. 즉 "전파되지 않는 삭제"가 발생할 수 없다. ⚠ 그래서 조건이 규칙이 된다 — **`docs` 삭제를 추가하는 커밋은 툼스톤을 같이 넣어야 한다**(`contract.ts` 의 `OUTBOX_TABLES` 주석이 소유).
- **시크릿 스캔** ✅ — CI `secret-scan` 잡 신설. ⚠ **마켓플레이스 액션을 쓰지 않았다**: 시크릿을 찾겠다고 저장소 전체를 읽는 서드파티 액션에 권한을 주는 것은 방어와 방향이 반대다. **버전 핀 + SHA-256 체크섬 대조**한 릴리스 바이너리를 받아 돈다(신뢰면이 늘지 않는다). 전 이력을 본다(`fetch-depth: 0`) — 지금 지웠어도 과거 커밋에 남아 있으면 유출이기 때문이다. **239커밋 전량 스캔 결과 깨끗**하다.
- **P2-8 복구 드릴** ✅ — `web/test/restoreDrill.test.ts`. ⚠ 링크는 이미 다 검사돼 있었다(`importRoundtripLarge` · `dbRows` · `cloudOutbox`) — **없던 것은 체인**이다. 그리고 체인만 부서지는 실사고가 이미 있었다: v3 이 레거시 행을 `updated_at = 0` 으로 이행했고 **각 링크는 그걸 정확히 관측하며 통과**했는데, 아웃박스가 `> watermark(=0)` 로 모으므로 그 행들은 **영원히 동기화되지 않았다**. 그래서 드릴은 `내보내기 JSON → 파싱 → migrate → sanitize → SQLite 행 → 아웃박스 수집`을 **한 번에** 흘리고, 복구본 전량이 워터마크 0 에서 **수집 대상이 되는지**까지 단언한다.
  > 부수 소득: 첫 픽스처를 실제 스키마 대신 지어냈더니(`{date,time,title}`) `sanitizeImported` 가 통째로 걸러냈다. **드릴이 자기 자신을 먼저 잡았다** — 픽스처를 발명하면 복구가 아니라 상상을 검증하게 된다는 실증이라 테스트 주석에 남겼다.
- **WAF 레이트 리밋 규칙** — ⚠ **유일하게 남은 항목이고, 코드로 끝낼 수 없다**(대시보드 설정). 코드의 아이솔레이트-로컬 카운터는 **보조 방어**이고 분산 요청은 그대로 통과한다 — 그 사실을 `index.ts` 주석이 명시한다. 절차는 **런북 §7-5**. 사용자가 손으로 한 번 해야 한다.

### 13-0. ⚠ 이 문서가 틀렸던 것 두 가지

**① §9-4 의 절충안이 성립하지 않았다.** _"별도 진입점 + `lib/` 재사용 + `features/schedule`
의 **하위 컴포넌트만 선별 재사용**"_ 이라고 적어 뒀는데, 착수 실측 결과 `DayPlanner.tsx:9` ·
`WeekCalendar.tsx:17` · `MonthCalendar.tsx:16` 이 **props 가 아니라 `useApp` 을 직접 부른다.**
하나를 떼면 스토어 4종 + 훅 2종 + `shell/` 2종이 통째로 따라온다. "선별"은 리팩터를 전제하는데
그건 N1(features 재작성 금지) 안쪽이다.

→ **절충안을 좁혔다: `lib/` 만 공유하고 화면은 폰용으로 새로 짠다.** 이원화되는 것은 **픽셀이지
규칙이 아니다** — `tasksForDay` · `toggleTaskDone` · `eventsForDay` · `lib/scheduler`(1,084줄,
React 참조 0건)는 전부 `AppState` 를 인자로 받는 순수 함수라 문자 그대로 재사용된다.

**② 이 문서는 C-6 의 진짜 본체를 안 적어 뒀다.** §4 는 "폰도 로컬 캐시를 둔다"고 한 줄로
넘어갔는데, 실측하면 **동기화 층 전체가 SQLite 전용**이었다: `outbox.ts` · `merge.ts` ·
`run.ts` · `client.ts` 가 모두 `selectDb`/`execDb` 위의 SQL 문자열이고, `db/sqlite.ts:29` 가
비-Tauri 에서 무조건 null 을 돌려준다. 즉 **그 시점의 폰은 `syncOnce()` 가 조용히
`disconnected` 를 반환**했다. 자격증명 저장(`client.ts:70-82`)도 같은 이유로 전부 유실됐다.

### 13-1. 가장 큰 결정 — 폰에 **브라우저 SQLite(wasm)** 를 넣었다

선택지는 둘이었다.

| 방법                                               | 대가                                                         |
| -------------------------------------------------- | ------------------------------------------------------------ |
| 동기화 층을 인터페이스로 추상화 → IndexedDB 재구현 | LWW 비교 · 툼스톤 순서 · fence 의미론을 **두 번째로** 손코딩 |
| **`Db` 인터페이스에 브라우저 구현을 끼운다**       | wasm 의존(gzip ~165KB glue + 392KB wasm) + OPFS 가용성       |

후자를 골랐다. **근거는 이 저장소의 이력이다** — 쌍둥이 구현으로 두 번 물렸고(`rows.ts`↔`rows.rs`,
경계 파서 2종), 둘 다 "각 구현은 자기 테스트를 통과하는데 둘이 갈라져 있었다"는 형태였다.
동기화 층에서 갈리면 결과는 **조용한 유실**이라 대가가 훨씬 크다. 지금은 `roundtrip` 과
`restoreDrill` 이 검사하는 그 SQL 이 폰에서 **문자 그대로** 돈다.

구현: `db/sqlite.worker.ts`(워커) + `db/browserDb.ts`(메인) + `db/migrations.ts`(목록).

- **워커인 이유**: OPFS 영속의 두 경로 중 `opfs` 는 COOP/COEP 헤더를 요구하고(정적 자산 서빙에
  제약이 하나 더 붙는다), `opfs-sahpool` 은 안 요구하지만 `createSyncAccessHandle()` 이
  **사양상 워커 컨텍스트에서만 보장**된다. 워커면 그 변수가 사라진다.
- **스키마는 여전히 `src-tauri/migrations/*.sql` 공유본**이다(`?raw` 임포트 · `vite fs.allow`).
  ⚠ 순서 목록만 프런트에 한 번 적히므로 **`test/dbMigrations.test.ts` 가 `db.rs` 와 대조**한다 —
  007 을 db.rs 에만 넣고 여기 빼먹으면 폰만 옛 스키마로 조용히 돈다.
- **영속 실패는 침묵하지 않는다** — OPFS 를 못 잡으면 `:memory:` 로 내려가고 `durable:false` 를
  돌려주며 화면이 그 사실을 말한다.

> ⚠ **기본은 꺼져 있다.** `enableBrowserDb()` 를 폰 진입점만 부른다. 무조건 켜면 `npm run dev`
> 와 **트랙 A 스냅샷 59장**이 저장 백엔드를 통째로 갈아탄다 — 의도적으로 남긴 폴백이다.
> 이 계약은 e2e 케이스 하나가 기계적으로 지킨다(`데스크톱 셸은 브라우저 SQLite 를 켜지 않는다`).

### 13-2. 조용한 유실을 하나 막았다 — `isTauri()` ≠ "SQLite 가 정본"

`useApp.ts:118` 의 저장 분기가 `isTauri()` 였다. C-6 전까지 두 명제는 같은 뜻이었지만 **폰은
Tauri 가 아닌데 SQLite 가 정본**이다. 안 바꿨으면 폰 편집이 localStorage 로 가고, **아웃박스는
SQLite 만 훑으므로 그 편집은 영원히 동기화되지 않았다.** §12-1 · C-1 이 두 번 물린 실패 모드와
정확히 같은 형태다. → `isSqlitePrimary()` 로 교체.

### 13-3. 번들 예산 게이트를 다시 썼다 (엔트리별)

엔트리가 둘이 되자 `dist/assets` 총합은 **어느 사용자도 다운로드하지 않는 수치**가 됐다.
그대로 뒀다면 폰 자산이 데스크톱 예산을 먹어 "초과"가 뜨는데 **데스크톱은 1바이트도 안 커진**
상태가 된다 — 게이트가 거짓말을 한다(실제로 첫 빌드에서 557.7/500 으로 그렇게 떴다).

→ `dist/.vite/manifest.json` 을 따라 **엔트리별 초기 로드 그래프**를 잰다. 파일명 prefix
매칭(옛 방식)은 추측이었고 그래프는 관측이다.

부수 소득: `manualChunks` 가 `node_modules` 를 전부 `vendor` 한 덩어리로 묶고 있어 **폰이
안 쓰는 react-router · tanstack-query · cmdk 를 63.9KB 통째로 받고 있었다.** react 코어만
고정 분리하고 나머지를 번들러에 맡기니 **폰 137.2 → 91.9KB, 데스크톱 142.9 → 122.1KB** 로
함께 줄었다. 덩어리 하나는 "누가 뭘 쓰는지"를 표현할 수 없다.

> ⚠ **총합 축을 되살렸다.** 엔트리별 초기 로드만 재면 지연 로드되는 탭 20개와 **워커·wasm 이
> 통째로 게이트 밖**으로 나간다. 재작성 중에 실제로 "총합 557.7 → 422.0" 이 나왔는데 그건
> 줄어든 게 아니라 **135.7 이 안 보이게 된 것**이었다. 폴더를 직접 훑는 두 번째 축을 둔다.

### 13-4. Tailwind 파일럿 — 굳힌 규약 3가지 (C-7 이 승계한다)

`src/phone/phone.css` 머리주석이 SSOT.

1. **색은 여전히 `tokens.css` 에서 온다.** `@theme` 가 팔레트를 _정의하지 않고_ **가리킨다**
   (`--color-bg: var(--bg)`). 절대규칙 #3 이 "색은 저장값이 아니라 파생물"인데 여기 팔레트를
   다시 적으면 원천이 둘이 된다. 테마 전환도 공짜로 따라온다 — `:root` 와 `<html data-theme>`
   가 같은 요소라 `--bg` 가 바뀌면 `var(--bg)` 도 다시 계산된다. **복사했다면 라이트 테마에서
   조용히 틀렸을 것이다**(이 저장소가 이미 겪은 결함: 다크 전용 hex 가 흰 패널 위에서 1.58:1).
2. **브레이크포인트를 안 쓴다.** 560/700/900 은 데스크톱 셸의 경계다. 폰은 단일 폭.
3. **임의값(`w-[137px]`) 금지.** 필요하면 토큰 사다리를 먼저 늘린다.

기존 CSS Modules 59장은 **한 장도 안 건드렸다**(트랙 A 69개 전량 통과).

### 13-5. 서비스워커 — `selfDestroying` 을 껐다 (오리진이 갈렸으므로)

옛 판단("오프라인 이득 0")은 앱이 `localhost:8000` + serve.js 로 뜨던 시절 것이고 **그 오리진은
4단계-G 에서 죽었다.** 지금 SW 가 살 수 있는 곳은 **폰이 도는 Workers 오리진 하나**뿐이다 —
데스크톱 셸은 `tauri://` 로컬 파일을 물고, 트랙 A 는 `serviceWorkers: 'block'` 이다.

- `injectRegister: null` + `phone/main.tsx` 가 명시 등록 → **데스크톱 `index.html` 에 등록
  코드가 안 박힌다**(§5-2 "셸 빌드에선 제거"를 이렇게 이행했다. 빌드 산출물로 확인).
- precache 는 **껍데기 2.63KB 뿐**이다. 모든 js 를 glob 하면 데스크톱 청크 20여 개를 폰이
  미리 받는다. 청크·wasm·폰트는 런타임 `CacheFirst`(해시 파일명이라 안전).
- ⚠ **2MB 가변 폰트를 precache 에서 뺐다** — 첫 방문이 셀룰러일 수 있는데 껍데기 하나 받자고
  2MB 를 선불하는 것은 값이 안 맞는다. `font-display: swap` 이라 없으면 시스템 폰트로 즉시 뜬다.

### 13-6. 같은 오리진 서빙 — 그리고 **가정 하나가 변이 테스트로 반증됐다**

`server/wrangler.jsonc` 에 `assets`(`../web/dist` · SPA 폴백 · `run_worker_first: ["/api/*"]`).
설정은 설치된 **wrangler 4.112.0 의 스키마에서 확인**했다(추측 아님).

> ⚠ **`run_worker_first` 가 막는 것이 우리가 생각한 것과 달랐다.** 처음엔 "이게 없으면 SPA
> 폴백이 `/api/*` 를 삼킨다"고 주석에 적었는데, 스텁 워커(418)로 **변이 테스트**해 보니 틀렸다:
>
> | 경로          | 있을 때  | 없을 때      |
> | ------------- | -------- | ------------ |
> | `/plan`       | 200 html | **418 워커** |
> | `/api/health` | 418 워커 | 418 워커     |
> | `/nope.js`    | 200 html | **418 워커** |
>
> 없어도 `/api/*` 는 워커에 닿는다 — 다만 **fallthrough 로** 닿으므로 `dist` 에 `/api/…`
> 이름의 파일이 생기는 순간 깨진다. 즉시 깨지는 것은 **SPA 폴백**이다(`/plan` 새로고침 → 404).
> 이 저장소의 규율 그대로다: **적기 전에 돌려 본다.**

**CORS 는 닫힌 채로 둔다.** 실측 결과 교차 출처 호출자가 **0**이다 — 데스크톱 셸은
`client.ts:46-49` 가 `isTauri()` 에서 IPC(`cloud.rs`)로 내려가고(C-3 CSP 때문), Rust 는
`Origin` 헤더를 안 보낸다. 폰은 같은 오리진이 됐다. 허용목록을 **지우지 않고 비워 두는** 것이
§6 P1-6("axum 기본값이 우연히 안전했다")에 대한 답이다 — 안전이 **우연이 아니라 명시**가 된다.

⚠ **자산 디렉터리가 비어도 배포는 성공한다** — wrangler 가 조용히 0개를 서빙하고 API 는 멀쩡히
돌아 **폰만 깨진다.** 테스트가 그 디렉터리를 시끄럽게 단언한다(조용한 skip 금지). 절차는 런북 §7-6.

## 14. C-7 착수 — 선행조건 이행 (2026-07-20)

> C-7 = 6단계 Tailwind 본편. 계획 본문은 `플랫폼개편-설계.md` §4-6단계가 여전히 유효하다
> (실측 난이도표 · `composes:` 20건 · 조용히 깨지는 것 4종). **이 절은 그 계획이 요구한
> 선행조건의 이행 기록**이고, 계획 자체를 대체하지 않는다.

### 14-0. 왜 선행조건을 먼저 하는가

C-7 은 정의상 **시각 스냅샷 59장을 대량 재생성**한다. 그런데 이 앱에서 UI 의 안전망은
사실상 그 스냅샷뿐이라, **전환이 자기 검증망을 무력화하면서 진행된다.** `로드맵.md:25` 가
이 문제를 보고 배분 보드 단위 테스트를 **6단계 선행조건으로 격상**해 뒀다. 그 판단을 따른다.

### 14-1. JS 가 읽는 CSS 토큰을 잠갔다 (불변식 ④)

`test/invariants.test.ts`. Tailwind `@theme` 는 **미사용으로 보이는 토큰을 트리셰이킹**하는데,
토큰을 **JS 에서만** 읽는 곳이 3군데다(`AmbientCanvas` 4개 · `Graph.tsx` 8개 · `Settings.tsx` 1개).
셋 다 **폴백값이 있어 토큰이 사라져도 에러 없이 틀린 색으로 렌더된다.**

그리고 시각 게이트는 이 축을 못 잡는다 — 0단계-G 에서 실증됐다: `maxDiffPixelRatio: 0.02` +
단일 계열 팔레트라 **과목 색 전량 교체가 스냅샷 59장을 통과했다.**

⚠ **파일 목록을 손으로 적지 않는다** — `getComputedStyle` 을 쓰는 파일을 찾아서 판다.
네 번째가 생겨도 자동으로 걸린다. 그리고 **0개면 실패한다**(조용한 통과 방지).

> 정직한 한계: 이 테스트는 **원천(`tokens.css`)에 선언돼 있는가**를 보지 **빌드된 CSS 에
> 살아남았는가**를 보지 않는다. 그래도 값이 있는 이유는 C-7 이 토큰을 `@theme` 로 옮기는
> 순간 빨간불이 된다는 것 — 신호가 정확히 그 시점에 온다.

### 14-2. stale dist 를 막았다 (조용히 깨지는 것 ④)

`playwright.config.ts` 의 `reuseExistingServer: !CI` → **`false`**. 별도 터미널에 preview 가
떠 있으면 그걸 재사용하는데, 그 preview 는 **그때의 `dist`** 를 물고 있다 → 방금 빌드한 코드가
아니라 옛 산출물에 스냅샷을 찍는다. 같은 파일이 SW stale 캐시(`serviceWorkers: 'block'`)는
막아 놨는데 **stale dist 는 안 막혀 있었다** — 같은 종류의 함정인데 하나만 막혀 있었다.

C-7 에서 특히 치명적인 이유: 전환의 유일한 안전망이 "feature 1개 → 그 스냅샷만 재생성 →
diff 를 눈으로 확인"인데, stale dist 를 보면 **아무것도 안 바뀐 것처럼 통과**한다.
녹색이 "회귀 없음"이 아니라 **"안 쟀음"**을 뜻하게 된다.

### 14-3. stylelint 의 집행자를 교체했다 — 그리고 **설계서 가정이 또 틀렸다**

결정로그가 _"규율은 소멸이 아니라 `better-tailwindcss` 로 집행자만 교체된다"_ 고 적어 뒀다.
`eslint.config.js` 에 `src/phone/**` 대상 블록을 넣었다(C-7 이 feature 를 옮길 때마다 넓힌다 —
한 번에 전체를 켜면 아직 CSS Modules 인 파일에서 오탐만 쏟아진다).

> ⚠ **`플랫폼개편-설계.md` §4-6단계는 "임의값 룰을 명시적으로 켜야 막힌다"고 적었는데,
> `eslint-plugin-better-tailwindcss` v4.7.0 에 그런 룰은 없다**(룰 15개 전량 확인).
> 대신 `no-restricted-classes` 의 `restrict: [{pattern: '.*\[.*\].*'}]` 로 막는다.
> 결과는 같고 수단이 다르다 — **문서가 도구의 API 를 가정으로 적어 둔 사례**가 하나 더 늘었다.

**변이 테스트로 확인했다**(켰다고 믿지 않는다): `w-[137px]` 를 넣으면 실패하고, 빼면 통과한다.

**⚠ C-7 이 갖게 될 예외 둘을 지금 적어 둔다 — 그때 발견하면 이미 늦다:**

| 예외                                                                   | 왜 원리적으로 필요한가                                                                                                                                                                                                                                      |
| ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **반픽셀 font-size**(9.5/10.5/11.5px)                                  | `stylelint.config.js:17-22` 가 왜 반픽셀 금지를 일부러 안 넣었는지 기록한다 — 월 캘린더 `.cell` 이 고정 행 높이 + `overflow:hidden` 이라 0.5px 상향이 **과목 칩을 통째로 잘라먹은** 실사고. Tailwind `text-*` 는 정수 사다리라 그 값들이 전부 임의값이 된다 |
| **런타임 CSS 변수 인라인 주입** (`--seg` 4곳 · `--sub` · `--tint` 2곳) | 동적 색은 **정의상 정적 클래스로 표현 불가**다. 이건 절대규칙 #3(색은 파생물)의 구현이라 없앨 수 없다                                                                                                                                                       |

### 14-4. 배분 보드 단위 테스트 (로드맵이 격상해 둔 선행조건) ✅

`web/test/allocBoard.test.tsx` — **27케이스**. `AllocBoard` 만 단독 렌더하는 하네스이고,
`res`·`capWd` 는 Alloc 탭과 **같은 셀렉터**로 매 렌더 새로 판다 — 그래야 §2-4 가 지적한
"스케줄러 파생물을 쓰기 인자로 되먹는" 경로가 실제와 같이 돈다.

⚠ **클래스명·스타일 단언이 0이다.** 이게 이 테스트의 존재 이유다 — C-7 이 픽셀을 통째로
바꿀 것이므로, 픽셀을 단언하면 전환 첫날 전부 빨간불이 되고 그때 사람은 **테스트를 지운다.**
질의는 role·aria-label·텍스트뿐이다. 잠근 축: 셀 편집→상태 계약(auto→managed 승격 포함) ·
행/열 합과 잔여 · 접근성 계약(`role="table"`·rowcount/colcount·탭 스톱·`aria-current`) · 경계
(0 입력 · 음수 클램프 · 타이핑 중간 `"1."` · 고아 sid · capWd 전부 0).

**의도적으로 안 잠근 것**(적어 두지 않으면 다음 세션이 "왜 빠졌지"로 되돌린다):

| 안 잠근 것                               | 왜                                                                                                                                              |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 드래그&드롭 배분 · 화살표 키 스텝        | jsdom 이 `DataTransfer`·number 스테퍼를 실질 미구현 → **검사가 라이브러리 흉내를 검증**하게 된다. 조용히 통과시키면 "녹색인데 아무것도 안 쟀다" |
| 채움 농도 · 과목색 스와치 · 오늘 열 강조 | 정의상 픽셀. **C-7 에서 바뀌어야 정상인 것들**                                                                                                  |
| 토스트 문구                              | 카피 변경에 약하다 → 같은 사건을 **상태**(`weekAlloc` 유무·배지)로 잠갔다                                                                       |

**발견 셋**(결함 아님 · 계약으로 굳혔다): ① 챕터 시간이 계획 지평 안에 소진되면 `finished` 가
되어 예산 배지가 중립(`챕터 완료`)으로 바뀐다 — 픽스처를 40h 로 두면 **잔여 테스트가 전부
무의미해진다**(500h 로 올리고 이유를 주석에 남겼다). ② `NumberField` 는 클램프 결과가
현재값과 같으면 커밋하지 않아, **이미 0인 칸의 음수 입력은 주를 managed 로 승격시키지 않는다**.
③ number 입력의 비수치는 `''` 가 되고 셀이 `emptyValue={0}` 이라 **0으로 확정된다** —
"쓰레기 값 거부"와 "빈 칸=0"이 이 셀에선 같은 경로다.

### 14-5. ⚠ 부수 관측 — 병렬 에이전트가 게이트를 흔든다

선행조건 작업 중 `npm run verify` 가 **4건 실패**했다가 재실행에서 전량 통과했다. 원인은
코드가 아니라 **서브에이전트가 같은 저장소에 동시에 파일을 쓰고 있었던 것**이다.
**독립적으로 두 번 관측됐다** — 서브에이전트도 자기 실행에서 같은 현상을 겪었다(다른 3파일). 즉
"빨간불 → 초록불"이 수정 때문이 아니었다.

이 저장소는 세션 셋이 동시 작업하는 것을 전제로 하고(절대규칙 #5 가 그 위생 규칙이다),
거기에 서브에이전트가 더해지면 **게이트 결과가 시점에 의존**하게 된다. 규칙으로 남긴다:
**게이트는 병렬 작업이 멈춘 뒤에 돌린다.** 안 그러면 flaky 를 결함으로, 결함을 flaky 로 읽는다.

> (`text-xs`·`text-sm`·`text-lg`·`text-xl`…)은 `font-size` 와 함께 _동반 `line-height`_ 를 방출한다.**
> 브리지가 `--text-xs` _값_ 은 덮지만 내장 `--text-xs--line-height`(1.333/1.428…)는 그대로라, 그
> 유틸이 붙는 순간 **상속되던 `line-height`(예: body 1.6)를 조용히 덮어쓴다.** 반면 커스텀 크기명
> (`text-2xs`·`text-md`·`text-display` 등 브리지 신설 이름)은 font-size 만 방출해 정상 상속한다.
> → 원본이 line-height 를 **상속**하던(자체 선언 없던) 요소에 `text-xs/sm/lg` 를 쓰면 반드시
> `leading-[<원래 상속값>]` 을 함께 박는다. 텍스트 밀도 높은 화면에서 전 영역 ~1px 베이스라인
> 이동으로 누적되고 **정적 검사·타입·lint 전량 녹색 · 스냅샷만 잡는다.** (SeasonRoadmap 이 이미
> `text-sm leading-[1.6]` 으로 이 관용구를 썼는데 journal 이 너무 좁게 적용해 물렸다.)
>
> ⚠⚠ **규약 6-b(2026-07-23 · reads 사고 · dark 만 threshold 초과, light 는 운 좋게 통과)**: 이 앱은
> **preflight 를 안 쓴다**(`tw.css` 존재 이유) → Tailwind 의 `button,input,select,textarea{font:inherit}`
> 리셋이 **없다.** 따라서 **폼 컨트롤(`<button>`·`<input>`·`<textarea>`)과 그 자손 텍스트는 body 의
> `line-height:1.6` 을 상속하지 않고 UA 기본 `line-height:normal`(≈1.2) 로 렌더된다.** 즉:
>
> - 버튼/입력 _자손_ span 에 `text-xs/sm/…` 를 줄 때 핀은 `leading-[1.6]` 이 아니라 **`leading-[normal]`** 이다.
> - `<textarea>` 등 소스가 line-height 를 **명시**했으면 그 값(`leading-[1.6]!` 등)으로 복원한다(자체 상속 안 함).
> - **비폼 요소**(div·span·a 등 폼 밖)만 body 1.6 을 상속한다 → 거기 built-in 크기명엔 `leading-[1.6]`.
>   판별: 요소가 폼 컨트롤이거나 그 안쪽이면 `normal`, 폼 밖이면 `1.6`(또는 소스 명시값). `leading-[..]` 는
>   `--tw-leading` 을 세워 내장 동반 line-height 를 확실히 이긴다(컴파일 출력로 확인). `line-clamp-*` 는
>   line-height 를 방출하지 않으므로 별도 핀이 필요하다.

화면을 봐야 보였다. 남은 52개에서 같은 비율이면 **자동 스냅샷 재생성만으로는 못 잡는다** —
`--update-snapshots` 는 깨진 결과를 그대로 정답으로 굳힌다.

절차: 이식 → **띄워서 눈으로 확인** → 그다음 스냅샷 재생성. 순서가 뒤집히면 검증이 아니다.
그리고 **커버리지가 0인 화면은 이식 전에 스냅샷부터 만든다**(사후에 만들면 깨진 상태가
베이스라인이 된다).

### 15-5. 남은 순서

… `composes:` 20건을 가진 11파일(`ui/*`·`alloc`·`stats`·`settings` 등)은 **뒤로** — Tailwind 에
대응물이 없어 전부 수동 해체이고 단가가 확 오른다. `ds.module.css` 가 마지막이다.

### 15-6. 사고 없음(guide·goals) — 규약이 굳었다는 신호

`guide`·`goals` 이식에선 **실사고가 나오지 않았다**(discovery·review-run 은 각 하나씩 물렸다).
규약 다섯 + 실렌더 확인이 자리를 잡았다는 뜻이다. 다만 둘 다 새 처리를 하나씩 만났고 —
guide 는 표(구조 의사클래스 → 직접 클래스)·`li::marker`, goals 는 **em 단위 min-width**(라벨
컬럼을 `--container-*` 로 이름 주기)·**auto-fill 그리드**(테마 항목화) — 규약을 어기지 않고
기존 메커니즘(규약 2·3)으로 흡수됐다. 그리고 goals 에서 규약 하나가 명시적으로 갈라졌다:
**치수적 그래픽 요소**(중요도 바 6px 높이·점 8px·정렬 오프셋 6px)는 사다리 반올림의 예외로
표준 분수 유틸(`h-1.5`·`mt-1.5`)로 정확히 남긴다 — 2px 가 사라지면 안 보이는 간격이 아니라
시각 신호가 흔들리기 때문(clamp 를 반올림 예외로 둔 규약 3 과 같은 논리 · 임의값이 아니라
표준 유틸이라 규약 위반이 아니다).

### 15-7. ⚠ control(첫 폼 위주) — **전역 요소 규칙이 layered 유틸리티를 이긴다**

지금까지 넷은 `<div>/<span>/<h1>/<p>/<code>` 였다. control 은 `<button>`·`<input>`·`<h2>`
투성이고, 여기서 **구조적 장애물**이 처음 나왔다:

`base.css`·`components.css` 는 `@layer` 밖(unlayered)에서 요소 규칙(`button{}`·`input:focus{}`·
`h2{}`)을 건다. Tailwind 유틸리티는 `layer(utilities)` 안이다. **CSS 캐스케이드상 unlayered 는
layered 를 명시도와 무관하게 이긴다.** 그래서 폼 요소·제목 요소에서 유틸리티가 **조용히 묻힌다** —
`!` 없이 옮기면 히어로 `<h2>` 가 전역 `h2{font-size:16px}` 로 눌려 clamp(26~40px) 대신 **16px 로
붕괴**한다(빌드·린트 전량 녹색 · 화면에서만 보인다). 옛 CSS Module `.heroTitle`(unlayered 0,1,0)
이 먹혔던 건 그것도 unlayered 라 명시도로 이겼기 때문인데, Tailwind 로 옮기면 layer 로 내려간다.

**판정(2026-07-23 · Option A):** 폼/제목 요소에서 전역과 **다른** 속성만 `!`(important · layer 를
넘는다)로 이긴다. 전역과 **같은** 값(jobPeek 테두리 1px `line`·`r-sm` 등)은 `!` 없이 전역에
맡겨 과잉 `!` 를 피한다. **대안(전역 요소 규칙을 `@layer` 로 감싸기)은 기각** — 공유 `components.css`
를 이식 중에 건드리면 아직 CSS Module 인 53개 feature 의 raw 버튼/입력 캐스케이드가 흔들린다
(`ds.module.css` 를 맨 뒤로 미룬 것과 같은 원칙). `!` 는 control 에 격리된다.

부칙(control 에서 처음): **그래디언트 배경은 Tailwind 색 유틸로 표현 불가** — `--acc-fill`(칠해진
표면 SSOT · linear-gradient)을 `bg-[image:var(--acc-fill)]` 로 직접 참조한다. 임의 '값'이 아니라
**SSOT 토큰 참조**라 임의값 금지(규약)에 걸리지 않고(린트 패턴은 `[`+숫자+단위/`#`/`&` 만 막는다),
§14-3 이 예고한 "런타임 CSS 변수 주입" 예외와 같은 성격이다.

곁다리(control 에서 드러남): control 시각 스냅샷 2장이 **리드아웃·힌트 텍스트가 옛 "serve.js"**
로 stale 했다(코드는 이미 "워크스페이스"). Playwright 허용오차 안이라 통과하고 있었을 뿐이고,
이식이 오차 밖으로 밀어 드러났다 — 재생성으로 함께 바로잡았다.

### 15-8. atlas — 타임라인 점·연결선(`::before`/`::after`) + 스냅샷 밖 검증

atlas 는 control 규율(전역 요소 `!`)을 그대로 승계했고(h1/h2/h3·textarea·button·a), 새로 만난
것은 **장식 pseudo-element 그래픽**이었다: 동향 타임라인의 `.tlItem::before`(발광 점)·`::after`
(세로 연결선)를 Tailwind `before:`/`after:` 로 옮긴다. 점 6px·선 1px 는 사다리 밖이라 표준 분수
유틸(`before:size-1.5`·`after:w-px`)로 정확히 남긴다(§15-6 치수적 그래픽 예외의 연장).
Panel 의 색 틱은 런타임 전달 색이라 인라인 주입(`style={{ background }}`)을 유지한다(§14-3 예외).
`--sig`/`--fut` 로컬 별칭은 실토큰(`--signal`/`--warn`)으로 폈다.

⚠ **스냅샷 밖 검증**: atlas-detail 스냅샷은 `#main` 내부 스크롤이라 뷰포트(720px)만 잡고 **타임라인·
메모는 아래로 잘려 스냅샷에 없다**(fullPage 여도 문서가 뷰포트 높이라 소용없다). 규약 6(실렌더
확인)은 스냅샷이 못 보는 층을 정확히 겨냥한 것 — 임시 스펙으로 그 패널만 요소 스크린샷해 점·링·
연결선·textarea 가 실제로 그려지는지 눈으로 확인한 뒤 커밋했다(스냅샷만 믿었으면 못 봤다).

### 15-9. review — 지금까지 최대(689줄) · 마운트 애니메이션 인프라

`review` 는 `ds.*` 공유 클래스와 `rv.*` 를 촘촘히 혼용한다 — **`ds.*` 는 그대로 두고 `rv.*` 만
옮겼다**(부칙: ds.module.css 는 맨 뒤). 새로 만난 것 둘:

- **마운트 애니메이션**(막대 리빌 `rv-bar-rise` scaleY · 카드 페이드업 `rv-fade-up`). CSS Modules 는
  keyframe 이름을 스코프하므로 ds.module 의 `ds-fadeUp` 을 Tailwind 유틸에서 못 부른다 → 키프레임을
  **`tw.css` 에 전역으로** 두고 `animate-[rv-fade-up_0.46s_var(--ease)_both]` 로 붙인다(값의 `s`·`var()`
  는 임의값 패턴에 안 걸린다 — 막힌 단위는 px/rem/em/%/vw/vh/ch/deg 뿐). 막대 stagger 지연은
  런타임값이라 인라인 `style` 로 남긴다. 이 인프라는 이후 애니메이션 있는 feature 가 재사용한다.
- **oklab 액센트 베이크 그래디언트**(`sigChart` 배경·상단 헤어라인)·**달성률 글로우**(text-shadow).
  둘 다 Tailwind 색/유틸로 표현 불가 → tokens.css 에 이름 주고 `bg-[image:var(--…)]`·
  `[text-shadow:var(--…)]` 로 참조(§14-3 성격 · % 든 그래디언트를 클래스에 직접 쓰면 임의값 패턴에
  걸리므로 토큰이 유일한 길).

그 밖: `.mainCol .paBar` 같은 컨텍스트 오버라이드는 **그 컨텍스트가 늘 성립**하면(차트가 항상
mainCol 안) 오버라이드 값을 실효값으로 삼아 옮긴다. `text-2xl`(22px) 브리지 추가 · underline 색은
`decoration-acc/45`(불투명도 수식어)로 토큰 없이 표현.

### 15-10. mastery — 3-컴포넌트 공유 · 클래스 SSOT 를 파일로

mastery 는 한 스타일시트를 **세 컴포넌트**(`Mastery`·`KnowledgeMap`·`NextActions`)가 공유했다.
그 공유를 유지하려 Tailwind 클래스 문자열을 **`features/mastery/classes.ts`(`M` 객체)** 한 곳에
두고 셋이 import 한다 — 옛 `.module.css` 가 하던 SSOT 역할을 TS 상수 모듈이 잇는다. feature 내부
파일이라 레이어 규칙에 걸리지 않는다(components/hooks/lib 으로 승격할 공용물이 아니다).

재사용이 컸다: review 가 깐 `rv-fade-up` 키프레임(딜레이 변형 `_0.06s_` 포함)·`shadow-card/dot`·
`bg-sig-top` 헤어라인·`breakpoint-wide`·2컬럼 그리드 패턴을 그대로 썼다. 새 것은 시네마틱 패널
그래디언트 2종(히어로 acc+violet 3층·지식맵 acc 2층)·경고 톤 note 색·히어로 clamp 3종·개념행 `em`
글자 2종(`text-concept-nm`·`text-msdot`)뿐. 인라인 색 주입 22곳(숙달 램프·분포 세그·개념 점)은
정의상 런타임이라 그대로 뒀다(§14-3). 그리고 **`.fr`(프런티어 셀 링)은 드롭**했다 — 인라인
`boxShadow` 가 프런티어면 링+글로우를 항상 합성해 그 클래스를 덮으므로 no-op 이었다(코드 주석이
이미 그 사실을 적어 뒀다). `--ring-w`/`--ring-glow-r` skeleton 파라미터는 `8px` 가 임의값 패턴에
걸려 인라인 `style` 로 남겼다. 사고 0(4연속).

### 15-11. ledger — mastery 인프라 최대 재활용 · 커버리지 0 → 이식 전 스냅샷 · 첫 button 셀

ledger 는 레이아웃 사상이 **mastery 와 동형**(fill 프레임 → 히어로 밴드 → 2컬럼[매트릭스 | 행동])이라
지금까지 중 인프라 재사용이 가장 컸다: **지식맵/폴백 그래디언트 `--bg-map-mastery` 를 값이 같아 그대로
공유**(review→mastery 의 `--bg-sig-top` 재사용과 같은 패턴 · 리네임 없이)·상단 헤어라인·`rv-fade-up`
키프레임(딜레이 변형)·`shadow-hero/card`·`hero-gap/px`·`breakpoint-wide`. 새로 이름 준 것은 히어로
그래디언트 하나(**mastery 히어로에서 violet 층만 뺀 2층** · `--bg-hero-ledger`)·퍼널 막대 트랙
(`--bar-track` = line 40%)·2컬럼 트랙(380px)·상세 오버레이 폭(`min(360px,82%)` → `w-full
max-w-ledger-detail` 로 표현 · %·px 임의값 회피)·퍼널 gap(clamp)·eyebrow 자간(0.24em = `tracking-eyebrow`
한 칸 위)·상세 그림자(lg)뿐.

세 가지가 새로 나왔다:

- **커버리지 0 → 이식 전 스냅샷**(§15-4 를 처음으로 문자 그대로 적용). ledger 는 볼트 산출물에 그려져
  트랙 A 에선 목업 없이 '셋업 안내'만 떴다 — review-run 이 물렸던 바로 그 함정. `LEDGER_FIXTURE`(과목 3·
  챕터 10 · 단계별 furthest 분포)를 `boot()` invoke 스텁에 심고 `TABS` 에 넣어 **이식 _전에_** 다크/라이트
  베이스라인을 찍고 눈으로 확인한 뒤 옮겼다. 이식 후 두 스냅샷이 **threshold 안에서 통과**(픽셀 교체가
  반올림 오차만큼이었다는 신호) — mastery 에 이은 사고 0(5연속).
- **첫 `<button>` 히트맵 셀.** mastery 의 셀은 `<div>`(`cursor-default`)라 전역 규칙과 안 부딪혔는데
  ledger 셀은 `<button>` 이다 → control §15-7 규율이 여기서 처음 셀에 적용됐다: 전역 `button{}` 의
  border(1px)·padding(8/13)·radius(r-sm) 를 `border-0! p-0! rounded-xs!` 로 이기고 배경은 런타임 색
  인라인이 덮는다. 닫기 ✕·딥링크 버튼은 반대로 **전역 button 의 배경·테두리·hover 를 그대로 물려받아
  차이 나는 속성만**(딥링크: `rounded-md! p-2! font-semibold!`) 이겼다(과잉 `!` 회피 · §15-7 판정).
- **스냅샷 밖 오버레이 실렌더 확인**(§15-8 의 연장). 챕터 상세는 셀 클릭 시에만 뜨는 온디맨드 세부라
  fullPage 스냅샷에 안 잡힌다 — 임시 요소 스크린샷으로 다이얼로그·5단계 체크리스트·메트릭·딥링크(전역
  button `!` 오버라이드)가 실제로 그려지는지 확인한 뒤 커밋(스냅샷만 믿었으면 button 규율 결함을 못 봤다).

반픽셀 폰트(11.5/10.5/12.5px)는 mastery·review 선례대로 **인라인 없이 `--fs` 사다리로 반올림**했고
(11.5→`text-xs` 등), 히트맵 셀 gap 3px·radius 3px 도 mastery 선례대로 `gap-1`·`rounded-xs` 로 모았다.
