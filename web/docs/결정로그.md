# 결정 로그 (ADR) — web

> "왜 이렇게?"의 근거를 한 곳에. 코드 주석·메모리에 흩어진 결정을 승격. 새 큰 결정이 생기면 항목 추가(날짜·결정·이유·대안).

## 아키텍처

- **레이어 단방향 + eslint-boundaries** — 규모가 작을 때 구조에 선투자해 장기 유지보수·확장 비용을 낮춘다("기반 우선"). 역방향 결합을 런타임이 아니라 린트로 error 차단.
- **zustand + immer(스토어) / react-query(서버 상태)** — Redux 보일러플레이트 없이 관심사별 작은 스토어(useApp/useUI/useRuntime). 서버 조회·캐시는 react-query가 전담(중복 요청·무효화 표준화).
- **`useRuntime` 분리(B1/B3)** — plan-무관 캐시(`_ankiLive`·`_icsExport`…)가 `useApp.state`에 있으면 settle마다 참조가 갈려 `selectSchedule`이 무거운 `schedule()`을 통째 재계산. 별도 store로 빼 정확성/성능 확보. `_knowState`만 스케줄러 입력이라 state 잔류.
- **zod 스키마(lib/schema)** — 경계(디스크·API)에서 런타임 검증으로 손상 데이터 조기 차단.

## 스타일

- **CSS Modules 전면 전환** — 전역 클래스 201→27(앱 크롬만 전역). feature 스타일 충돌·드리프트 제거. 값은 전역과 픽셀 동일 유지가 전환 계약.
- **토큰 파생 + 액센트 노브** — `--acc` 하나로 soft/glow 파생, 과목색은 PALETTE 인덱스 파생(저장 안 함). 한 줄 교체로 전면 재색.
- **라임 기본 확정 · 다크+라이트 2테마** — 세피아 폐기.

## 런타임 / 빌드

- **serve.js = Node stdlib(무프레임워크)** — 로컬 단일 사용자 도구라 프레임워크 불필요. prebuilt dist 서빙 + `/api`. (⇒ 소스 수정 후 `npm run build` 필수 — 절대규칙 1.)
- **PWA `selfDestroying`** — 로컬+serve.js 백엔드 의존 도구라 오프라인 이득 ~0인데 SW precache가 "안 바뀐다" 마찰만 매일 유발 → SW 은퇴. 복구는 한 줄 제거.
- **React Compiler 채택** — 수동 memo 제거, 자동 메모이제이션. Rules of React는 eslint-react-hooks로 빌드 전 강제(bail 방지).
- **vendor 청크 3분할** — react(안정)·vendor·앱 코드로 캐시 적중률↑.

## 테스트

- **e2e는 serve.js OFF + `--disable-gpu` 핀** — 프런트 단독 렌더 검증, GPU↔SwiftShader 비고정이 flaky 원인이라 고정. `--update-snapshots`(=`e2e:update`)는 **기존 스냅샷을 안 덮는다**(변경분 미갱신) → UI를 바꿨으면 반드시 `npx playwright test -g <name> --update-snapshots=all`. 또 `reuseExistingServer:!CI`라 이전 세션의 낡은 dist preview(4173)를 재사용하는 함정 — 재빌드 후엔 4173 리스너 kill 확인.
- **커버리지 게이트** — `verify`에 포함. 신규 로직은 lib 순수함수로 빼 단위 테스트하는 게 기본.

## 계획 개편 — 일일 배치 레이어 + 계획 1탭 통합 (2026-07-18)

> 트리거: "계획표 짜는 탭들(주간 스케줄·학습 항목·연동)을 대대적 개편 — 일일 계획을 디테일하게, 굳이 따로 있을 필요 없다." 상세 설계 = `docs/계획개편-설계.md`(SSOT).

- **자동엔진은 폐기 아닌 '제안자 강등'** — `scheduler.schedule()`이 전 기간 자동초안을 깔고, 신규 `dayPlans[ds]` 수동 오버라이드가 그날의 진리. 규칙 #4(명시결정·엔진 자산 보존: 복습사다리·적응형·마감·숙달도·통계·.ics) 준수. 대안(엔진 폐기)은 파괴적이라 기각.
- **무마이그레이션 = 옵셔널 필드** — `dayPlans`·`tasks[]`·`ScheduleItem.start` 모두 `.optional()`. 기존 백업 JSON 100% 바이트호환(§2 N2). `applyDayPlans`는 **manual 날 없으면 완전 무동작**(자동 산출 불변)이 회귀 고정의 전제.
- **'계획' 호스트 1탭 + 3세그먼트(뼈대·과목·배치)** — schedule/routine/items를 hidden 강등, `SUBTAB_GROUPS`로 흡수(라우트·⌘K·g단축키 유지). 셸(`plan-host`)은 자체 화면 없이 배치로 리다이렉트(`shell:true`).
- **타임블로킹 은유** — 배치 = 투두 트레이(미지정 할일) + 캘린더(일/주/월). 할 일 = 공부 블록(스케줄러 소유) + **자유 할 일 `tasks[]`**(과제·심부름 등, 스케줄러 입력 아님·독립 오버레이). 미지정→드래그로 시간박기(`start` 부여). 학습 스케줄러 → 개인 플래너로 확장.
- **배치 기본 뷰 = 일(day)** — "오늘 계획 짜기"(Today CTA §7) 진입이 곧 오늘 편집기. 구 `SchedView`(overview/cards)는 `week`로 흡수(preprocess+`.catch('day')`, 부분손상 격리). 카드뷰는 위크보드와 정보 중복이라 제거.
- **복습 재씨앗은 guarded 후처리(§4-3)** — `reseedManualReviews`가 `applyDayPlans` 직후 수동 날의 `new` 블록 하류 복습을 보강하되, **manual 날 없으면 무동작**(자동 불변)이고 대상 날에 이미 그 챕터 rev가 있으면 skip(이중계상 방지). 인라인 자동 씨앗 경로는 불변 — 회귀 위험 격리.
- **볼트 불러오기는 코드 이동 아닌 lib 공유** — 레이어 경계상 feature→feature import 금지라, 과목 세그먼트는 `items/VaultImport`가 연동 탭 `VaultPanel`과 **같은 `lib/vault` 함수·같은 쿼리 캐시(['vault'])**를 호출(두 곳에서 같은 훅). 해제/트리 상세는 연동 탭 소유.

## 계획 재개편 v2 — 주간 배분 보드 중심 (2026-07-18)

> 트리거(2차 피드백): "조잡하고 중심이 없다. 계획에서도 중심이 한눈에 일정 보여주며 거기서 짜야. 과목 주당 시간을 정하면 요일에 배분(3h→월2·목1)하면 할당 끝, 그게 안 된다." 상세 = `docs/계획개편-설계.md` §12(SSOT).

- **v1이 놓친 층 = '주간 배분'** — v1은 전략(주당h)→투두→하루 타임박스로 이었는데, 그 사이 "이번 주 과목 예산을 요일에 배분"하는 면이 없었다. 그래서 계획을 열면 하루 화면(중심 부재)이고, 요일 분배는 `scheduler` 블랙박스뿐(내가 짠다 감각 없음). → **주간 배분 보드(과목행×요일열)를 계획의 중심으로 신설.**
- **배분이 `new` 요일 분배를 주도, 엔진은 그 위에 복습/Anki/모의 자동** — 사용자 3결정: ①중심=배분 보드 ②배분 주기=**매주 새로**(반복 템플릿 아님) ③엔진=배분 주도·복습/Anki만 자동. 규칙 #4 보존(엔진 자산 유지, `new`의 요일 분배 결정권만 사용자에게).
- **`weekAlloc` = dayPlans 패턴의 주(週) 층 일반화** — `weekAlloc[weekMon][sid]=분[7]`(index=wd). 옵셔널·무마이그레이션. `scheduler` step5: 배분 있는 주는 alloc 벡터로 `new` 구동+`continue`, **없는 주는 자동 100% 불변**(dayPlans 불변식 동형, `scheduler.test` 42개 그대로 통과로 증명). 복습 씨앗은 `pushReviewTasks` 헬퍼로 auto·alloc 두 경로 공유(산출 동형). `SCHEDULE_INPUT_KEYS`에 등록(invariants.test가 강제).
- **보드 초기값 = 자동 파생, 첫 편집 시 managed 승격** — 무배분 주 보드는 `res.days`의 그 주 `new` 분을 (sid,wd) 집계해 표시(=현 자동 분배가 시작점). 첫 셀 편집이 그 스냅샷을 `weekAlloc[wk]`로 승격(`ensureWeekAlloc`, dayPlans `ensureManual` 동형).
- **배치 기본 뷰 day→alloc** — 계획 열면 배분 보드 착지(중심). 저장된 뷰가 있으면 우선(`.catch('alloc')`). 뷰 스위치 [배분·일·주·월], 배분/주가 weekOffset 주네비 공유. 요일 헤더 클릭→그날 일 편집기 드릴다운(전략=보드, 전술=타임박스).
- **완료 과목 헛경고 억제** — 챕터를 다 끝낸 과목은 예산이 남아도 "Nh 남음"이 아니라 "완료 ✓"(itemStat.finished 참조) — 더 배분하라 조르지 않게.

## 계획 UX 폴리시 + 블록 모델 (2026-07-18)

> 트리거(3차 피드백): "배분 보드 UX/UI가 조잡·접근성·조망성 부족" + "+블록이 같은 과목이면 하나로 누적된다 — 별도 블록이어야, 블록 길이도 바꿀 수 있어야."

- **배분 보드 = 값의 시각적 무게로 읽는다** — 셀에 배분 분량 비례 과목색 채움(`fillAlpha` 0.16~0.5)으로 주(週) 부하를 한눈에. 균일 회색 스프레드시트(숫자 나열)는 "한눈 조망" 목표에 반한다.
- **드래그 배분은 순수 편의 레이어, 접근성 정본은 숫자 입력** — 과목 행을 요일 칸에 드롭하면 +1h. 셀은 `<input type=number step=0.5>`라 ↑↓·타이핑이 이미 WCAG 2.1.1 대안 → 드래그에 별도 키보드 대안 불필요(드래그는 마우스 편의만 얹음). 드롭은 잡은 과목 행에만 허용(과목→요일 의미 유지).
- **모바일 = 스티키 좌우 열(설계의 아코디언 대신)** — 좌(과목명)·우(예산상태) 열 + 헤더 행을 `position:sticky`로 고정, 요일만 가운데서 스크롤. 설계 §12-6의 "과목 아코디언"과 **같은 목표**(가로 스크롤에도 라벨·상태 유지)를 훨씬 저위험으로 달성. 함정: `.grid overflow:hidden`이 sticky 컨테이닝 블록을 가로채므로 제거하고 네 모서리 셀 라운딩으로 대체.
- **리드아웃 = 배분과 직접 관계된 숫자만** — 오해 소지 '가용 113h'(주당 수십h 총량) 제거, **배분/주당예산 · 달성%**로. 툴바 중복 배분합도 제거(상단 크롬이 소유).
- **+블록 = 별도 블록(병합 제거) + 블록별 완료** — 같은 sid|type 누적 병합(`addOrMergeBlock`)을 `addBlock`(독립 블록)으로. 충돌(완료키가 `sid|type` 그날 단위라 한 체크가 둘 다 토글)은 **블록별 `done` + 집계 미러링**으로 해소: `setBlockDone`이 `block.done`을 세팅하고 `completions[ds][sid|type]`를 그날 done 블록들의 **OR/합**으로 재계산. 하류(스케줄러 복습씨앗 `pushReviewTasks`·통계·.ics는 이 집계만 읽음)는 **무변경**. 대안(완료키에 blockId 추가)은 하류 전면 개편이라 기각. 승격 시 기존 `sid|type` 완료를 블록 `done`으로 시딩(체크 유실 방지 · 승격 시엔 키당 1블록이라 무모호).
- **블록 길이 인라인 편집 = 스테퍼 버튼** — 트레이 블록/할일에 −/＋ 30분 스테퍼. `<input>`은 `draggable` 행과 텍스트 선택·드래그가 충돌해 버튼으로(타임라인 카드는 기존 리사이즈/편집바 유지).
- **efficacy 안내** — 계획상 챕터를 다 배우게 된 과목(`itemStat.finished`)에 배분해도 `new` 블록은 안 생기고 복습·Anki만 얹힌다(엔진의 챕터 소진 판정). "배분했는데 왜 안 굴러가나"를 보드 노트로 명시(엔진 시맨틱은 규칙 #4로 불변 — 안내만).

## 계획 재개편 v3 — 뼈대·과목 병합, 상세는 시트로 (2026-07-18)

> 트리거(4차 피드백): "과목하고 뼈대 탭을 합치면 좋겠다 — 과목 탭 유형으로 가되 층을 나눠 위=뼈대·아래=과목/볼트, 오른쪽에 가용시간. 배분도 흡수. 과목 누르면 아래로 펼쳐지는 게 아니라 탭 프레임보다 작은 새 페이지가 떠서 그 과목 배분까지."

- **계획 3세그먼트 → 2세그먼트(과목·배치)** — 뼈대(가용시간·수업·일과)와 과목은 둘 다 "정의"(가끔 정하는 것)이고 배치는 "운영"(매일 보는 것)이다. 리듬이 같은 둘을 한 층위에, 다른 하나를 옆에 두는 게 맞다. `SUBTAB_GROUPS=['plan-host','items','schedule']`.
- **병합 = 폴더 물리 이주(경계 규칙의 강제)** — `eslint-plugin-boundaries`가 `features → features` import를 error로 막으므로 화면만 합칠 수 없다. `routine/{Routine,DayRing}` → `items/{SkeletonPanel,DayRing,AvailRail}`로 이동. `routine` 키는 **리다이렉트 shim**만 남겨 `g o`·⌘K·기존 `/routine` 딥링크와 invariants(TABS↔LOADERS 패리티)를 지킨다.
- **배분은 '흡수'가 아니라 '미러'** — 사용자 원안은 배분 보드를 과목 탭에 흡수였으나, 보드의 핵심 가치는 셀 편집이 아니라 **열 합계(요일별 배분/가용 초과)** 라는 교차 조망이다. 과목 상세는 매트릭스의 **한 행**만 보여줄 수 있어 "화요일이 이미 초과인지"를 못 보여준다 — 재개편 v2가 세운 '배분 보드=계획의 중심'과 정면 충돌. 그래서 **보드는 배치에 그대로 두고**, 상세 시트와 우측 레일이 같은 `lib/weekAlloc`(allocView/setAllocCell/colSumMin)을 호출한다. **두 입구, 한 진실**(별도 상태 없음 → 자동 동기).
- **아코디언 → 중앙 시트** — `ItemCard` 제자리 펼침은 뒤 카드를 밀어 갤러리 조망을 깨뜨렸다(과목이 늘수록 악화). `SubjectSheet`가 뒤 갤러리를 그대로 둔 채 한 과목만 판다. 카드는 '읽는' 물건, 편집은 전부 시트가 소유. 시트 안에서 **정의(주당 목표·챕터·마감)와 배분(요일 7칸)을 함께** 정한다 — 예산과 분배가 갈라져 왕복하던 문제 해소.
- **`DetailDrawer`에 `placement='center'` + body 포털** — 셸 조상이 스태킹 컨텍스트를 만들어, 포털 없이는 `position:fixed`가 뷰포트가 아닌 그 조상 박스 기준으로 잡히고 z-index도 갇힌다(헤더·사이드바가 오버레이를 덮고 패널 헤드가 잘림). 중앙 시트를 만들며 드러난 **기존 우측 드로어의 잠재 결함**이라 컴포넌트 차원에서 고쳤다.
- **뼈대도 같은 중앙 시트(제자리 펼침 아님)** — 처음엔 요약 스트립 + 인라인 펼침으로 짰으나, 그건 `ItemCard` 아코디언을 걷어낸 이유(뒤 콘텐츠가 밀려 조망이 깨짐)를 그대로 반복하는 것이었다. **한 탭 안에서 '펼침'과 '시트' 두 어휘를 섞지 않는다** — 요약 바는 상시(가용·수업·일과), 편집기는 과목과 동일한 `DetailDrawer placement='center'`로. 시트 안에서 수업·일과 카드는 2열.
- **reduced-motion 백스톱에 delay 0 추가(기존 결함)** — 전역 백스톱이 `animation-duration`만 0.01ms로 죽이고 `animation-delay`는 남겨둬, `ds.card`의 스태거(nth-child 0.05~0.24s)가 `fill-mode:both` 탓에 지연 구간 내내 `opacity:0`에 머물렀다. 모션 자제 사용자에게 카드가 최대 240ms 비는 건 '즉시'가 아니다 → `animation-delay/transition-delay: 0s !important`. `data-fx='lite'`도 동형. (시트 스냅샷이 두 번째 카드를 투명하게 박으면서 드러난 **선재 결함** — 병합 작업이 만든 게 아니다.)
- **시각 스냅샷은 뷰포트 캡처 + 불투명 대기** — 시트는 `position:fixed`라 `fullPage`가 스크롤 오프셋만큼 어긋나게 그린다(헤더 누락·좌측 잘림). 또 `toBeVisible`은 opacity를 보지 않아 진입 애니 첫 프레임을 박을 수 있어, 카드 `opacity:1`을 명시적으로 기다린 뒤 찍는다.
- **요일 막대 = 용량 위 적재** — 우측 레일 막대의 중립 틀=그 요일 가용, 안쪽 액센트 채움=이번 주 배분(초과면 `--bad`). 보드의 열 맥락을 과목 탭에 **최소한으로** 이식한 것 — 시트에서 칸을 채울 때 "그 요일이 찼는지"를 레일에서 읽으라는 뜻.

## 계획 재개편 v4 — 캘린더 독립·배분 승격, 캘린더 재작성 (2026-07-18)

> 트리거(5차 피드백): "캘린더뷰(일·주·월)가 가장 앞, 그다음 배분을 독립탭으로, 그다음 과목 순. 그리고 캘린더 뷰 아직 너무 조잡하다 — TickTick을 보고 디테일하게."

- **계획 세그먼트 = [캘린더 · 배분 · 과목]** — 배분은 주(週) 단위로 한 번 정하는 '전략', 캘린더는 매일 보는 '전술'이라 리듬이 다르다. 뷰 스위치(`schedView`) 안에 섞여 있으면 계획의 축이 흐려져 `alloc`을 독립 탭으로 승격했다. `schedule`은 '배치'→'캘린더'로 개명하고 [일·주·월]만 소유. 기본 착지도 배분→캘린더 주 뷰로(`defaultUI().schedView='week'`).
- **`alloc`도 폴더 물리 이주** — v3의 뼈대와 같은 이유(`features→features` import 금지). `schedule/AllocBoard` → `alloc/AllocBoard`. 옛 저장본의 `schedView:'alloc'`은 `migrateSchedView`가 `week`로 흡수(캘린더의 뷰가 아니게 됐으므로).
- **탭 경계를 넘는 드릴다운은 URL이 통로, 뷰 전환은 보내는 쪽이** — 배분 보드의 셀/요일 클릭 → 캘린더 일 뷰. 한 컴포넌트 안일 땐 `setAnchorDs+setView`로 끝났지만 이제 탭이 갈렸다. 받는 쪽 effect에서 `setState`로 되받는 건 캐스케이드 렌더라 린트가 막는다(`react-hooks/set-state-in-effect`) → **보내는 쪽이 `setSchedView('day')` 후 `/schedule?ds=`로 이동**하고, 받는 쪽은 `?ds=`를 `useState` 초기값으로만 읽는다.
- **주 캘린더 전면 재작성 — 비율 배치 → 고정 픽셀 격자** — 옛 구현은 하루를 열 높이 100%에 매핑하고 3시간 격자를 그렸다. 그 결과 30분 세션이 몇 px로 뭉개져 이름조차 안 보였다(사용자가 "조잡"이라 부른 실체). **1시간=48px 스크롤 격자**로 바꾸고 30분 보조선·현재 시각 라인+배지·마운트 시 '지금'으로 자동 스크롤을 얹었다.
- **겹침은 `packLanes`(순수 함수 · lib)** — 겹치는 일정을 나란한 레인으로. 폭 분모는 **그 클러스터의 레인 수**다(전역 최대가 아니라) — 하루 한 번 3중 겹침이 났다고 나머지가 다 1/3로 쪼그라들면 안 된다. DOM·픽셀 무관이라 `test/packLanes.test.ts` 8케이스로 잠갔다.
- **시각 없는 것은 시간축에 두지 않는다** — 마감·미배치 학습을 상단 **종일 행**으로 분리(옛 구현은 시간축 안에 배지로 섞여 있었다).
- **월 뷰: 히트맵 → 일정 칩 격자** — 히트맵은 "얼마나 했나"만 답했고 **그날 뭘 하는지**를 못 보여줬다. 칸마다 과목 색점+이름 칩 + "+N개 더". 히트맵의 가치(달 부하 리듬)는 버리지 않고 칸 배경 옅은 틴트로 계승 — **칩은 '무엇', 틴트는 '얼마나'**.
  - 칩 정렬은 `new > mock > blank > rev > anki`. 매일 도는 Anki가 매 칸 첫 줄을 차지하면 달 전체가 같은 모양이 돼 아무것도 안 읽힌다.
  - 칸은 `[날짜 / 칩(잘림) / +N(바닥 고정)]` 3행 격자 — 단순 flex+overflow면 넘칠 때 "+N"까지 잘려 *더 있다는 사실 자체*가 사라진다.
  - 칸 최소 높이 76px + 부족하면 세로 스크롤. 6주를 720px 창에 1fr로 나누면 칸이 54px가 돼 둘째 칩이 반쯤 잘렸다 — **잘린 칩은 정보가 아니라 노이즈**(읽히지도, 없지도 않음).
- **월 네비는 공통 nav가 소유** — 뷰 본문이 자체 헤더를 또 그리면 헤더가 두 줄이 되고 정작 nav 줄은 뷰 스위치만 남아 빈 띠가 된다. 주 뷰의 주 이동과 같은 자리·같은 문법으로 통일.
- **`scrollTo` 대신 `scrollTop` 대입** — 초기 스크롤 위치엔 애니메이션이 불필요하고, jsdom엔 `Element.scrollTo`가 없어 테스트에서 컴포넌트가 통째로 터진다(실제로 그렇게 깨졌다).
