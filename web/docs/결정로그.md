# 결정 로그 (ADR) — web

> "왜 이렇게?"의 근거를 한 곳에. 코드 주석·메모리에 흩어진 결정을 승격. 새 큰 결정이 생기면 항목 추가(날짜·결정·이유·대안).

## 아키텍처

- **레이어 단방향 + eslint-boundaries** — 규모가 작을 때 구조에 선투자해 장기 유지보수·확장 비용을 낮춘다("기반 우선"). 역방향 결합을 런타임이 아니라 린트로 error 차단.
- **zustand + immer(스토어) / react-query(서버 상태)** — Redux 보일러플레이트 없이 관심사별 작은 스토어(useApp/useUI/useRuntime). 서버 조회·캐시는 react-query가 전담(중복 요청·무효화 표준화).
- **`useRuntime` 분리(B1/B3)** — plan-무관 캐시(`_ankiLive`·`_icsExport`…)가 `useApp.state`에 있으면 settle마다 참조가 갈려 `selectSchedule`이 무거운 `schedule()`을 통째 재계산. 별도 store로 빼 정확성/성능 확보. `_knowState`만 스케줄러 입력이라 state 잔류.
- **zod 스키마(lib/schema)** — 경계(디스크·API)에서 런타임 검증으로 손상 데이터 조기 차단.

## 스타일

- **CSS Modules 전면 전환** — 전역 클래스 201→27(앱 크롬만 전역). feature 스타일 충돌·드리프트 제거. 값은 전역과 픽셀 동일 유지가 전환 계약.
- **토큰 파생 + 액센트 노브** — `--acc` 하나로 soft/glow 파생, 과목색은 PALETTE 인덱스 파생(저장 안 함). 한 줄 교체로 전면 재색.
- **라임 기본 확정 · 다크+라이트 2테마** — 세피아 폐기.

## 런타임 / 빌드

- **serve.js = Node stdlib(무프레임워크)** — 로컬 단일 사용자 도구라 프레임워크 불필요. prebuilt dist 서빙 + `/api`. (⇒ 소스 수정 후 `npm run build` 필수 — 절대규칙 1.)
- **PWA `selfDestroying`** — 로컬+serve.js 백엔드 의존 도구라 오프라인 이득 ~0인데 SW precache가 "안 바뀐다" 마찰만 매일 유발 → SW 은퇴. 복구는 한 줄 제거.
- **React Compiler 채택** — 수동 memo 제거, 자동 메모이제이션. Rules of React는 eslint-react-hooks로 빌드 전 강제(bail 방지).
- **vendor 청크 3분할** — react(안정)·vendor·앱 코드로 캐시 적중률↑.

## 테스트

- **e2e는 serve.js OFF + `--disable-gpu` 핀** — 프런트 단독 렌더 검증, GPU↔SwiftShader 비고정이 flaky 원인이라 고정. `--update-snapshots`(=`e2e:update`)는 **기존 스냅샷을 안 덮는다**(변경분 미갱신) → UI를 바꿨으면 반드시 `npx playwright test -g <name> --update-snapshots=all`. 또 `reuseExistingServer:!CI`라 이전 세션의 낡은 dist preview(4173)를 재사용하는 함정 — 재빌드 후엔 4173 리스너 kill 확인.
- **커버리지 게이트** — `verify`에 포함. 신규 로직은 lib 순수함수로 빼 단위 테스트하는 게 기본.

## 계획 개편 — 일일 배치 레이어 + 계획 1탭 통합 (2026-07-18)

> 트리거: "계획표 짜는 탭들(주간 스케줄·학습 항목·연동)을 대대적 개편 — 일일 계획을 디테일하게, 굳이 따로 있을 필요 없다." 상세 설계 = `docs/계획개편-설계.md`(SSOT).

- **자동엔진은 폐기 아닌 '제안자 강등'** — `scheduler.schedule()`이 전 기간 자동초안을 깔고, 신규 `dayPlans[ds]` 수동 오버라이드가 그날의 진리. 규칙 #4(명시결정·엔진 자산 보존: 복습사다리·적응형·마감·숙달도·통계·.ics) 준수. 대안(엔진 폐기)은 파괴적이라 기각.
- **무마이그레이션 = 옵셔널 필드** — `dayPlans`·`tasks[]`·`ScheduleItem.start` 모두 `.optional()`. 기존 백업 JSON 100% 바이트호환(§2 N2). `applyDayPlans`는 **manual 날 없으면 완전 무동작**(자동 산출 불변)이 회귀 고정의 전제.
- **'계획' 호스트 1탭 + 3세그먼트(뼈대·과목·배치)** — schedule/routine/items를 hidden 강등, `SUBTAB_GROUPS`로 흡수(라우트·⌘K·g단축키 유지). 셸(`plan-host`)은 자체 화면 없이 배치로 리다이렉트(`shell:true`).
- **타임블로킹 은유** — 배치 = 투두 트레이(미지정 할일) + 캘린더(일/주/월). 할 일 = 공부 블록(스케줄러 소유) + **자유 할 일 `tasks[]`**(과제·심부름 등, 스케줄러 입력 아님·독립 오버레이). 미지정→드래그로 시간박기(`start` 부여). 학습 스케줄러 → 개인 플래너로 확장.
- **배치 기본 뷰 = 일(day)** — "오늘 계획 짜기"(Today CTA §7) 진입이 곧 오늘 편집기. 구 `SchedView`(overview/cards)는 `week`로 흡수(preprocess+`.catch('day')`, 부분손상 격리). 카드뷰는 위크보드와 정보 중복이라 제거.
- **복습 재씨앗은 guarded 후처리(§4-3)** — `reseedManualReviews`가 `applyDayPlans` 직후 수동 날의 `new` 블록 하류 복습을 보강하되, **manual 날 없으면 무동작**(자동 불변)이고 대상 날에 이미 그 챕터 rev가 있으면 skip(이중계상 방지). 인라인 자동 씨앗 경로는 불변 — 회귀 위험 격리.
- **볼트 불러오기는 코드 이동 아닌 lib 공유** — 레이어 경계상 feature→feature import 금지라, 과목 세그먼트는 `items/VaultImport`가 연동 탭 `VaultPanel`과 **같은 `lib/vault` 함수·같은 쿼리 캐시(['vault'])**를 호출(두 곳에서 같은 훅). 해제/트리 상세는 연동 탭 소유.
