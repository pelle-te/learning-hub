# 리뷰 템플릿 — web 변경분/feature

> `/리뷰`(web-reviewer 팬아웃)가 쓰는 관점을 사람이 PR·변경분에 직접 적용할 때의 체크리스트. 심각도순으로 `파일:라인 · 결함 · 근거 · 제안` 형식으로 기록.
> **리뷰는 결함 _발견_.** 품질을 _점수화_(추세)하려면 `평가루브릭.md` + `/평가`. 통과/실패 기계 검증은 `/게이트`.

## 1. 정확성 / 버그

- [ ] 경계값·null/undefined·빈 배열 처리
- [ ] async 레이스(중복 요청·언마운트 후 setState·순서 뒤집힘)
- [ ] 상태 무효화 정확성(특히 `useRuntime` 분리 캐시 vs `useApp` — §아키텍처 3)
- [ ] persist 계약 유지(flush 병합·split/merge 대칭 불변)
- [ ] 회귀: 기존 테스트가 이 변경을 덮나

## 2. 접근성 (a11y)

- [ ] 키보드 도달·포커스 순서·포커스 트랩(모달/팔레트)
- [ ] aria-current/label, 역할 정직성(가짜 tablist 금지)
- [ ] reduced-motion 백스톱, `fxLite` 존중
- [ ] 대비(토큰 기반), 터치 타깃 크기

## 3. 레이어 경계 / 재사용

- [ ] boundaries 단방향 준수(역방향 import 없음)
- [ ] 컴포넌트 내 인라인 계산 → `lib` 순수함수로 뺄 것
- [ ] 중복 로직(이미 lib/utils·scheduler 등에 있나)
- [ ] 새 전역 CSS 클래스 신설 금지(ds + module)

## 4. 성능

- [ ] 불필요 재렌더 유발(Rules of React 위반 → 컴파일러 bail)
- [ ] 렌더 경로의 무거운 계산(메모/lib 이관)
- [ ] 번들/청크 영향(`npm run budget`)
- [ ] 리스트 key·가상화 필요 여부

## 마감

- [ ] `npm run verify` + (시각 변경 시) `npm run e2e` 녹색
- [ ] 확신 없는 지적은 "PLAUSIBLE"로 표시, 과잉 지적 금지
