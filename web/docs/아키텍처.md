# 러닝 허브 웹앱 — 아키텍처 SSOT

> 레이어링·경계 계약·데이터레이어·백엔드의 **단일 진리**. 코드가 바뀌면 이 문서를 갱신한다.
> 요약·절대규칙은 `../../CLAUDE.md`, 이 문서는 _깊이_ 담당.

## 1. 레이어 (FSD식 단방향 의존)

```
app  →  features  →  components  →  {hooks, store}  →  lib
```

`eslint.config.js`의 `eslint-plugin-boundaries`가 이 방향을 **error**로 강제한다. 역방향(예: `lib`이 `store`를 import)은 빌드 전 린트에서 막힌다. 허용표:

| from         | import 가능                                                    |
| ------------ | -------------------------------------------------------------- |
| `app`        | features, components, hooks, store, lib, **shell**, shellToast  |
| `features`   | components, hooks, store, lib, **shell**, shellToast            |
| `components` | hooks, lib, **shellToast**(잎 모듈만 — 배럴 금지)              |
| `hooks`      | lib                                                            |
| `store`      | lib, **shellToast**(저장 실패를 알리는 유일한 통로)            |
| `shell`      | components, hooks, store, lib, shell, shellToast               |
| `shellToast` | lib                                                            |
| `lib`        | lib                                                            |

- ⚠ **`shell` 은 2026-07-26 감사(H10)에서 경계에 등록됐다.** 그전까지 어느 element 에도 안 잡혀
  "어느 레이어에서도 import 가능"한 예외였고, 그 예외로 **허용표상 금지인 `components → store` 가
  배럴 한 칸(`@/shell`)을 거쳐 통과**했다. `shell/toast/` 만 별도 element 로 가른 이유: zustand 단독
  모듈이라 스토어·IPC 사슬이 없고(실측), `store/useApp` 이 저장 실패를 알릴 유일한 통로다.
- 그 정리로 **팔레트·단축키 도움말이 `app/` 으로 이동**했다(App 만 렌더하고 액션·스토어·IPC 를
  무는 앱 크롬이라 `components` 계약을 애초에 만족하지 않았다). `queryClient` 는 `lib/` 로 —
  `@tanstack/react-query` 만 무는 순수 설정이고, `app/` 에 있던 탓에 SD-7 린트가 예외를 파야 했다.
- `main.tsx` 등 진입점·CSS import는 `no-unknown-files`/`no-unknown` off로 검사 제외.
  단 **`main.tsx` 는 별도 allowlist 로 더 좁게 묶인다**(SD-7) — `@/lib/**`·`@/styles/**` 외의
  `@/…` 정적 import 를 전부 막는다(스토어를 전이로 끌어오는 경로 차단).
- 경계 패턴은 `**/src/<layer>/**` (Windows 경로 정규화 이슈로 절대경로 매칭 — `eslint.config.js` 주석 참고).
- **원칙:** 하위 레이어는 상위를 _모른다_. `lib`은 순수 로직·IO(React 무관), `hooks`는 React 훅(lib만 소비·React 의존), `store`는 상태, `components`는 무상태 프리미티브, `features`는 탭, `app`은 셸.

## 2. 탭 시스템 — 2원천

탭은 **메타(shell)** 와 **구현(features)** 이 분리된다. 탭 추가 = **각 파일에 한 줄**.

1. **`shell/tabs.ts` — 탭 메타 단일 원천.** `TABS: TabMeta[]`(key·label·group·surface·order·hidden·icon·fill). 나브·팔레트·g단축키가 이걸 순회. 그룹(plan/train/collect/discover/settings)과 표면(study/materials · Wave⑥ 스위처)도 여기 정의 — **구체 로스터는 코드가 정본**(이 문서에 복제 금지 · 감사 #26).
   - `SUBTAB_GROUPS` — 흡수 탭: 호스트 탭 상단 섹션 세그먼트(SubTabs)로 접히는 그룹. 첫 항목=나브 노출 호스트. 현행 4그룹(plan-host·integrations·journal·stats 호스트)은 tabs.ts 참조. 라우트·딥링크·⌘K는 살아있다.
   - `hostTabKey`·`subTabGroupOf`·`orderedTabs`·`tabByKey`·`navGroups`·`surfaceOf` 헬퍼.
2. **`features/registry.tsx` — key→React 컴포넌트.** `LOADERS`(key→동적 import 썽크)를 `lazy()`로 감싸 `getReactTab(key)`. 같은 썽크를 `prefetchTab(key)`가 재사용 → 나브 hover/focus 시 청크 선로딩(즉시반응).

> **새 탭 절차는 `protocols/새탭추가.md`** — tabs.ts + registry.tsx + feature 폴더 + 테스트 + e2e 스냅샷.

## 3. 데이터 레이어 (store — 관심사별 분리)

| 스토어          | 소유                                                                         | 영속                                                                                               |
| --------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `useApp`        | 앱 데이터(plan·계획 상태) 단일 출처                                          | flush가 디바운스로 **`isSqlitePrimary()`(셸·폰)=SQLite** / dev 브라우저=localStorage(KEY)+IDB 미러 |

| `usePageChrome` | 탭별 헤더/서브탭 크롬                                                        | —                                                                                                  |

**왜 useRuntime 분리(B1/B3):** `_ankiLive`·`_icsExport`는 `schedule()` 입력이 아닌데 `useApp.state`에 있으면 settle마다 참조가 갈려 `selectSchedule`(참조 캐시)이 무거운 `schedule()`을 통째 재계산한다 → AppState 밖 별도 store로 뺐다. `_knowState`만 스케줄러 `graphPriority` 입력이라 state에 남는다(무효화가 정확성에 필요).

**persist 2계층 계약:** 내보내기(export)용 전체 JSON과 로컬 저장이 같은 형태. `mergeRuntime`(직렬화 직전 병합) ↔ `splitRuntime`(boot 직후 분리)이 대칭. 이 계약·테스트는 불변으로 유지.

### 3-1. 저장 백엔드 3종 (2단계~ · C-6 폰 추가)

**`AppState` 가 여전히 중앙 표현이고, 그 아래 sink 만 실행 경로에 따라 갈린다.**

| 실행 경로                          | 앱 상태 정본               | 비고                                                                                                            |
| ---------------------------------- | -------------------------- | --------------------------------------------------------------------------------------------------------------- |
| **Tauri 셸**(배포본)               | **SQLite**(plugin-sql)     | `lib/db/` — 부팅 읽기 → 편집마다 **변경된 행만** upsert                                                         |
| **폰 웹앱**(C-6 · Workers 오리진)  | **SQLite**(wasm+OPFS·워커) | `lib/db/browserDb.ts` — **`enableBrowserDb()` 로 명시 opt-in**(폰 진입점만). 같은 검증된 SQL 동기화 층을 재사용 |
| dev 브라우저(`npm run dev`·트랙 A) | localStorage + IDB 미러    | 개발·검증 전용 폴백. 없애면 dev 와 스냅샷 59장이 함께 죽는다                                                    |

- ⚠ **저장 경로 분기는 `isTauri()` 가 아니라 `isSqlitePrimary()`** 다(C-6). 폰은 Tauri 가 아닌데 SQLite 가 정본이라, `isTauri()` 로 막으면 폰 편집이 localStorage 로 새어 **아웃박스에 안 걸려 영원히 동기화되지 않는다**(조용한 유실). CLAUDE.md 가 반복 경고하는 그 부류.

- **I1(백업 호환)은 저장소와 무관하다** — export/import 는 계속 JSON 이고 `migrate`·`sanitizeImported`·`exportSnapshot` 은 한 줄도 안 바뀌었다. `migrate` 는 스키마 변환기가 아니라 **레거시 JSON 입력 정규화**라 앞으로도 import 경로에 남는다.
- **행 값 = 레코드 통째 JSON**(필드별 열 아님). `.passthrough()` 스키마의 모르는 필드가 열로 펼치면 왕복에서 증발한다. 질의가 필요하면 FTS5 를 파생으로 얹는다.
- **트랜잭션을 쓰지 않는다.** `tauri-plugin-sql` 은 sqlx 커넥션 풀이라 별도 `execute` 로 부른 `BEGIN` 이 다른 커넥션의 쓰기를 막아 `database is locked` 로 죽는다(실측). 대신 upsert + 사라진 키만 삭제라 **DB 가 비는 순간이 없고**, 중간에 죽어도 남는 건 "여분의 옛 행"이지 "사라진 행"이 아니다.
- **`journal_mode=WAL`** — 기본 롤백 저널에선 읽는 중 쓰기가 막혀, "닫기 직전에 상태를 읽으면 그 다음 쓰기가 통째로 실패"하는 형태로 드러났다.
- **창 닫기 가드**(`lib/tauri.ts` `installCloseGuard`) — 비동기 쓰기는 `pagehide` 로 못 지켜진다(실측). 닫기를 보류하고 쓰기 완료를 기다린 뒤 `destroy()`. `core:window:allow-destroy` 와 **항상 같이 간다**.
- ⚠ **`selectors.ts` 캐시 3종은 이 변화와 무관하다.** 그건 저장소가 아니라 zustand 알림 의미론 + immer 참조 동등성의 산물이라, 전체 상태가 메모리에 남는 한 존재 이유가 그대로다.

### 3-2. 볼트 읽기 (플랫폼 개편 3단계~)

| 실행 경로     | 볼트 접근                          | 갱신                      |
| ------------- | ---------------------------------- | ------------------------- |
| **Tauri 셸**  | `src-tauri/src/vault.rs`           | **notify 감시 → 자동**    |
| 브라우저(dev) | File System Access(`lib/vault.ts`) | 사용자가 버튼을 눌러야 함 |

- **폴더 선택·권한 개념이 셸엔 없다.** `workspace.rs` 가 워크스페이스를 알고 볼트는 `<workspace>/knowledge` 이므로 물을 이유가 없다. IDB 핸들 영속(`vaultHandle`)·`queryVaultPermission`/`requestVaultPermission` 분기는 **브라우저 경로에만** 남는다.
- **파일 감시는 셸에서만 가능하다** — FSA 에 watch 가 없다(설계 §10 이 OPFS 대안을 탈락시킨 근거). 그래서 "볼트가 바뀌면 앱이 스스로 안다"는 성질은 원리적으로 셸 전용이다.
- ⚠ **집계는 `subjectsFromIndex` 하나가 소유한다.** Rust 도 FSA 도 **노트 레코드까지만** 만든다. 예전엔 인덱스 경로와 파일 스캔 경로가 각자 집계해 **같은 볼트에서 숫자가 갈렸다** — 깊이 2단 고정으로 노트 **46%(519 중 239)** 를 조용히 버리고 있었고, `verified` 판정 방식도 달랐다. 생산자를 늘리더라도 집계는 늘리지 않는다.

### 3-3. 클라우드 동기화 — 다기기 (C-1~C-5 · SSOT=`클라우드전환-설계.md`)

**목적: 여러 기기(PC 셸·폰 웹앱)에서 같은 앱 데이터를 보고 편집한다.** 앱 데이터만 클라우드로 가고, 로컬 자원(볼트·산출물·AI)은 각 PC 에 남는다. 각 기기는 로컬 SQLite 사본을 정본처럼 쓰고, **행 단위 LWW** 로 밀어올리고(push) 받아온다(pull). 어느 시점에도 **진짜 정본을 쥐는 주체는 서버 하나**다(불변식 I7).

| 층                                | 무엇                                                                                                                                                                           |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `server/`                         | **Cloudflare Workers + D1** — 정본. 인증(기기 단위 토큰)·입력검증(zod)·한도. 게이트 `cd server && npm run verify`(실 workerd+D1 왕복)                                          |
| `web/src/lib/cloud/`              | `outbox`(보낼 것 수집)·`push`(재시도·백오프)·`client`(pull·전송 분기)·`merge`(받은 것 병합)·`run`(`syncOnce`=push→pull→merge)·`schema`·`contract`(서버와 **문자 그대로 공유**) |
| `web/src/store/syncController.ts` | **구동**(언제 동기화하나) — 이벤트 기반(부팅·복귀·이탈·편집후) + 데스크톱 폴링 보조. 병합 결과를 메모리에 반영                                                                 |
| `src-tauri/src/cloud.rs`          | 데스크톱 HTTP 중계 — 웹뷰 CSP(`connect-src 'self' ipc:`)가 직접 `fetch` 를 막아 Rust 가 중계(폰은 진짜 브라우저라 직접 `fetch`)                                                |

- **정합 모델**: LWW(`updated_at` 큰 쪽 승) + **툼스톤**(삭제 부활 방지 — 그냥 지우면 상대가 되살린다) + **fence/워터마크**(오프라인 큐 · 스캔 도중 쓰기가 워터마크 아래로 묻히는 조용한 유실 방지). 워터마크가 **둘**이다: `watermark`(어디까지 보냈나) · `cloud:pullMark`(어디까지 받았나) — 겸직시키면 조용히 틀린다.
- ⚠ **서버 SQL 과 클라이언트 병합 SQL 은 같은 모양**이어야 한다(`server/src/index.ts` ↔ `lib/cloud/merge.ts`). 한쪽만 고치면 **기기마다 병합 결과가 갈린다** — 이 프로젝트에서 가장 비싼 버그류(재현이 기기 의존).
- **동기화 대상**: `AppState` 행(`rows.ts` 의 `OUTBOX_TABLES`) + 사용자 저작물(`docs`). **제외**: `runtime_cache`(재계산 가능)·`meta`(상태 파생 — LWW 로 병합하면 원본과 어긋난다).
- ⚠ **동기화 코어를 만졌으면** dev 로 끝내지 말 것 — dev 는 CSP·오리진이 느슨해 그 부류 결함을 못 본다. 릴리스 exe 로 **트랙 B 1회** + `server` 게이트.

## 4. 백엔드 (`src-tauri/` — Rust 커맨드. **서버 프로세스 없음**)

> **4단계에서 `serve.js`(Node HTTP :8000)를 삭제했다.** 라우트 12종이 전부 Tauri 커맨드가 됐고,
> **앱이 여는 포트는 하나도 없다.** 그 결과 HTTP 공격면(Host 위조·CSRF·경로 traversal·정적 서빙)이
> "방어했다"가 아니라 **"그런 표면이 없다"** 로 닫혔다. serve.js 의 26개 회귀 테스트는 Rust
> `#[cfg(test)]` 통합 테스트(산출물·도구·볼트·Anki·탐구)로 이관됐다(SSOT=`src-tauri/src/testkit.rs`).

**커맨드 목록은 `src-tauri/src/lib.rs` 의 `generate_handler!` 가 SSOT — 여기 나열하지 않는다**
(탭 로스터와 같은 이유. 옛 라우트 표는 한때 6개만 적어 절반이 빠졌고 CLAUDE.md·설계 문서와도 서로 달랐다).

부류만: 능력 탐지(`capabilities`) · 산출물 8종(`artifact_read`) · 파이썬 도구 11종(`run_tool`) ·
탐구 잡(`research_*`) · AI 5종(`ollama_run`·`ollama_embed`) · 뉴스(`atlas_news`) ·
볼트(`vault_scan` + `vault:changed` 이벤트) · 내보내기(`save_text_file`) · Anki 중계(`anki_connect`).

- **경계는 둘뿐이다**: 프런트에서 `invoke` 를 부르는 곳은 `web/src/lib/tauri.ts` 하나(불변식 I2),
  셸/브라우저 전송 분기는 **모듈당 한 곳**이다 — 백엔드 커맨드는 `lib/api.ts`, 클라우드는
  `lib/cloud/client.ts`, Anki 는 `lib/anki.ts`. 소비처 20여 곳은 전송을 모른다.
  (⚠ 옛 문구는 "`lib/api.ts` **안에만**"이었는데 실제로는 셋이다 — 사상("모듈당 한 곳")은
  지켜지고 있었고 문구만 낡았다. 2026-07-26 감사에서 정정.)
- **실패는 봉투로 온다**(`{ok:false,error}`) — 소비처가 `.ok` 로 분기하고 있어서다. 산출물만 예외로
  throw 하되 '미생성'은 `HTTP 404` 로 번역해 `artifactState` 의 기존 분류를 유지한다.
- **동시성 캡은 RAII**(`tools.rs` `Cap`) — 해제 누락·이중 해제가 타입 수준에서 표현 불가능하다.
- **브라우저(dev·트랙 A)엔 백엔드가 없다.** 트랙 A 는 산출물 5종만 `__TAURI_INTERNALS__.invoke`
  스텁으로 목업한다(IPC 는 `page.route` 로 못 가로챈다).

## 5. 빌드·PWA (`vite.config.ts`)

- **React Compiler(React 19)** — 빌드타임 자동 메모이제이션. 수동 memo/useMemo 불필요. 단 Rules of React 위반 시 조용히 bail → `eslint-plugin-react-hooks`가 위반을 빌드 전에 잡아 최적화 적용률 보장.
- **vendor 청크 3분할**: `react`(react/react-dom/scheduler) · `vendor`(그 외 node_modules) · 앱 코드. 캐시 적중률↑.
- **PWA SW — C-6 에서 `selfDestroying: false`(폰만 등록).** 옛 "은퇴"는 앱이 `localhost:8000`+serve.js 로 뜨던 시절 판단이고 그 오리진이 죽으며 뒤집혔다. 지금 SW 가 살 수 있는 오리진은 **폰이 도는 Workers 오리진 하나**뿐 — 데스크톱 셸은 `tauri://` 로컬 파일, 트랙 A 는 `serviceWorkers:'block'`. 등록은 `phone/main.tsx` 가 명시적으로(`injectRegister:null` 이라 데스크톱 `index.html` 엔 안 박힌다). 폰엔 오프라인 셸 이득이 실재(지하철에서 열면 셸 없이는 아무것도 안 뜬다 · 데이터는 OPFS 에 있어도). dev 는 SW off.
- 별칭 `@` → `src`. ⚠ dev `/api` 프록시는 **제거됐다**(4단계 — 프록시할 대상이 없다).

## 6. 테스트 — **5개 층**(각 층이 다른 종류의 진실을 잠근다)

새 스택이 생기면서 "정적 검사 전량 녹색인데 실물에서 죽는" 부류에 반복해 물렸다. 그래서 검사를 **무엇이 필요한가**로 배치한다: 실물(진짜 워크스페이스·DB·볼트)이 필요하면 `cargo`, WebView2 안에서만 존재하면 트랙 B, 인터넷 노출·인증이면 `server`.

| 층                              | 무엇을 잠그나                                                                                                                           | 명령                                              |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| **Vitest**(jsdom)               | 단위·컴포넌트·순수 로직·매퍼 왕복                                                                                                       | `npm run test` / `test:coverage`(게이트)          |
| **트랙 A**(Playwright·Chromium) | 시각/동작 스냅샷. **백엔드 없이** 돌고 산출물만 invoke 스텁 목업 · `--disable-gpu` 핀 · `phone.spec` 이 폰 OPFS 저장소 실재를 관측      | `npm run e2e`                                     |
| **트랙 B**(릴리스 exe·WebView2) | **WebView2 에서만 깨지는 것** — 창·라우팅·IPC 왕복(Channel)·종료 flush·CSP·오리진. **스냅샷은 안 찍는다**(선행 `tauri:build:fast` 필요) | `npm run e2e:shell`                               |
| **cargo**(Rust)                 | **실물 통합** — 산출물·파이썬 도구·볼트 읽기/감시·Anki 스캔·탐구 잡·실 DB 스탬프. 초 단위(SSOT=`testkit.rs`)                            | `cargo test --manifest-path src-tauri/Cargo.toml` |
| **server**(실 workerd+D1)       | 인증·입력검증·정본 — 온보딩→토큰→push→pull→폐기 왕복. **인터넷에 노출되는 유일한 층**                                                   | `cd server && npm run verify`                     |

- 커버리지 게이트가 `npm run verify` 에 포함. 신규 로직은 lib 순수함수로 빼 테스트하는 게 기본 패턴.
- ⚠ **트랙 A 는 Chromium 이라 WebView2·CSP·오리진 결함을 원리적으로 못 본다** — "됐다" 전엔 릴리스 exe 로 트랙 B 1회. 트랙 B 는 **사용자 실 DB 를 쓰므로 쓰기 금지**(`LEARNING_HUB_E2E_DATA_DIR` 로 격리).
- `/게이트` 가 verify+build+budget+e2e(+cargo 있으면 tauri:check·build·e2e:shell)를 한 번에 돌린다. `server` 게이트는 별도(빼먹지 말 것).
