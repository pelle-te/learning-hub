# 계획 개편 설계 — 일일 배치 레이어 신설 + 계획 탭 통합

> 트리거: 사용자 요청(2026-07-18) — "계획표 짜는 탭들(주간 스케줄·학습 항목·연동 현황)을 대대적으로 개편. 일일 계획을 디테일하게 짤 수 있어야 하고, 굳이 따로따로 있을 필요 없다."
> 확정 결정(2026-07-18): ① **일일 배치 = 자동초안 + 수동 오버라이드**(엔진은 제안자로 강등, 버리지 않음) ② **'계획' 호스트 1탭 = 뼈대·과목·배치 세그먼트** ③ 설계 문서 선행(이 문서).
> 확정 결정 2차(2026-07-18): ④ **타임블로킹 은유** — 배치 세그먼트 = **투두 트레이 + 캘린더**(구글 캘린더 결). ⑤ 할 일 범위 = **공부 블록 + 자유 할 일**(과제·심부름 등) 둘 다 → 학습 스케줄러에서 **개인 플래너**로 확장. ⑥ **미지정 트레이 + 드래그로 시간박기**(untimed→time-boxed). ⑦ 캘린더 = **주(있음)+월(신규)**, 월 칸 = **학습량 히트맵 + 마감·할일 수**.
> 이 문서는 *설계*다. 구현은 §11 단계대로 서브에이전트 격리로 진행하고, 큰 결정은 `결정로그.md`에 승격한다.

> ⚠️ **SSOT 아님(2026-07-18 기준)** — 이 문서의 변경이력(§12)은 **v2에서 멈췄고** 코드는 v3·v4·v5·v6까지 갔다. 그 사이 결정은 전부 `결정로그.md`에 승격돼 있다. **계획 탭의 현행 정본은 `결정로그.md` + 코드** — 여기서 읽어야 할 것은 개편의 _동기와 최초 확정 결정_(위 3줄)이고, 화면 구성·컴포넌트 구조는 이미 다르다.

## 0. 한 줄 요약

지금 앱의 스케줄은 **전부 자동 파생**(주당 목표 → `schedule()`가 매일 블록 생성)이고, **사람이 하루를 직접 짜는 면(面)이 없다**. 이 문서는 (1) 빠진 **일일 배치 레이어**를 자동초안 위에 수동 오버라이드로 얹되 **타임블로킹**(투두 트레이 + 캘린더)으로 구현하고, (2) 흩어진 셋업 탭(일과·항목·연동 불러오기)을 **'계획' 호스트 한 탭의 3세그먼트**로 합치고, (3) Today의 중복 "주간 스케줄 확인" 버튼을 단일 "오늘 계획 짜기"로 정리한다.

**타임블로킹 은유(2차 결정)** — 전략층(주당h·챕터)은 **예산**으로 유지. 그 예산에서 **할 일 카드**가 흘러나오고(자동+수동, 공부 블록 + 자유 할 일), 사용자가 카드를 **캘린더 가용시간에 끌어다 시간박기(time-box)** 한다. 안 박은 건 **미지정 트레이**에 남는다. 자동엔진은 이 초안을 깔아주는 조수. 캘린더는 **주/월/일** 뷰.

```
전략(예산)         투두(할 일)                캘린더(타임박스)
이번주 물리 6h  →  □ 물리 3장 2h    ─┐         화 09 ───────
                   □ 물리 4장 2h     ├→ 드래그 →   14 █ 물리 2h
                   □ 과제 제출 ⏰17시 │            16 █ 수학 1h
   (자유 할 일)     □ 도서관 반납    ─┘  (미지정은 트레이에 잔류)
```

## 1. 문제 진단

### 1-1. 스케줄이 단방향 자동 파생 — 일일 계획 면이 없다

```
일과(routine 가용시간)            ┐
학습 항목(weeklyHours·챕터·마감)  ┤→ schedule() 가 new/rev/anki/blank/mock 블록을 매일 자동 생성 → today/schedule 은 "읽어 표시"만
연동(볼트→items 불러오기)         ┘
```

- `lib/scheduler.ts` `schedule()`: 주당 목표시간을 빈 시간에 **마감우선·인터리빙**으로 쪼개 블록 배분. 복습 사다리(+1·3·7·16일)·적응형 용량·숙달도 가중·모의·백지까지 전부 여기서 파생.
- `layoutDay()`: 그날 블록을 빈 창에 **자동 패킹**(피크 시간 우선)해 시각 배정. 사용자 개입 지점 없음.
- 사용자가 손댈 수 있는 유일한 지점: `dayOverrides[ds]` = 그날 **가용 _시간 수_** (`Schedule.tsx` DayHeadBar). **블록을 언제·몇 시간·무슨 과목으로 놓을지**는 어디서도 못 정한다.

→ 사용자가 말한 "원래라면" 깔때기에서 **마지막 칸(장기 계획 → 매일 구체 배치)이 통째로 없다.**

### 1-2. 세 가지 지적은 모두 같은 뿌리

| 지적                                                    | 코드 실체                                                                                                                                                 | 원인                                               |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| Today "주간 스케쥴 확인" 버튼 3개                       | `todayTotal===0 && hasItems`일 때 ①상단바 chrome 액션 `TodaySignature.tsx:373` ②히어로 `.mChip` `:428` ③큰 CTA `:527` (＋흐름 레일 빈상태 `:651`가 4번째) | 갈 곳이 "주간"뿐이라 전부 `/schedule`로 보냄       |
| "블록 없으면 주간으로 — 원래 오늘 스케줄 설정하러 가야" | 흐름 레일 빈상태 `:651` `주간 스케줄 확인`                                                                                                                | **"오늘 계획 짜기" 목적지가 없어서** 주간으로 우회 |
| "주간 탭 카드 뷰 따로는 불필요"                         | `schedView:'overview'                                                                                                                                     | 'cards'` `Schedule.tsx:367`, 카드뷰=요일 7장 나열  | 위크보드와 정보 중복 |

### 1-3. 계획 셋업이 4탭으로 흩어짐

`plan` 그룹: today · goals · schedule(+routine 숨은 서브탭) · degree · items. `discover` 그룹: integrations(볼트 불러오기가 여기). 사용자가 하나의 흐름으로 인지하는 "뼈대→과목→배치" 셋업이 3~4탭에 분산.

## 3. 정보구조 재편 — '계획' 호스트 1탭

### 3-1. 신설: `plan` 호스트 탭 + 3세그먼트

```
계획(plan-host)                      ← 나브 노출(surface=study, group=plan)
 ├─ 뼈대   (routine 이식)            ← 반복 캔버스: 가용시간·수업·일과
 ├─ 과목   (items + 볼트 불러오기)   ← 장기 범위: 과목·주당h·챕터·마감 + 인라인 import
 └─ 배치   (schedule 위크보드 + 일일 편집기)  ← NEW: 주간 예산을 매일 구체 블록으로
```

- 세그먼트 전환은 기존 `SubTabs` 계약(`SUBTAB_GROUPS`) 재사용 — 라우트·⌘K·g단축키 유지.
- `tabs.ts` 반영(초안):
  - 신설 `{ key:'plan-host', label:'계획', group:'plan', surface:'study', order:18, icon:'calendar', fill:true }` (today 다음, goals/degree 앞).
  - `schedule`·`routine`·`items`는 **`hidden:true`로 강등**(라우트·딥링크 유지), 배치 세그먼트의 하위로 흡수.
  - `SUBTAB_GROUPS`에 `['plan-host','routine','items','schedule']` 형태 추가(호스트=첫 항목). 세부는 구현 시 세그먼트 라벨(뼈대·과목·배치)로 매핑.
- **연동(integrations) 처리**: 텔레메트리·Anki 라이브·정본원장은 "모니터링"이라 자료 표면에 **잔류**. **볼트→항목 불러오기 액션(VaultPanel의 import 부분)만** 과목 세그먼트에 인라인으로 재노출(같은 store 액션 재사용, 코드 이동 아님 — 두 곳에서 같은 훅 호출).

### 3-2. 나브 효과

`plan` 노출 탭: today · **계획** · goals · degree (기존 today·schedule·items·goals·degree 5 → 4). routine/import 흡수로 셋업 진입이 한 곳.

> ⚠️ 리스크: 호스트 신설은 `test/invariants.test.ts`(LOADERS↔TABS 패리티)·나브 스냅샷·e2e에 영향. §11 Phase 1에서 스냅샷 재생성 전제.

## 4. 데이터 모델 — 일일 배치 오버라이드

### 4-1. 신규 타입 (schema.ts · 옵셔널 · 무마이그레이션)

```ts
// lib/schema.ts — AppStateSchema에 추가(옵셔널이라 기존 저장 100% 호환, passthrough)
const PlacedBlockSchema = z.object({
  id: z.string(),
  type: z.enum(['anki', 'new', 'rev', 'blank', 'mock']), // SessionType
  sid: z.string(), // 과목 id('mock'은 모의)
  name: z.string(),
  color: z.string().optional(),
  start: z.number().optional(), // 자정 기준 분(명시 배치) — layoutDay가 존중. **없으면 미지정(트레이)**.
  min: z.number(),
  chapters: z.array(z.string()).optional(),
  pinned: z.boolean().optional(), // 자동 재계산에서 보존
});
const DayPlanSchema = z.object({
  mode: z.enum(['auto', 'manual']), // manual = 그날 배치의 진리는 사용자
  blocks: z.array(PlacedBlockSchema),
});
// AppStateSchema: dayPlans: z.record(DayPlanSchema).optional()  // 키=ds(YYYY-MM-DD)
```

- `dayOverrides`(그날 가용 시간 수)와 **직교**: `dayOverrides`=용량, `dayPlans`=배치. 둘 다 그날 단위 오버라이드지만 층이 다르다.
- 신규 필드는 `RUNTIME_CACHE_KEYS` 아님 → 영속·백업·.ics 대상. 스키마 바이트호환은 `.optional()`로 확보(§2 N2).

### 4-2. 통합 지점 — 스케줄러는 제안, 오버라이드가 진리

`ScheduleItem`에 옵셔널 `start?:number` 추가(명시 배치 신호). 파이프라인:

1. `schedule()`는 **평소대로** 전 기간 자동 초안 생성(변경 없음 — 복습/적응형/마감/모의/백지 로직 보존).
2. **후처리 오버라이드 패스**(신규 `applyDayPlans(state, res)`):
   - `dayPlans[ds].mode==='manual'`인 날: 그날 `Day.items`를 `dayPlans[ds].blocks`로 **치환**(각 블록에 `start` 실림).
   - `pinned` 블록: 그 날이 여전히 auto여도 위치 고정(향후 auto 재실행 시 보존) — MVP에선 manual 전환이 기본, pinned는 재계산 대비 플래그.
3. `layoutDay()`: `start`가 실린 세션은 **그 시각에 배치**, 나머지 auto 세션은 그 주위 빈 창에 패킹(기존 `take/placeItem` 확장 — `start!=null`이면 우선 점유).

→ Today 흐름 레일·Schedule 아젠다·통계·.ics는 **최종 `res`만 읽으므로 자동으로 수동 배치를 반영**(렌더 코드 재사용, 신규 표시 경로 최소).

### 4-3. 크럭스 — 수동 배치와 복습 파생의 관계

**결정 필요/권고**: 자동엔진은 `new` 모듈을 배치하는 순간 복습(`reviewTasks`)을 씨앗한다(그날 배운 챕터 근거). 사용자가 **수동으로 추가/이동한 `new` 블록**도 그 하류 복습을 만들어야 일관적이다.

- 권고: 복습 씨앗 단계를, 주간 배분 루프 내부(자동만 봄) → **최종 day.items(자동+수동 통합)를 스캔**하는 별도 선(先)패스로 이동/보강. 앵커=완료일(doneDs) 규칙(②#23)은 그대로.
- 적응형 용량·마감 경고: 수동 배치가 가용을 초과해도 **강제 클램프하지 않음** — 대신 배치 세그먼트에서 "이 날 계획 X.Xh > 가용 Y.Yh" 경고(기존 DayFoot `over` 표식 재사용).

> 이 이동은 스케줄러 회귀 테스트(`scheduler.test.ts`)에 민감 → Phase 2에서 자동-only 경로가 기존과 100% 동일함을 먼저 고정(수동 없을 때 무변경)한 뒤 수동 경로 추가.

### 4-4. 자유 할 일(Task) — 투두의 원료 (2차 결정 ⑤⑥)

공부 블록(과목 파생)과 **별개로**, 과목에 안 묶인 자유 할 일(과제 제출·도서 반납·실험 보고서)을 1급으로. **공부 블록의 자동생성·복습 사이징은 스케줄러 소유라 건드리지 않고**, 자유 할 일은 독립 리스트로 얹는다(저위험 분리).

```ts
const TaskSchema = z.object({
  id: z.string(),
  title: z.string(),
  sid: z.string().optional(), // 연결 과목(선택) — 색·필터용. 없으면 순수 자유 할 일
  color: z.string().optional(),
  ds: z.string().optional(), // 배정 날짜(YYYY-MM-DD). 없으면 '언젠가'(인박스, MVP 선택)
  start: z.number().optional(), // 시각(분). 없으면 그날 **미지정 트레이**
  min: z.number().optional(), // 소요(선택) — 캘린더 블록 높이
  deadline: z.string().optional(), // ⏰ 마감(선택)
  done: z.boolean().optional(),
  doneDs: z.string().optional(),
  at: z.number().optional(), // 생성 시각(로그·정렬)
});
// AppStateSchema: tasks: z.array(TaskSchema).optional()  // 신규·옵셔널·무마이그레이션
```

**두 원료, 한 캘린더** — 일일 편집기·주/월 뷰는 두 소스를 **합쳐 렌더**한다:

|        | 공부 블록(study)                               | 자유 할 일(task)                        |
| ------ | ---------------------------------------------- | --------------------------------------- |
| 출처   | `schedule()` 자동 + `dayPlans` 수동 오버라이드 | `tasks[]` (전부 수동, 선택적 과목 링크) |
| 완료   | `completions[ds][sid                           | type]`(기존)                            | `task.done`(신규) |
| 시각   | `start`(auto=layoutDay, manual=사용자)         | `start`(없으면 트레이)                  |
| 방법론 | 복습 사다리·CBMS·백지 연결(기존)               | 없음(단순 체크)                         |

- **미지정 트레이** = `ds===그날 && start==null`인 항목(공부 블록·자유 할 일 공통). 드래그로 시각 부여 → 트레이에서 캘린더로 이동.
- 인박스('언젠가' = `ds==null`)는 MVP 선택 사항 — 넣으면 "날짜 미정 할 일" 서랍. 1차엔 제외 가능.

## 5. 세그먼트별 화면 설계 (탭재설계 사상 준수)

각 세그먼트는 `탭재설계.md` 4원칙(단일목적·상단 리드아웃·fill 프레임·온디맨드 세부)을 따른다. 상단 바 리드아웃은 세그먼트별로 스왑.

### 5-1. 뼈대 (routine 이식)

- 단일 질문: "매주 반복되는 내 가용시간은?"
- 현 `Routine.tsx` 거의 그대로(좌 편집기 수업·일과 / 우 24h 발광 링 + 요일 막대). 리드아웃: 주간 가용·선택요일·일평균.
- 변경: 하단 안내 문구의 "특정 날짜는 스케줄 탭" → "배치 세그먼트"로 문구 갱신.

### 5-2. 과목 (items + 불러오기 인라인)

- 단일 질문: "무엇을 얼마나(주당/장기) 공부하나?"
- 현 `Items.tsx`(과목 카드 갤러리 + 챕터 에디터) 그대로. 리드아웃: 과목·주당합계·챕터·마감.
- 추가: 헤더에 **"볼트/Anki에서 불러오기"** 인라인 액션(연동 VaultPanel import 훅 재사용). 빈 상태 EmptyState의 기존 `/integrations` 유도를 이 인라인으로 대체(탭 이동 없이).

### 5-3. 배치 (타임블로킹: 트레이 + 캘린더) — NEW의 핵심

- 단일 질문: "오늘/이번 주, 무엇을 언제 할까?"
- **뷰 스위치: [일] · [주] · [월]** (기존 `schedView` overview/cards 세그먼트를 이 3뷰로 교체 — **카드 뷰 제거**, §1-2).
- **좌: 투두 트레이**(항상) — 그날/이번주 **미지정 할 일**(공부 블록 + 자유 할 일) 리스트. 체크·추가·정렬. 여기서 캘린더로 드래그.
- **우: 캘린더**(뷰별):
  - **일** = 하루 타임라인(§6) — 가용창=드롭존, 고정 일과·타임박스 블록. 시간박기의 주무대.
  - **주** = `WeekCalendar` 확장(7일 타임 그리드 + 타임박스 블록·마감 플래그). 요일 클릭 → 일 뷰.
  - **월** = **학습량 히트맵**(§6-5) — 날짜 칸에 그날 학습량 색농도 + 마감 플래그 + 미완 할일 점. 날짜 클릭 → 일 뷰.
- 리드아웃: 이번 주 h·완료%·마감(기존 유지). `.ics` 내보내기 스트립 유지.

## 6. 일일 편집기 상세 (자동초안 + 수동 오버라이드)

사용자 확정 프리뷰:

```
[자동초안]  09:00 물리 2h  (엔진 제안)
              ↓ 손댐
[내 계획]   14:00 물리 3장 2h 📌핀
           16:30 수학 1.5h
           빈칸 + 과목 끌어놓기
```

### 6-1. 레이아웃 (트레이 + 캘린더 데이 컬럼)

- **좌 — 투두 트레이**: 그날 **미지정 항목**(공부 블록 + 자유 할 일)을 체크리스트로. 각 줄=제목·과목색·소요(선택)·⏰마감·체크. 상단 "+ 할 일"으로 자유 할 일 즉시 추가. 학습 항목의 과목 칩도 여기서 끌 수 있음(과목→`new` 블록).
- **우 — 하루 타임라인**(캘린더 데이 컬럼): 가용 창=드롭존(연녹), 고정 일과(수면·수업)=점유(회색), 타임박스된 블록/할일=과목색 카드(드래그·리사이즈).
- 상단 스위치: **[자동] ↔ [내 계획]** — 그날 `mode`. 자동=엔진 초안 표시(읽기), 손대는 순간 manual 승격.

### 6-2. 인터랙션

- **시간박기(핵심)**: 트레이 항목을 타임라인 가용창에 드래그 → `start` 부여(트레이에서 사라지고 캘린더에 카드). 반대로 카드를 트레이로 내리면 `start` 제거(미지정 복귀).
- **옮기기**: 캘린더 카드 드래그 → `start` 갱신. 겹치면 밀거나 거부(스냅 15분).
- **시간·길이**: 카드 리사이즈 핸들 또는 인라인 시각/분 입력.
- **추가**: "+ 할 일"(자유 할 일, 과목 링크 선택) / 과목 칩 드래그(공부 블록) / "+ 블록" → 유형(집중·복습·Anki·백지·모의).
- **완료**: 체크(공부=`completions`, 자유=`task.done`). **삭제**: ✕.
- **핀**: 📌 토글 → `pinned`. 핀 블록은 "다시 자동으로" 재계산에서 보존.
- **리셋**: "다시 자동으로" → `delete dayPlans[ds]`(핀 있으면 핀만 남기고 재초안 옵션). 자유 할 일(`tasks`)은 리셋 대상 아님(사용자 소유).

### 6-3. 상태 규칙

- 첫 편집 시 `dayPlans[ds] = { mode:'manual', blocks: <현재 자동초안 스냅샷> }` 생성 후 그 위에서 편집(자동초안을 잃지 않게).
- **완료(completions)와의 관계**: 완료 키는 `sid|type`(그날). 수동 블록도 같은 키 체계라 Today/Schedule 체크박스가 그대로 동작. 단, 한 날 같은 sid|type 2블록은 완료 충돌(기존 병합 불변식과 동일) → 편집기에서 **같은 과목 같은 유형 중복 배치 시 병합 또는 경고**.
- **경고**: 그날 배치 합 > 가용 → `over` 표식(빨강). 미배치 복습 등 기존 warnings 유지.

### 6-4. 접근성(드래그 대안)

- 드래그는 Items 카드처럼 **키보드 대안 필수**(WCAG 2.1.1): 블록 포커스 + Alt+↑↓ 시간 이동, Alt+←→ 길이, Enter 편집. 드롭 대신 트레이 항목 Enter→"어디에" 슬롯 선택 폴백.

### 6-5. 월 뷰 — 학습량 히트맵 (2차 결정 ⑦)

월은 시간별 블록을 다 못 담으므로 **하루 = 한 칸 요약**:

- **색농도** = 그날 총 학습 분(`res.days[ds]` 또는 `dayPlans` 배치 합) → 연한색(적음)~진한 과목/액센트색(많음). 빈 날=무색.
- **마감 플래그** = 그날 마감인 과목/할일(네온 점·이름 툴팁).
- **미완 할일 점** = `tasks(ds, !done)` 수 배지.
- 날짜 클릭 → **일 뷰로 진입**(그날 편집). 오늘 칸 강조. 6주 그리드(월요일 시작, `DOW_MON` 일관).
- 순수 파생 read라 저비용 — 스케줄러 재계산 없이 `useSchedule` 결과 + `tasks` 집계만.

```
 월  화  수  목  금  토  일
█23 ██  █   ██  █●          ← 진함=학습량, ● =미완 할일, 밑줄 이름=마감
 4h  6h  2h  5h  3h
```

## 12. 재개편 v2 — 주간 배분 보드 중심 (2026-07-18, 2차 사용자 피드백)

> 트리거: 사용자(2026-07-18) — "조잡하고 중심이 없다. 계획 탭에서도 중심이 한눈에 일정 보여주면서 거기서 짜는 느낌으로. 과목 주당 시간을 정하면 배치 탭에서 요일에 배분(3h → 월2·목1)하면 할당 끝, 이런 느낌인데 그게 아니다. UX/UI도 개판."
> 확정 결정(2026-07-18, v2): **①중심=주간 배분 보드(과목×요일 그리드)** **②배분 주기=매주 새로(반복 템플릿 아님)** **③자동엔진=배분이 주도, 엔진은 복습/Anki/모의만 그 위에 자동 추가.**

### 12-1. v1이 놓친 것 — '주간 배분' 층의 부재

v1(§1~§11)은 전략(주당h·챕터)→투두→**하루 타임박스**로 이었다. 하지만 그 사이 **"이번 주 과목 예산을 요일에 배분"하는 층**이 없다. 그래서:

- `PlanHost`가 `<Navigate to="/schedule">` 한 줄 → 계획을 열면 **하루 타임라인**에 떨어짐(한눈 조망 불가 · "중심 없음"의 실체).
- 주당h→요일 분배는 `scheduler.ts` step5(`perWeek`·마감우선·인터리빙)의 **블랙박스 자동**뿐 — 사용자가 "월2·목1" 손으로 배분하는 면이 없음("효능 없는 계획표"의 실체).
- 세그먼트(뼈대·과목·배치) → 뷰(일·주·월) → 트레이/타임라인 **3중 중첩**으로 위계가 흐림("탭 배치 개판").

### 12-2. 신설: 주간 배분 보드 (계획의 홈·중심)

**단일 질문: "이번 주, 어느 과목을 어느 요일에 얼마씩?"** — 과목(행) × 요일(열=월~일) 매트릭스.

```
주간 배분 보드                     이번주 24.0h / 가용 31.5h   [이전 주 복사] [자동 제안]
        월    화    수    목    금    토   일  │ 주당(배분/예산)
물리   ██2h        ██2h        █1h   ·    ·  │ 5.0 / 5h  ✓
수학    ·   █1.5h   ·   █1.5h   ·    ·    ·  │ 3.0 / 3h  ✓
영어    ·    ·    █1h    ·    █1h   ·    ·  │ 2.0 / 4h  ⚠ 2h 남음
       ───────────────────────────────────────
가용   5.0  4.5   6.0  4.5   5.0  3.0 3.5  │  (열 합 > 가용이면 빨강)
```

- **셀 = 그 과목·그 요일 배분(분)**. 입력(0.5h 스텝) 또는 과목 "잔여 예산 칩"을 요일 칸에 드래그.
- **행 끝 리드아웃**: 배분합/주당예산 — 맞으면 ✓, 부족/초과 경고("Nh 남음").
- **열 아래 리드아웃**: 그 요일 배분합 vs 가용(뼈대 파생) — 초과 시 열 빨강.
- **상단 리드아웃(탭재설계 사상)**: 이번주 배분 총 h / 가용 h / 가장 가까운 마감.
- **[이전 주 복사]**: per-week지만 편의 — 지난 주 배분 벡터를 이번 주로. **[자동 제안]**: 엔진 초안 배분(현 step5 산출을 요일별로 집계)으로 채움.
- **드릴다운(온디맨드 세부)**: 셀/요일 헤더 클릭 → 그날 **일 편집기(DayPlanner)** 로 진입(그 배분을 하루 안 몇 시에 타임박스). 즉 보드=전략 중심, DayPlanner/주캘린더/월히트맵=전술 드릴다운.

### 12-3. 데이터 모델 — 주간 배분(per-week)

```ts
// schema.ts — 옵셔널·passthrough(무마이그레이션). 키=weekMon(ISO, 월요일) → sid → 7요일 분(index=wd, 0=일..6=토)
export const WeekAllocSchema = z.record(
  // weekMon → { sid → number[7] (분) }
  z.record(z.array(z.number()).length(7)),
);
// AppStateSchema: weekAlloc: z.record(...).optional()
```

- `dayPlans`(그날 배치의 진리)와 **직교**: `weekAlloc`=주간 **분배 예산**(어느 요일에 얼마), `dayPlans`=그날 **시각 배치**(몇 시에). 보드에서 배분 → 필요 시 DayPlanner에서 타임박스.
- **매주 새로**: 반복 템플릿 없음. 주별 독립 레코드. 미배분 주는 자동(아래 불변식).

### 12-4. 엔진 통합 — 배분이 주도, 무배분 주는 불변

**dayPlans 패턴을 주(週) 층으로 일반화한다.** `schedule()` step5(주 단위 학습 모듈 배분)를 다음으로 대체:

1. 그 주 `weekAlloc[wk]`가 **있으면(managed week)**: 그 주 weekly 과목은 **전부 배분 벡터로 구동** — 각 (sid,wd)에 `alloc[sid][wd]`분만큼 `new` 블록을 그날에 배치(`advance()`로 챕터 포인터 전진, 같은 sid|new 병합). 배분에 없는 sid는 그 주 0. 복습 씨앗은 **배치된 covered 챕터에서 기존 offsets 로직 그대로**(변경 없음).
2. `weekAlloc[wk]`가 **없으면**: 현 step5 자동(`perWeek`·마감우선·인터리빙) **100% 그대로** → **무배분 시 자동 산출 불변**(회귀 고정 전제, `scheduler.test.ts`).
3. daily(Anki)·복습 배치(step6)·백지(6.5)·모의(6.6)·`applyDayPlans`(6.9)·`layoutDay`는 **무변경** — 배분은 step5의 `new` 소스만 교체.

→ 규칙 #4(파괴 금지) 보존: 엔진은 복습 사다리·Anki·모의·적응형·마감통계·.ics를 그대로 소유. 배분은 `new` 학습 블록의 **요일 분배 결정권**만 사용자에게 넘긴다.

- **보드 초기값 = 자동 파생**: 무배분 주 보드는 `res.days`의 그 주 `new` 블록 분을 (sid,wd)로 집계해 표시(=현 자동 분배가 곧 시작점). **첫 편집 시 그 스냅샷을 `weekAlloc[wk]`로 승격**(dayPlans `ensureManual` 동형). 이후 그 주는 managed.
- **챕터 소진/마감 가드**: 배분이 `_dlIdx` 초과 요일이거나 `chaptersLeft` false면 그 셀은 무효(경고). 배분 총합이 챕터 총량 초과해도 클램프 안 함 — 보드에서 "주당 예산 초과" 경고만(기존 사상).

### 12-5. IA 정리 — 3중 중첩 해소

- **계획 홈 = 배분 보드**(PlanHost `Navigate` 제거, 보드를 기본 세그먼트로). "한눈 조망 + 짜기"를 착지 즉시.
- **배치 세그먼트 뷰 = [배분·주·일·월]**: 기본=**배분**(보드). 주=`WeekCalendar`(시간그리드), 일=`DayPlanner`(타임박스 드릴다운), 월=`MonthHeatmap`. 카드뷰는 이미 제거됨(§1-2).
- **뼈대·과목**은 셋업 세그먼트로 유지(§5-1·5-2). 배분 보드가 스타.
- **Today "오늘 계획 짜기"** → 배분 보드(그 주)로 재타깃(§7 목적지 갱신).
