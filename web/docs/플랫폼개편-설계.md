> ⚠ **max-lines 래칫은 6단계에서 반드시 깨진다** — Tailwind 는 CSS 를 JSX 로 옮겨 줄 수·줄 길이를 늘린다. 재기준선 시점을 §6에 명시.

**0-G 상세 — 과목 색 파생 키 (미결정).**

### 1단계 — Tauri 셸 이사

**목표**: Tauri 2 셸이 현 `web/dist` 를 로드. `serve.js` 는 sidecar 로 유지.

**차단 전제(모두 충족 전 착수 금지)**
1. **0-E ③ 완료** — 백업 범위 정정. 미완 시 데이터 영구 유실.
2. **사용자 데이터 수동 이관 플로우 확정** — WebView2 ↔ Chrome 오리진 분리로 **자동 이관 경로가 물리적으로 없다**. 기존 앱에서 전체 내보내기 → Tauri 첫 실행 시 가져오기. 릴리스 노트 필수 항목.
3. **Rust 툴체인** — `rustc`/`cargo` 1.97.1 ✅ 설치됨. MSVC 빌드도구는 첫 `tauri build` 에서 확인.

**v2 신설 작업 — `WORK` 경로 결정 전략** ⚠
`serve.js:32-33` 이 `WORK = path.dirname(__dirname)` = `D:\atelier` 로 워크스페이스를 **실행 위치에서 추론**한다. 파이썬 도구 11종이 전부 이 cwd 로 돌고(`serve.js:157,203`), 아티팩트 6종 경로도 여기 기준(`serve.js:71-76`)이다.
Tauri 앱은 설치 경로에 놓이므로 **1단계에서 이미 이 추론이 깨진다**(sidecar serve.js 의 `__dirname` 이 설치 경로가 됨).
→ **워크스페이스 경로를 설정값으로 승격**: 최초 실행 시 폴더 선택 → 저장 · 기존 사용자 자동 추론 후 확인 · 폴더 이동 시 복구 UX. `gen-artifacts.mjs:34-37` 의 하드코딩 경로와 **한 곳으로 통합**할 기회.
> **따라서 "1단계 = 기능 변화 0"은 성립하지 않는다.** v1 의 이 표현을 **"프런트 회귀 0 + 셸/경로 설정 신규"**로 정정한다.

**v2 정정 — 완료 기준(순환 논증 제거)**
v1 은 "e2e 스냅샷이 100% 동일 동작을 증명한다"고 썼다. **성립하지 않는다** — Playwright 는 Chromium 으로 `vite preview`(`playwright.config.ts:31-36`)를 찍는데 Tauri 렌더러는 **WebView2** 다. 스냅샷 59장이 전부 녹색이어도 WebView2 에서 깨져 있을 수 있고, "무효화되는 도구로 무효화되지 않았음을 증명"하는 순환이다.
→ **e2e 2트랙 분리**:
- **트랙 A (기존 유지)** — Playwright + `vite preview`. 같은 `dist` 를 로드하므로 **프런트 회귀 검증에 계속 유효**. 비주얼 회귀 전용.
- **트랙 B (신설)** — `tauri-driver`(WebDriver, Windows 는 Edge WebDriver 경유 · **WebdriverIO 스택**) 로 셸 스모크 소수. 창 뜸 · 라우팅 · IPC 왕복 · 종료 시 flush.

**완료 기준**: 트랙 A 59장 무변경 · 트랙 B 스모크 통과 · `tauri build` 성공 · 수동 이관 플로우 1회 왕복 검증.

**부수 작업**: `러닝허브_실행.bat` 의 4기능 흡수 — 포트 8000 stale 서버 강제종료(`:11-17`) → `tauri-plugin-single-instance` · 조건부 재빌드(`:20-21`) → dev 모드 · 헬스체크 폴링(`:40-45`) → sidecar 준비 대기 · Chrome `--app=` 실행(`:48-57`) → WebView2 가 대체. `chcp 65001`/`PYTHONIOENCODING` 짝은 Rust spawn 에 승계.

### 2단계 — SQLite 데이터 모델 (최대 레버)

`AppState` 35슬라이스 → SQLite(`tauri-plugin-sql`). **I1(export/import JSON 계약) 유지**, 내부 저장만 교체. 양방향 검증 구간(JSON 경로와 SQL 경로 동시 수행 후 대조) 뒤 JSON 경로 제거.

**동시 해소**: 5MB 절벽 · 편집당 전량 재직렬화 · `selectors.ts` 수동 캐시 3종 · `migrate`/`sanitizeImported` 이중 유지 · 벡터 캐시 전량 재직렬화(`semantic.ts`).
**신규 획득**: FTS5 노트 검색 · sqlite-vec 벡터 인덱스.

**v2 신설 — 동기/비동기 계약 파괴** ⚠ 가장 위험
`persistence.ts:389` `storage.setItem` 은 **동기**인데 Rust `invoke` 는 **비동기**다. 그리고 `useApp.ts:136-141` 의 언로드 안전망이 `pagehide`/`visibilitychange` **동기 flush** 에 걸려 있는데, **Tauri 창 닫기에서 `pagehide` 발화가 보장되지 않는다**. 둘이 겹치면 400ms 디바운스 대기 중 편집이 유실된다.

## 10. 탈락시킨 대안

- **원격 서버 + DB** — 내구성만이면 **앱이 소유한 로컬 파일**(2단계)이 더 안전하고 싸다. 그리고 원격으로 가도 **볼트는 여전히 로컬**이다(`knowledge/` 마크다운을 이 기계에서 Obsidian 으로 편집하고 `pipeline/` 파이썬이 직접 읽는다 — 동기하려면 Dropbox 를 직접 만드는 일). 네트워크 노출은 인증·세션·CSRF·TLS·백업 운영을 사용자 1명을 위해 세우게 한다.
- **Next.js/RSC** — 서버 유무와 무관하게 값이 없다: SEO 없음 · 낯선 방문자 없음 · 사용자 1명이라 SSR 이 아낄 TTFB 가 없음 · **렌더할 데이터가 서버에 없다**(소유권이 클라이언트).
- **OPFS + wa-sqlite(WASM) + Worker** — Rust 없이 SQLite·Worker 이득을 대부분 얻는 유력 후보. 탈락: 2프로세스 실행이 남고 **File System Access API 에 watch 가 없어 파일 감시가 불가능**(§4-3단계가 제품 성격 변경이라 판단한 기능).
- **Electron** — 무겁고 Node 런타임을 안고 간다.
- **SonarQube Server/Cloud** — 룰은 `eslint-plugin-sonarjs` 로 인프라 0에 얻는다(§0-F). 서버가 더 주는 건 대시보드·추세뿐이고 Cloud 는 소스가 제3자로 나간다. 추세가 필요해지면 나중에 얹어도 룰 엔진이 같아 재작업 없음.
- **전면 재작성** — N1. 고점을 내리는 유일한 경로.
- **Tailwind 를 "안 함"** — 원래 판단이었으나 **사용자 지시로 6단계 채택**. 근거 정정도 기록: 처음엔 "레이아웃 기하가 복잡해 Tailwind 가 약하다"고 했으나 실측하니 calc/clamp/grid 는 158개(2%)뿐이라 **그 논거는 틀렸다**. 실제 마찰은 관계형 셀렉터 1,904개다.
