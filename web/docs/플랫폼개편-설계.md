## 0. 한 줄 요약

이 앱의 남은 구조적 결함은 **거의 전부 한 뿌리에서 나온다 — 데스크톱 워크로드를 브라우저 샌드박스 안에서 돌리고 있고, 앱 데이터가 JSON 덩어리 하나다.** 프레임워크 선택(React 19 · Vite · zustand · CSS Modules)과 도메인 로직(`features/` 27k LOC, `lib/scheduler/`)은 손대지 않고, **그 아래 플랫폼과 데이터 모델만** 교체한다.

```
                 지금                              목표
셸        브라우저 + 배치파일 2프로세스    →   Tauri 2 단일 바이너리
프런트    React19 · Vite · zustand        →   그대로 (무변경)
스타일    CSS Modules 54개 + ds/tokens    →   Tailwind v4 (@theme=tokens) · 6단계
앱 데이터  localStorage JSON 블롭 1개       →   SQLite 테이블
볼트      메인스레드 풀스캔, 수동 버튼      →   Rust 증분 스캔 + 파일 감시
백엔드    serve.js 816줄(무테스트)         →   Rust 커맨드 + Python sidecar
모바일    없음                            →   읽기 전용 뷰(5단계 · 방식 미결정)
```

## 1. 문제 진단 — 왜 이 둘인가

### 1-1. 감사 결과 요약 (2026-07-19)

강점(유지): React Compiler 실동작(`useMemoCache` 출력물 확인) · `noUncheckedIndexedAccess` strict TS에 `any` 0·`@ts-ignore` 0 · `eslint-plugin-boundaries` error 강제 · zustand 전체구독 0건 · 23탭 전부 코드 스플리팅 · `prefers-reduced-motion` 28파일 · `invariants.test.ts`의 Proxy 기반 불변식 잠금.

갭 8종과 그 뿌리:

| ① | Web Worker 0건 — 볼트 스캔이 메인스레드 풀스캔, 증분 없음, 취소 불가 | 샌드박스 |

**①④⑤⑦은 샌드박스·백엔드 구조에서, ②는 데이터 모델에서 나온다. ③⑥⑧만 독립적이다.**

### 1-2. JSON 블롭이 만든 파생 결함

`AppState`는 35개 슬라이스가 든 JSON 덩어리 하나(`persistence.ts` `study_planner_v3`)다. 여기서 파생된 것:

- **5MB 절벽** — `completions`·`retentionLog`·`cbms`·`summaries`·`blankResults`가 append-only인데 롤오프·아카이빙이 없다. `navigator.storage.estimate()` 0건이라 **벽에 부딪힌 순간에야** 알게 된다(그 경고마저 30초 스로틀).
- **편집 1회 = 전량 재직렬화.**
- **`selectors.ts`의 수동 18슬라이스 튜플 캐시**(`selectors.ts:47-58`) — 쿼리가 불가능하니 `schedule()`이 읽는 슬라이스 전량을 손으로 나열해 참조 비교한다. 정교하지만 **본질적으로 SQL 인덱스의 대용품**이다.
- **`selectStudyMinByWeekday`·`selectRiskSummary`는 루트 참조 캐시** — 요약 한 글자 편집에도 days×items×chapters 전수 스캔이 다시 돈다.
- **`semantic.ts`의 벡터 캐시가 저장마다 전체 재직렬화** — 1000항목이면 매번 10~20MB `JSON.stringify`가 메인스레드에서.
- **`AppStateSchema`(선언)와 `migrate`/`sanitizeImported`(손코딩)의 이중 유지** — 이미 드리프트가 있다(`tasks`가 `ACTIVITY_KEYS`엔 있고 `sanitizeImported` 방어엔 없다 → 손상 백업의 `tasks[].start`가 문자열이면 캘린더 산술이 NaN).

### 1-3. 비목표 (명시적으로 하지 않는 것)

- **N1. `features/` 27,219줄 재작성 금지.** 스케줄러 엔진·간격반복·일편집기 좌표·학위요건에 수년치 디버깅이 박혀 있고, 주석이 실제 회귀를 기록한다. 다시 쓰면 그 사고를 다시 겪는다. 갈아엎기가 고점을 **내리는** 유일한 경로.
- **N2. 프런트 프레임워크 교체 금지.** React 19 + Vite + zustand 는 이 앱에 정답이다. Next.js/RSC·Redux/Jotai 는 순손실(§6). **단 CSS 레이어는 예외 — 사용자 지시로 Tailwind 전환을 6단계에 넣었다(§3-6).**
- **N3. Python 파이프라인 재작성 금지.** `pipeline/`은 별도 repo이고 Python이 맞다. Tauri sidecar로 계속 spawn한다.
- **N4. 다중 사용자·원격 접근 범위 밖.** 지금도 `127.0.0.1` 바인딩 + Host/Origin 가드가 전제다.

### 2-1. 파일 감시가 제품 성격을 바꾼다

`notify` 크레이트 기반 볼트 감시는 성능 개선이 아니라 **인터랙션 모델의 변경**이다. 지금은 탭을 열고 버튼을 눌러야 볼트 상태가 갱신된다. 감시가 붙으면 볼트에서 노트를 쓰는 즉시 대시보드가 반응한다 — "가끔 확인하는 대시보드"에서 "항상 맞는 대시보드"로.

### 2-2. Rust를 쓰는 곳 / 안 쓰는 곳

Tauri = Rust 전면이 아니다. 공식 플러그인으로 TS만 쓰고 넘어가는 영역이 넓다.

**Rust 불필요 (TS만)** — 아티팩트 읽기(`plugin-fs`) · 앱 데이터(`plugin-sql`) · Ollama/뉴스 호출(`plugin-http`) · 창·트레이·단축키

**Rust 필요** — 볼트 증분 스캔(성능이 목적) · 파일 감시(`notify`) · 파이썬 spawn의 인자 검증·동시성 캡 · **Windows 손자 프로세스 트리킬** · 리서치 잡 모델

하필 Rust가 필요한 구간이 serve.js에서 회귀를 가장 많이 겪은 곳이다 → **0단계-A(회귀 테스트)가 4단계의 전제조건**인 이유.

## 3. 이행 계획 — 4단계 + 선행 0단계

원칙: **각 단계가 독립적으로 릴리스 가능하고, 어디서 멈춰도 동작하는 앱이 남는다.** 빅뱅 금지.

### 0단계 — 플랫폼 무관 선행 (Rust 불필요, Tauri 결정과 독립)

이 단계 산출물은 **Tauri로 가든 안 가든 100% 재사용**된다(`web/src`가 그대로 가므로). 낭비 0.

- **0-A. serve.js 회귀 테스트** ← 4단계 전제조건
  주석에만 있는 방어를 테스트로 잠근다: `readBody` UTF-8 청크 경계 · 경로 traversal 403(형제 폴더 `dist-backup` 탈출 포함) · `Object.hasOwn` 프로토타입 가드 · 동시성 캡 증감/해제 멱등 · 화이트리스트 밖 도구/아티팩트 거부 · dash 접두 인자 거부 · `killTree` 손자 정리 · SPA 폴백/캐시 헤더.
  **이 테스트가 곧 Rust 포팅의 동등성 명세다.**
- **0-B. zod 4 + 경계 파싱** — zod 3.25→4(번들·파싱 성능 개선, vendor 청크 55KB gz의 상당 부분이 zod). 그 위에 아티팩트 8종 파싱 도입. `schema.ts`↔`persistence.ts` 드리프트(`tasks` 방어 누락) 정정 + `invariants.test.ts`로 두 목록 일치를 잠금.
- **0-C. 값싼 게이트** — `eslint-plugin-jsx-a11y`(aria 406회 수작업 관리 중, 회귀 방어 0) · `bundle-budget.mjs`에 CSS 예산(`:20`이 `.js`만 계측, CSS 361KB 무게이트) · Renovate(의존성 2 메이저 정체의 재발 방지) · `aria-modal` 선언 대비 포커스 트랩 누락 2곳(`Graph.tsx`·`ArticlePractice.tsx`) 확인·정정.

### 1단계 — 셸 이사 (기능 변화 0)

Tauri 2 스캐폴딩 + 현 `web/dist`를 그대로 로드. **serve.js는 sidecar로 살려둔다** — 이 단계에서 백엔드를 건드리지 않는 것이 핵심.

**완료 기준: 앱이 100% 동일하게 동작한다.** e2e 스냅샷이 그것을 증명한다. 기능 변화가 0이므로 실패하면 원인이 셸에 국한된다.

> ⚠ **선행 조건(사용자 작업)**: Rust 툴체인 미설치 확인됨(`rustc`·`cargo` 없음, `D:\atelier` 전체에 `.rs` 0개). rustup + MSVC 빌드도구 설치 필요. WebView2는 Win11 기본 탑재.

### 2단계 — 데이터 모델 전환 (최대 레버)

`AppState` 35슬라이스 → SQLite 스키마. **`persistence.ts`의 export/import 계약(전체 JSON 형태)은 유지**하고 내부 저장만 교체 — 백업 호환성이 불변식.

동시에 해소: ② 5MB 절벽 · 전량 재직렬화 · `selectors.ts` 수동 캐시 3종 · `migrate`/`sanitizeImported` 이중 유지 · 벡터 캐시 재직렬화.
신규 획득: FTS5 노트 검색 · sqlite-vec 벡터 인덱스.

이행 중 **양방향 검증 구간**을 둔다 — 같은 읽기를 JSON 경로와 SQL 경로로 동시 수행해 결과가 일치하는지 대조한 뒤 JSON 경로를 제거한다.

### 3단계 — 볼트를 Rust로

`lib/vault.ts` 풀스캔 → Rust `walkdir`+`rayon` + mtime 증분 + `notify` 감시. ①이 해소되고 검색이 생긴다.
함께 정정: 폴백 스캔이 깊이 2단 고정이라 **챕터 하위 폴더 노트가 조용히 누락**되던 결함(`vault.ts:116-148` vs 인덱스 경로의 임의 깊이 처리 — 두 경로가 서로 다른 볼트 구조를 지원하며 그 차이가 미문서화).

### 4단계 — serve.js 해체

0-A의 테스트를 동등성 기준으로, 파이썬 도구 spawn·잡 모델·동시성 캡을 Rust 커맨드로 이관. Ollama는 `plugin-http` 직접 호출. 잡 상태는 SQLite(④ 해소). `serve.js` 삭제 + `러닝허브_실행.bat` 은퇴.

### 5단계 — LAN 읽기 전용 뷰(모바일 조회)

> 사용자 결정(2026-07-19): "폰/태블릿에서 **조회만**" — 편집은 PC, 이동 중엔 오늘 일정·복습 확인 정도.

이 요구는 **원격 서버도 Next.js도 부르지 않는다.** 4단계가 이미 로컬 HTTP 서버(Rust)를 세우므로 그 위의 작은 확장이다.

```
[PC] Tauri 앱 ── SQLite(정본) ── Rust HTTP ──(같은 LAN)── [폰] 브라우저: 읽기 전용
```

- **모바일 UI는 이미 있다** — e2e 스냅샷에 `today/schedule/stats/items · mobile` 이 있고 브레이크포인트(560/700/900)도 잡혀 있다. **같은 React 앱을 읽기 전용 모드로** 띄운다(별도 코드베이스 금지).
- **동기화 없음** — 폰이 PC 의 SQLite 를 직접 읽으므로 정본이 하나다. 충돌 해소·머지 로직이 아예 필요 없다.
- **제약(수용)**: PC 가 켜져 있어야 한다. PC 꺼진 상태에서도 봐야 한다면 그건 스냅샷 푸시라는 다른 설계이고, 그때 비로소 원격 저장소가 정당해진다.
- **보안 표면 확대(주의)**: 지금 모델은 `127.0.0.1` 바인딩 한 줄이다. LAN 노출은 `0.0.0.0` 바인딩 + 토큰 + **읽기/쓰기 라우트 분리**를 요구한다 — 조회 경로가 실수로 쓰기를 허용하면 안 된다. 4단계 Rust 서버 설계 때 라우트를 처음부터 read/write 로 갈라둔다.

> **미결정(2026-07-19)**: PC 가 꺼진 상태에서도 봐야 한다는 요구가 추가됐다. 이 경우 **항상 켜져 있어야 하는 건 '앱'이 아니라 '읽기 전용 스냅샷'** 이라 DB·인증·동기화가 여전히 불필요하고 정적 호스팅으로 끝난다. 두 후보 — ⓐ **PWA 오프라인 캐시**(LAN 에서 1회 로드 후 오프라인 열람. 데이터가 외부로 안 나감·무료·무유지보수. 한계=마지막 접속 시점 데이터. 은퇴시킨 SW 를 이 용도로만 부활) ⓑ **클라우드 스냅샷 푸시**(어디서나 최신. 대가=개인 학습 기록 사본이 제3자 인프라에 생김 — 되돌리기 어려우므로 사용자 결정 사항). 배타적이지 않다(ⓐ 먼저, 부족하면 ⓑ 를 얹음 · 스냅샷 형식 공유라 낭비 없음). **5단계 착수 시점에 실제 불편을 보고 정한다.**

> **왜 서버+Next.js 가 아닌가**(2026-07-19 검토): 내구성과 다기기는 다른 문제다. 내구성만이면 **앱이 소유한 로컬 파일**(2단계 SQLite)이 서버보다 안전하고 싸다. 그리고 원격 서버로 가도 **볼트는 여전히 로컬**이다 — `knowledge/` 마크다운 수천 개를 이 기계에서 Obsidian 으로 편집하고 `pipeline/` 파이썬이 직접 읽으므로, 서버는 볼트를 볼 수 없다(동기하려면 Dropbox 를 직접 만드는 일이 된다). 게다가 네트워크 노출은 인증·세션·CSRF·TLS·백업 운영을 사용자 1명을 위해 전부 세우게 한다. Next.js 는 그와 별개로도 값이 없다 — SEO 없음, 낯선 방문자 없음, 사용자 1명이라 SSR 이 아낄 TTFB 가 없다.

### 6단계 — CSS Modules → Tailwind v4 전환

> **사용자 지시(2026-07-19)**: "계획서에 Tailwind CSS 로 대체하는 것까지 해서 업데이트."
> **기록해두는 반대 논거**(규칙 #4 는 지시를 뒤집지 말라는 것이지 근거를 지우라는 게 아니다 — 나중에 이 판단을 되짚을 사람을 위해 남긴다): 아래 §6-3 의 위험이 실재한다. 그럼에도 진행하되, 위험을 *없는 셈 치지 않고* 설계로 관리한다.

#### 6-1. 실측한 전환 난이도

`*.module.css` 54개, 총 **8,053 선언**:

| 구분 | 개수 | Tailwind 적합도 |
|---|---|---|
| color·font-size·display·background | 2,196 | ◎ 유틸리티 스위트스팟 |
| padding·gap·border-radius·flex·align-items | 1,488 | ◎ |
| `var(--토큰)` 참조 | 2,159 | ○ v4 `@theme` 로 거의 직역 |
| calc/clamp/minmax | 77 | ○ arbitrary value |
| 그리드 배치 | 81 | ○ |
| **복합·상태 셀렉터** | **1,904** | **✗ 여기가 전부다** |

즉 **~47% 는 기계적 치환**이고, 난이도는 전부 `1,904`에 몰려 있다. `.card:hover .cardTools` · `.seg > button` · `ds.card` 의 `nth-child` 스태거 · `focus-within` 툴바 같은 **관계형 스타일**은 1:1 치환이 불가능하고 `group-*`/`peer-*`/`data-[]:` 로 **JSX 구조를 다시 짜야** 한다.

#### 6-2. 이 전환이 실제로 해결하는 것

- **죽은 CSS 소멸** — 지금 모듈 54개·소스 340KB 중 무엇이 미사용인지 알려주는 장치가 0이다. 유틸리티는 안 쓰면 애초에 안 실린다.
- **네이밍 비용 제거** — `.cardMain`/`.cardTools`/`.durStep` 류의 작명이 사라진다.
- **토큰 규율 유지** — `tokens.css` 의 115개 변수를 v4 `@theme` 로 옮기면 PALETTE 인덱스 파생·액센트 노브(절대규칙 #3)가 그대로 산다.

#### 6-3. 위험과 완화 (없는 셈 치지 않는다)

| 위험 | 완화 |
|---|---|
| **e2e 시각 검증망 소실** — 66개 스냅샷을 한꺼번에 재생성하면 "픽셀이 변했다"가 더 이상 신호가 아니게 된다. 가장 위험한 변경 중에 회귀 감지가 0이 됨 | **feature 단위 점진 전환.** 한 번에 한 feature 만, 그 feature 의 스냅샷만 재생성하고 **diff 를 눈으로 확인**한 뒤 커밋. 나머지 스냅샷은 계속 살아 있어야 한다(다른 feature 가 틀어지면 그건 진짜 회귀) |
| **`결정로그` 의 픽셀 결정이 조용히 뒤집힘** — 고정 행 높이·바탕 틴트 제거·시간당 44px 하한·칩 캡과 "+N개 더" 등은 사용자가 직접 지시하고 되돌리기까지 한 것들이다(규칙 #4) | feature 전환 PR 마다 `결정로그` 의 해당 항목을 체크리스트로 첨부. 스냅샷 diff 로 검증 |
| **1,904 관계형 셀렉터의 JSX 재작성** = `features/` 를 건드림 (N1 이 금지한 재작성과 경계가 가깝다) | **스타일만 바꾸고 로직·구조는 보존**하는 것을 계약으로. `group-*` 도입으로 래퍼가 필요하면 추가는 하되 컴포넌트 분해·상태 흐름은 불변. 단위 테스트 752개가 통과해야 함 |
| stylelint 의 규약 강제(생 hex 금지·브레이크포인트 3종)가 무력화 | Tailwind 테마로 이관 + `eslint-plugin-better-tailwindcss` 로 임의값(`[#fff]`) 사용을 error 로 차단 |

#### 6-4. 순서 제약 (중요)

**1~5단계와 겹치면 안 된다.** 1단계는 "기능 변화 0"을 e2e 스냅샷으로 증명하는 것이 핵심인데, Tailwind 전환은 스냅샷을 대량 재생성한다 — 둘이 섞이면 스냅샷 차이가 어느 쪽 원인인지 분간이 불가능해진다(0단계-D 에서 의존성 메이저를 1단계 앞으로 당긴 것과 **같은 이유**).

→ **플랫폼 이행(1~4단계) 완료 후 착수.** CSS 는 Tauri 와 직교하므로 미루는 비용이 없고(1~4단계는 새 feature 를 만들지 않아 CSS 가 늘지 않는다), 그때는 셸이 안정돼 스냅샷 기준선이 신뢰할 만하다.

#### 6-5. 전환 경로

1. Tailwind v4 도입 + `tokens.css` → `@theme` 이관. **기존 CSS Modules 와 공존**(v4 는 레이어 분리로 가능).
2. `ds.module.css`(712줄)를 **줄어드는 호환 레이어**로 취급 — 새 코드는 유틸리티, 기존은 그대로.
3. feature 1개씩 전환 → 그 feature 스냅샷만 재생성 → diff 확인 → 커밋. `골든/` 레퍼런스 feature 부터(스타일 앵커라 규약이 여기서 정해진다).
4. 모듈이 빈 파일이 되면 삭제. `ds.module.css` 가 0줄이 되면 종료.
5. stylelint 역할을 Tailwind 린트로 이관, `bundle-budget` 의 CSS 예산을 하향 조정(유틸리티는 훨씬 작아야 정상).

## 4. 불변식 (전 단계 공통)

이행 중 어느 단계에서도 깨면 안 되는 것:

- **I1. 백업 호환** — `exportSnapshot` JSON은 기존 백업을 읽을 수 있어야 하고, 내보낸 것은 기존 앱이 읽을 수 있어야 한다(2단계의 핵심 제약).
- **I2. 레이어 단방향** — `eslint-plugin-boundaries` error 유지. Tauri 호출은 `lib/`가 소유(React 무관 IO의 정의).
- **I3. 스케줄러 산출 동형** — `scheduler.test` 42케이스는 전 단계에서 그대로 통과해야 한다. 데이터 저장소가 바뀌어도 스케줄 결과는 불변.
- **I4. 게이트 녹색** — `npm run verify` + `e2e` + `budget`. CI도 함께 갱신.
- **I5. 규칙 #4 (명시 지시 보존)** — 사용자가 못박은 UI 결정(배분 보드 고정 행 높이, 바탕 틴트 제거, 블록 색 유지 등 `결정로그.md`)은 플랫폼 이행이 뒤집지 않는다.

## 6. 탈락시킨 대안

- **OPFS + wa-sqlite(WASM) + Web Worker** — Rust 없이 SQLite·Worker 이득을 대부분 얻는 유력 후보. 탈락 이유: 2프로세스 배치파일 실행이 그대로 남고, **File System Access API에 watch가 없어 파일 감시가 불가능**하다(§2-1이 제품 성격 변경이라 판단한 기능). "고점" 기준에서 결정적.
- **Electron** — 무겁고 Node 런타임을 여전히 안고 간다. 로컬 도구엔 Tauri 우위.
- **전면 재작성** — N1 참조. 고점을 내리는 유일한 경로.
- **Tailwind 를 "안 함"** — 원래 이 문서의 판단이었으나 **사용자 지시로 6단계에 채택**(§3-6). 판단 근거의 정정도 기록해둔다: 처음엔 "레이아웃 기하가 복잡해 Tailwind 가 약하다"고 했는데 실측하니 calc/clamp/grid 는 158개(2%)뿐이라 **그 논거는 틀렸다**. 실제 마찰은 관계형 셀렉터 1,904개다.
- **serve.js를 Hono/Fastify로** — 미들웨어 보일러플레이트(⑦)는 해소되나 4단계에서 삭제될 코드에 대한 투자. 0-A 테스트로 대체.
