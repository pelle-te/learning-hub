# 평가 루브릭 — web 품질 채점의 SSOT

**목적:** "이 변경/기능이 좋아졌나"를 _수치로_ 재는 채점 기준. 게이트(`verify`/`e2e` — 결정론 통과/실패)·리뷰(`리뷰템플릿.md` — 정성 발견)와 달리, 이 루브릭은 **점수(0~5)**를 매겨 변화의 *방향과 크기*를 추적한다. 

> ⚠⚠ **2026-08-20 — `점수` 모드와 `web-evaluator` 는 은퇴했다.** 이 루브릭은 폐기되지 않았지만
> **자동 채점 창구가 없다.** 지금 이 문서를 쓰는 곳은 둘이다:
> ① 사람이 직접 채점할 때 ② `/리뷰 규약` 이 "무엇으로 품질을 재고 있나"를 판정할 때.
> 발견의 우선순위는 이제 점수가 아니라 **원장의 심각도·비용**이 진다(`web/docs/원장.md`).
>
> **분업**
>
> - **게이트**(`/게이트`) — 기계적 통과/실패. 단계 정본은 `web/scripts/gate.mjs` 의 `ALL`.
> - **감사**(`/리뷰 <축>`) — 결함 _발견_ → 원장 append. 축은 코드·성능·ux·데이터·규약.
> - **실행**(`/실행`) — 원장을 닫는 유일한 명령.

**5점 앵커 = `골든/`이 가리키는 레퍼런스**(feature=`features/today`, lib=`lib/scheduler`·`lib/utils` 같은 검증된 순수모듈). 채점은 아래 절대 기준이되, 애매하면 골든을 5점 레퍼런스로 삼는다.

---

## A. Feature/탭 루브릭 (7차원 · 각 0~5 · 합 /35)

각 차원은 **증거 한 줄**(어느 파일:라인·어느 동작이 근거인지)과 함께 점수를 매긴다. **증거 없는 점수는 무효.**

### 1. 정확성·견고성

로직이 옳고, 경계·null·빈 배열·async 레이스·상태 무효화가 안전한가. persist 계약(flush 병합·split/merge 대칭) 유지하나.

- **5** 경계·에러 경로까지 옳고 테스트가 방어. **3** 정상 경로는 옳으나 엣지 1~2 미처리. **1** 재현 가능한 버그 존재(레이스·무효화 오류). **0** 핵심 동작이 틀림.
- **측정 타당도(§가드):** *실패 시나리오(입력→잘못된 출력)를 짚거나 테스트로 확인*했을 때만 채점. 코드 훑고 "괜찮아 보임"은 측정 아님 → `N/A`.

### 2. UX·재설계 사상 충실 (`protocols/탭재설계.md`)

단일 목적·상단 리드아웃·fill 프레임·온디맨드 세부에 부합하나. **빈/로딩/에러 상태가 1급**(EmptyState)인가. 정보 위계가 "0.5초에 요지"인가.

- **5** 한 화면에 단일 목적, 리드아웃이 핵심을 즉시 전달, 3-상태 완비. **3** 기능은 되나 위계 평평·세부 과다 노출. **1** 스크롤 흩뿌림·빈 상태 방치. **0** 목적 불명·깨진 상태.
- 사용자가 못박은 제약이 있으면 그것이 사상보다 우선(어긴 게 아니라 존중이면 감점 아님).

### 3. 접근성 (a11y)

키보드 도달·포커스 순서/트랩·aria(current/label, 역할 정직성)·reduced-motion 백스톱·대비.

- **5** 키보드만으로 완전 조작·aria 정확·reduced-motion 존중. **3** 대체로 되나 포커스/aria 한둘 누락. **1** 키보드 함정·가짜 role. **0** 스크린리더/키보드 사용 불가.

### 4. 디자인 시스템 충실 (`디자인시스템.md`)

토큰·`ds`/module 사용, **전역 클래스 신설 0**, 액센트·다크/라이트 **양쪽** 정상, 픽셀 일관성.

- **5** 토큰만 사용·양 테마·양 액센트 검증·전역클래스 0. **3** 대체로 토큰이나 하드코딩 값 1~2. **1** 임의 색/간격 다수·한 테마만. **0** DS 이탈.

### 5. 레이어·재사용·단순성 (`아키텍처.md` §1)

boundaries 단방향 준수, 계산 로직은 `lib` 순수함수로 분리, 중복 0, 과설계 없음.

- **5** 경계 준수·로직 lib 분리·중복 0·읽기 쉬움. **3** 대체로, 컴포넌트 내 인라인 계산 한둘. **1** boundaries 위반 또는 중복 로직. **0** 뒤엉킨 결합.

### 6. 성능

불필요 재렌더 유발(Rules of React 위반→컴파일러 bail), 렌더 경로의 무거운 계산, 번들/청크 영향.

- **5** 낭비 렌더 0·무거운 계산 메모/lib·번들 예산 내. **3** 사소한 낭비. **1** 명백한 재렌더 폭발 또는 예산 초과. **0** 체감 저하.
- **측정 타당도:** `npm run budget`·React DevTools/프로파일 등 _실제 증거_ 있을 때만. 추정만이면 `N/A`.

### 7. 테스트·검증가능성

단위(lib)·컴포넌트·e2e가 이 기능을 덮나. 회귀 방어·엣지 포함·커버리지 유지.

- **5** 정상+엣지+회귀 테스트, 커버리지 유지. **3** 정상 경로만 테스트. **1** 테스트 희박·커버리지 하락. **0** 미검증 로직 병합.

## B. Lib 모듈 루브릭 (순수 로직 · 5차원 · 합 /25)

`lib/`은 UI·사상·DS가 없어 A의 2·3·4가 안 맞는다 → 이 5차원으로 분기.

### 1. 정확성 (검산·테스트)

입출력이 옳고 경계·불변식이 성립하나.

- **5** 전 케이스 옳고 테스트/검산 통과. **3** 정상 옳으나 엣지 1~2. **1** 재현 버그. **0** 핵심 오류.
- **측정 타당도:** 테스트 실행·검산 증거 있을 때만. 없으면 `N/A`.

### 2. 순수성·경계 격리

React/DOM/전역 상태 무의존, IO는 주입/경유(`api`·`idb`·`kv`), 결정성.

- **5** 완전 순수·부수효과 격리. **3** 대체로, 숨은 결합 1개. **1** 렌더/전역에 몰래 의존. **0** 부수효과 뒤엉킴.

### 3. 견고성 (에러·엣지 경로)

잘못된 입력·IO 실패·빈 값에서 안전하게 실패하나(무음 손상 아님).

- **5** 모든 실패 경로 처리·zod 등 경계 검증. **3** 주요 경로만. **1** 손상 데이터 통과. **0** 크래시/무음 오염.

### 4. 테스트 커버 (엣지 포함)

- **5** 정상+경계+에러+회귀. **3** 정상+일부 엣지. **1** 정상만. **0** 없음.

### 5. 단순·명료

- **5** 최소 표면·명료한 이름·과설계 0. **3** 약간 장황. **1** 불필요한 추상/복잡. **0** 난독.

## 점수 집계

- 대상 점수 = 차원 합 /만점 → **백분율**. **차원이 `N/A`(미측정)면 그 차원을 분모에서 빼고 명시**(예: `28/30 (성능 N/A)`). 미측정을 만점으로 채워 부풀리지 마라 — _가장 무거운 결함_.
- 표본(탭 여러 개·모듈 여러 개) 점수 = 평균 + **차원별 평균**(어느 차원이 약한지 드러나게).
- 기록은 `평가기록.md`에 날짜·범위·커밋과 함께 누적 — **추세가 핵심**(절대값보다 델타). `[feature]`/`[lib]` 분기 표기(만점 다름 → % 로 비교).

## 사용 원칙 (엄수)

- **두 모드.** ① _생성 중 자기점검_ — 만들며 빠르게 훑어 약한 차원을 보강(목표: 갭 조기 발견). ② _검사(감사)_ — 독립 채점. **채점자는 그 코드를 만들지 않은 독립 서브에이전트**(작업자≠검사자 · web-evaluator). 자기 코드 자기채점은 확증편향.
- **증거 필수·타당도 가드.** 실제 대조/실행 증거 없이 매긴 점수는 무효. 특히 차원 1(정확성)·6(성능)·7·B1·B4는 *실행/측정 증거*가 없으면 `N/A`(만점 금지).
- **⚠️ 점수는 모델 판단이라 공유 맹점을 가진다.** 같은 베이스 모델이 못 보는 결함은 채점도 못 본다 — 점수를 *절대 진리*로 과신하지 말고 **추세 진단**으로. **사람 교차검증이 진짜 평가자**(루브릭은 보조). 사람이 잡은 결함은 회귀처럼 누적해 다음엔 게이트/린트/테스트가 잡게 한다.
- **점수를 위해 과적합하지 마라.** 루브릭은 *진단*이지 목표함수가 아니다 — 5점을 위해 군더더기 추상/불필요 테스트를 끼우면 차원 5(단순)에서 깎인다(자정 설계).
- **티어 가중.** 매일 쓰는 핵심 탭(today·schedule·items…)은 차원 2·3·4의 바를 _더 높게_. 드묾·숨김 보조 탭은 가벼워도 감점하지 않는다(균일 투자 강제 금지 — 비대화 방지). 티어 부정합(핵심인데 얕음/보조인데 비대)은 그 자체로 감점 사유.
- **차원 부족하면 추가하되 날씬하게** — 루브릭 본문은 짧게, 사례는 `평가기록.md` 회귀로 보강.
