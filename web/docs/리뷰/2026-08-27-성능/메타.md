# 메타 — 성능 팩 자신을 검증한다 (2026-08-27)

1. **팩이 시켰는데 못 한 것** — `P023` 잔여(히트맵 글로우 **페인트**)를 또 못 쟀다: 그 화면은
   `artifact_read('ledger')` **성공** 픽스처가 있어야 렌더된다. `[지시가 모호함]` ⭐ 팩의
   _"돌려서 재는 것만 본다"_ 가 **«그 화면을 띄우는 것부터가 일이다»** 를 예상하지 않는다 —
   측정 대상이 기본 하네스에서 렌더조차 안 될 때의 절차가 없다.
2. **팩이 안 시켰는데 해야 했던 것** — ① **계측기 분담**(메인이 chrome-devtools MCP 를 점유하고
   하위축들에 다른 포트·도구를 배정). 안 했으면 셋이 같은 브라우저와 4173 을 두고 충돌했다.
   ② **실측 원문의 보존 정책** — 트레이스 21.5 MB 를 그냥 커밋할 뻔했고, 그건 이 회차 자신이
   찾은 `P032`(잔여 43 MiB)를 절반 태우는 일이었다.
3. **거짓 양성을 유발한 지시** — _"이 팩의 단일 규율: `[측정]`/`[재현]` 만"_ 이 **역방향으로**
   샜다: 수치가 나오면 그 수치의 **조건**을 안 따지게 된다. 실제 사고 셋 — 메인의 「폰트 92.3%」는
   SW 활성 상태의 분모였고(정본 56.6%), 「부팅 LCP 197→443ms」는 회차 간 편차였으며(재측정 284/232/392),
   축1 의 「부팅 웨이브가 어느 게이트에서도 실행된 적 없다」는 `clock.install` 을 안 쓰는 가드
   둘을 안 본 것이었다. **팩에 «수치마다 조건을 병기하라»가 없다.**
4. **예산이 어디로 갔나** — 축1(체감) 46분 · 137툴 → 지적 3 · 유지 6. 축2(비용) 36분 · 103툴 →
   지적 3 · 기각 6. 축3(예산) 11분 · 44툴 → 지적 4 · 잔재 0. 메인 → 지적 3(그중 `P028` 은 축1 과
   병합) · 진보 6행. **어느 하위축도 0건이 아니다.**
5. **표본 대조** — **됐다.** web.dev CWV(임계·백분위) · Lighthouse CI 설정 문서(`resource-summary`
   종류/개수 예산 · `maxNumericValue` · 이력 서버) · Pretendard 배포 산출물(92슬라이스 CSS +
   `HEAD` 로 실 크기)을 전부 열었고 URL·확인일을 달았다. `ⓓ=없음` **6행 중 5행**.
