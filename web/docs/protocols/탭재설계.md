# 프로토콜: 탭 재설계

> 트리거: "(탭) 재설계 / 다시 디자인". **today 탭에서 확정된 재설계 사상**을 각 탭 기능에 맞게 이식한다. today를 복붙하지 말고 그 *사상*을 적용.

## 재설계 사상 (today에서 확정 · 불변)

1. **단일 목적 · 한 화면** — 탭은 한 가지 핵심 질문에만 답한다. 스크롤로 흩뿌리지 말고 한 화면에 담는다.
2. **상단 리드아웃** — 가장 중요한 숫자·상태를 화면 최상단에 크게(오늘 히어로처럼). 사용자가 0.5초 안에 "지금 뭐가 중요한가"를 읽는다.
3. **fill 프레임** — 화면을 꽉 채우는 컬럼/그리드 프레임. 여백에 늘어진 카드가 아니라 짜인 레이아웃.
4. **온디맨드 세부** — 세부·부가 정보는 기본 접힘. 필요할 때 펼치거나 호버로 노출. 첫 화면은 요지만.

> ⚠️ **명시 지시 임의변경 금지**: 사용자가 특정 탭에 대해 못박은 결정(레이아웃·색·요소)은 이 사상보다 우선. 재설계는 그 제약 안에서.
> ⚠️ Phase C 실패 교훈: "기존 화면을 전체창에 늘리기"는 재설계가 아니다. 각 탭의 *기능*을 사상에 맞게 다시 구성하는 것.
> 라임 액센트 기본 확정. 다크+라이트 2테마 유지.

## 절차

1. **그 탭의 단일 목적 정의** — 이 탭이 답하는 한 문장 질문은? (예: 통계="내 학습이 늘고 있나", 스케줄="이번 주 뭘 언제")
2. **리드아웃 선정** — 그 질문의 답이 되는 핵심 지표 1~3개를 상단 히어로로.
3. **fill 프레임 설계** — 나머지를 채우는 컬럼/그리드. 각 영역은 목적에 종속.
4. **세부 온디맨드화** — 부가 정보는 접기/호버/세그먼트로.
5. **DS 준수** — 토큰·액센트·컴포넌트 규격은 `web/docs/디자인시스템.md`. 새 전역 클래스 만들지 말고 `*.module.css` + ds 토큰.
6. **a11y·반응형** — reduced-motion 백스톱, 모바일 하단탭 레이아웃 유지. EmptyState 1급 지원.
7. **게이트 + 스냅샷** — `npm run verify` + `npm run e2e:update`(시각 변경이라 스냅샷 재생성 필요) + `npm run build`.

## 참고

- 레퍼런스 구현: `web/docs/골든/`이 가리키는 탭(스타일 앵커).
- 큰 재설계는 서브에이전트로 단계 분리(설계→구현→검증)해 정밀도 유지.
