# 릴리스 — 배포본 만들기와 **자동 업데이트 전달**

> **이 문서가 SSOT 인 것**: 서명키 취급 · 릴리스 아티팩트 · `latest.json` · 업데이트가 사용자에게 닿는 경로.
> 설계 근거는 `src-tauri/src/updater.rs` 머리주석, UI 는 `web/src/features/settings/UpdateCard.tsx`.

## 0. 왜 이게 생겼나 (2026-07-25)

같은 감사에서 **텔레메트리**(`/api/log` · 런북 §7-7)를 넣어 배포 후 결함을 _알게 되는_ 경로를 만들었다. 그런데 그 수정을 **전달할** 경로가 없었다 — 배포가 NSIS 인스톨러 수동 재설치뿐이었다.

> **관측과 전달은 짝이다.** 한쪽만 있으면 다른 쪽이 무의미해진다: 고칠 것을 몰라도 배포 경로만 있으면 쓸 데가 없고, **결함을 알게 됐는데 전달할 방법이 없으면 관측이 좌절만 만든다.** 종전이 후자였다.

---

## 1. ⚠⚠ 서명키 — 이 문서에서 가장 중요한 절

업데이트는 **서명된 것만** 설치된다. 공개키는 `src-tauri/tauri.conf.json` 의 `plugins.updater.pubkey` 에 박혀 배포본마다 고정되고, 개인키로 서명하지 않은 업데이트는 클라이언트가 **거부**한다.

| 파일                         | 무엇       | 취급                                                            |
| ---------------------------- | ---------- | --------------------------------------------------------------- |
| `src-tauri/.updater-key`     | **개인키** | ⚠ 커밋 금지(`.gitignore` 59행) · **오프라인 백업 필수**         |
| `src-tauri/.updater-key.pub` | 공개키     | 커밋 안 하지만 비밀 아님(값은 `tauri.conf.json` 에 이미 들어감) |

**두 방향으로 모두 위험하다 — 어느 쪽도 나중에 복구할 수 없다:**

- **유출되면**: 이 앱의 업데이트를 **사칭**할 수 있다. 사용자 PC 에서 임의 코드가 도는 것과 같다. CI 의 `secret-scan` 잡(gitleaks · 전 이력 스캔)이 뒤늦게 잡지만, push 된 시점에 이미 유출이다.
- **잃어버리면**: 이 앱에 **다시는 업데이트를 배포할 수 없다.** 새 키로 서명한 업데이트는 기존 사용자가 거부한다. 남는 길은 새 공개키를 박은 빌드를 만들어 **손으로 재설치시키는 것**뿐이다.

> ✅ **지금 해야 할 일 하나**: `src-tauri/.updater-key` 를 이 저장소 **밖**(비밀번호 관리자 · 오프라인 저장소)에 백업하세요. 이 파일은 재생성할 수 없습니다.

키를 처음부터 다시 만들어야 한다면(유출 등):

```bash
npx tauri signer generate -w src-tauri/.updater-key
# 출력된 공개키를 src-tauri/tauri.conf.json 의 plugins.updater.pubkey 에 붙여넣는다.
# ⚠ 이 시점에 기존 배포본은 앞으로의 업데이트를 전부 거부한다 — 사용자 재설치가 필요하다.
```

## 2. 릴리스 절차

### 2-1. 버전 올리기 — **두 곳이 같아야 한다**

```
src-tauri/tauri.conf.json   "version": "0.2.0"
src-tauri/Cargo.toml        version = "0.2.0"
```

⚠ 업데이터는 **`tauri.conf.json` 의 버전**을 현재 버전으로 보고 `latest.json` 의 값과 비교한다. 둘이 어긋나면 "새 버전이 있다"고 잘못 말하거나 반대로 침묵한다.

### 2-2. 게이트 통과 후 서명 빌드

```bash
# 게이트가 먼저다 — CLAUDE.md '게이트' 절이 SSOT
cd web && npm run gate && cd ..

# 서명 빌드. 환경변수 두 개가 서명을 켠다(없으면 서명 없이 나가고 업데이트가 안 붙는다).
export TAURI_SIGNING_PRIVATE_KEY="$(cat src-tauri/.updater-key)"
export TAURI_SIGNING_PRIVATE_KEY_PASSWORD=""      # 키 생성 시 비밀번호를 안 걸었으면 빈 문자열
npm run tauri:build
```

⚠ **`tauri:build:fast`(`--no-bundle`)를 쓰지 말 것.** 그건 개발 루프용이고 인스톨러·업데이트 아티팩트를 안 만든다(루트 `package.json` 의 `_주석:build:fast`).

산출물(`src-tauri/target/release/bundle/nsis/`):

| 파일                               | 무엇                                                |
| ---------------------------------- | --------------------------------------------------- |
| `러닝허브_0.2.0_x64-setup.exe`     | 신규 설치용 인스톨러                                |
| `러닝허브_0.2.0_x64-setup.exe.sig` | **서명** — `createUpdaterArtifacts: true` 가 만든다 |

⚠ `.sig` 가 없으면 서명 환경변수가 안 걸린 것이다. 그 상태로 릴리스하면 **모든 클라이언트가 업데이트를 거부**한다.

### 2-3. `latest.json` 만들기

업데이터가 읽는 파일이다. `tauri.conf.json` 의 `endpoints` 가 이 URL 을 가리킨다.

```json
{
  "version": "0.2.0",
  "notes": "사용자가 설치 전에 읽는 릴리스 노트. UpdateCard 가 그대로 보여 준다.",
  "pub_date": "2026-08-01T00:00:00Z",
  "platforms": {
    "windows-x86_64": {
      "signature": "<러닝허브_0.2.0_x64-setup.exe.sig 파일의 내용 전체>",
      "url": "https://github.com/pelle-te/learning-hub/releases/download/v0.2.0/러닝허브_0.2.0_x64-setup.exe"
    }
  }
}
```

⚠ `signature` 는 `.sig` **파일 경로가 아니라 내용**이다. ⚠ `notes` 는 사용자가 실제로 읽는다 — "두 번째 클릭"의 값이 여기서 나온다(무엇이 바뀌는지 모르고 누르는 설치는 자동 설치와 다르지 않다).

### 2-4. GitHub Release 에 올리기

```bash
gh release create v0.2.0 \
  "src-tauri/target/release/bundle/nsis/러닝허브_0.2.0_x64-setup.exe" \
  latest.json \
  --title "v0.2.0" --notes-file RELEASE_NOTES.md
```

⚠ **저장소가 비공개면 이 방식은 동작하지 않는다.** `endpoints` URL 이 인증을 요구하게 되고 업데이터는 토큰을 싣지 않는다. 대안 둘:

1. 공개 릴리스 전용 저장소를 따로 둔다.
2. `latest.json` 과 인스톨러를 **Workers 오리진**에 정적 자산으로 올린다 — 이미 같은 오리진에서 폰 웹앱을 서빙하고 있으므로(런북 §7-6) 추가 호스팅이 0 이다. 그때 `endpoints` 를 그 URL 로 바꾼다.

## 3. 사용자에게 닿는 경로

설정 → **앱 업데이트** → `업데이트 확인` → (있으면 버전·릴리스 노트 표시) → `내려받아 설치하고 재시작`.

⚠ **부팅 시 자동 확인을 하지 않는다.** 배지로 재촉하지 않고, 자동으로 받지도 설치하지도 않는다. 근거는 `updater.rs` 머리주석 — 이 앱은 학습 세션 중에 켜져 있고, 진행 중인 집중 타이머·미저장 3문장 요약이 있는 상태의 자동 재시작이 이 앱에서 가장 나쁜 실패다.

---

## 4. CI 에서 서명하려면 (선택)

지금은 릴리스를 **로컬에서** 낸다. CI 로 옮기려면 시크릿 두 개를 등록한다:

| 시크릿                               | 값                                 |
| ------------------------------------ | ---------------------------------- |
| `TAURI_SIGNING_PRIVATE_KEY`          | `src-tauri/.updater-key` 파일 내용 |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | 키 비밀번호(안 걸었으면 빈 문자열) |

⚠ 그렇게 하면 **개인키가 GitHub 에 산다.** 저장소·조직이 침해되면 서명 능력이 함께 간다. 1인 프로젝트에서 로컬 릴리스가 몇 분 걸리는 것과 비교해 이 위험이 값을 하는지 먼저 판단할 것 — 지금은 **일부러 로컬**이다.
