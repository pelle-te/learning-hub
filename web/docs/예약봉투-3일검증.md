# 예약 봉투 — 3일 화물 검증 (P-13 · 2026-08-01)

> **인프라를 짓기 전에 화물부터.** 이 문서는 기능 설계서가 아니라 **하나의 가설을 3일 만에 죽이거나
> 살리는 절차**다. 설계 스케치는 `로드맵.md` 의 P-13 이 갖고 있고, 여기 있는 것은 "손으로 뭘 하는가"뿐이다.

## 0. 이 검증이 묻는 것 — 딱 한 문장

> **앱이 이미 계산해 둔 결정**("오늘 첫 블록은 회로이론 2장 · 09:00 · 복습 12개 대기")이 아침에
> 폰으로 도착했을 때, 그것이 **결정으로 읽히는가 잔소리로 읽히는가.**

⚠⚠ **반박이 이 한 줄에 전부 걸려 있다.** 로드맵은 이 항목을 **두 번 기각**했고(`폰 Web Push — 드롭
유지` · `FocusChip` 주석의 _"'마감 알림도 넣자'는 재제안은 이 주석 한 줄로 끝난다"_) **그 기각은 당시
옳았다** — 논거가 _"푸시할 유일한 내용이 넛지"_ 였기 때문이다. 바뀐 것은 지반이다: (d)축(앱이 먼저
말을 건다)이 2026-07-31 에 **사용자가 직접 고른 성공 정의**가 됐고, 이 안의 화물은 넛지가 아니라
**이미 계산된 결정**이라 임계도 권유도 새 계산도 없다. **그 구분이 실감되지 않으면 기각이 여전히
옳고 이 안은 폐기다.**

## 1. ⚠⚠ 실측이 로드맵의 방법을 뒤집었다 (2026-08-01)

로드맵 P-13 의 "가장 싼 검증"은 이렇게 적혀 있었다: _"폰에 알림 권한만 받고 3일간 손으로 `curl`
1발/일"_. **그 방법은 지금 코드에서 성립하지 않는다.**

| 확인한 것                        | 결과                                                                 |
| -------------------------------- | -------------------------------------------------------------------- |
| 폰에 서비스워커가 있는가         | **있다** — `selfDestroying:false` · Workers 오리진에만 붙는다        |
| 그 SW 에 `push` 핸들러가 있는가  | **없다** — `generateSW` 전략이고 커스텀 SW 소스가 저장소에 아예 없다 |
| `pushManager`·`setAppBadge` 참조 | **0건**                                                              |

즉 **Web Push 를 쏴도 표시할 코드가 없다.** curl 을 성공적으로 보내도 화면에는 아무 일도 안 일어나거나
브라우저 기본 문구("이 사이트가 백그라운드에서 업데이트되었습니다")가 뜬다 — 후자를 보고 "화물이
잔소리로 읽혔다"고 판정하면 **틀린 것을 재는 것**이다.

그리고 `push` 핸들러를 넣으려면 `generateSW` → `injectManifest` 전환이나 `importScripts` 가 필요한데,
그건 **인프라를 먼저 짓는 것**이고 이 항목이 명시적으로 금지한 순서다(_"인프라를 먼저 지으면
매몰비용이 판단을 오염시킨다"_).

**→ 그래서 전송을 바꾼다. 검증 대상은 전송이 아니라 화물이다.**

## 2. 절차 — 3일, 코드 0줄

전송은 **폰 자체의 알림(리마인더/알람)** 을 쓴다. 앱이 아니라 사람이 예약한다는 점만 다르고,
"아침에 폰 잠금화면에 한 문장이 뜬다"는 **관측하려는 상황과 동일**하다.

### 매일 밤 (PC 끄기 전 · 1분)

1. 러닝허브를 연다. **오늘 탭 하나만 본다.**
2. 화면에 이미 있는 값으로 **한 문장**을 만든다. 아래 형식을 벗어나지 말 것:

   ```
   내일 첫 블록: <과목> <챕터> · <시각> · 복습 <N>개 대기 · <가장 가까운 마감> D-<n>
   ```

   ⚠ **새 계산을 하지 말 것.** 임계·권유·격려 문구를 붙이는 순간 이건 넛지가 되고, 그러면 이 검증이
   재는 대상이 바뀐다. 화면에 없는 수는 쓰지 않는다.
   ⚠ 앱을 안 열었으면 **그날은 봉투가 없다** — 문장을 지어내지 말고 아래 기록표에 `봉투 없음`.
   이건 설계의 일부다(_"조용히 없는 것이 조용히 틀린 것보다 낫다"_).

3. 폰 리마인더에 **다음 날 07:30**(또는 평소 기상 30분 뒤)으로 그 문장을 그대로 예약한다.

### 다음 날 아침 (30초)

알림을 본 **직후에** 아래 표에 세 칸을 채운다. 나중에 몰아 적으면 기억이 결론에 맞춰 재구성된다.

## 5. 살아남았을 때만 — 인프라의 진짜 순서 (지금 짓지 말 것)

로드맵 P-13 이 적은 서버 표면(테이블 1 · cron 핸들러 1 · VAPID 키쌍 1)에 **한 줄이 빠져 있었다**:

0. **SW 에 `push`·`notificationclick` 핸들러**(`generateSW` → `injectManifest` 전환) ← 이것이 0번이다
1. VAPID 키쌍 · 구독 저장
2. D1 봉투 테이블 · cron 핸들러

⚠ cron 의 CPU 상한이 **10ms** 라 서버가 D1 을 훑어 배분을 재계산하는 설계는 원리적으로 못 산다 —
**판단은 로컬 PC 가, 전달만 클라우드가**는 취향이 아니라 제약이다.
⚠ iOS 는 **홈 화면에 설치된 PWA** 에서만 푸시가 된다(Safari 탭에서는 원리적으로 불가).
⚠ 폐기 조건(**14일 열림 0 → 자동 OFF**)의 문구는 **설정 UI 안에 문자로 박는다** — 문서에 적은 폐기
조건은 이 저장소에서 지켜진 적이 없다.
