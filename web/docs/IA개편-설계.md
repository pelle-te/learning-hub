## 1. 무엇이 문제인가 (관측된 것만)

IA 가 **질문**이 아니라 **바이트 출처**로 갈려 있다.

| 탭         | 데이터 출처           | 사용자가 던진 질문   |
| ---------- | --------------------- | -------------------- |
| `mastery`  | 볼트 산출물(지식엔진) | 내가 어디까지 아는가 |
| `ledger`   | 챕터 원장(파이프라인) | 내가 어디까지 아는가 |
| `graph`    | 로컬 items + 지식맵   | 내가 어디까지 아는가 |
| `stats`    | 앱 상태(완료·스트릭)  | 내가 어디까지 아는가 |
| `forecast` | 스케줄 투영           | 내가 어디까지 아는가 |

다섯 화면이 **같은 질문 하나**에 답하는데 사용자는 출처를 모른다 — 그래서 어디를 열어야 할지
매번 다시 배운다. 반대로 장기 시야 3화면(`goals`·`degree`·`atlas`)은 서로 다른 그룹에 흩어져
"내 길은 어디로 가고 있나"를 보려면 세 번 이동한다.

⚠ **이 표는 코드 읽기에서 나온 것이지 관측이 아니다.** 각도 자신의 자기비평이 그것이었고,
그래서 `N-11` 방문 원장이 먼저 들어갔다. 원장은 2026-07-26 에 심었으므로 **아직 데이터가 0**이다.

## 2. 그래서 지금 무엇을 하고 무엇을 안 하는가

**한다 — 근거가 관측 없이도 서는 것만.**

- 같은 호스트에 이미 흡수된 세그먼트 묶음을 **더 늘린다**. 이건 새 IA 가 아니라 **기존
  메커니즘(`SUBTAB_GROUPS`)의 적용**이고, 되돌리기가 한 줄이다.
- 1단계 대상: **`goals`·`degree` → `schedule`(계획) 호스트의 '멀리' 세그먼트.**
  근거: 셋 다 *언제 무엇을 할까*의 시간 축이고(오늘·이번 주·이번 학기), 지금은 그 축이
  레일에서 세 항목으로 쪼개져 있다. 라우트·⌘K·`g` 단축키는 **전부 그대로**다.

**안 한다 — 관측이 필요한 것.**

- `오늘 / 계획 / 기록 / 앎 / 수집 / 시스템` 6목적지 재편 자체. **6 이라는 수와 그 경계는
  내가 정한 것이지 관측된 것이 아니다.** `route_visits` 가 2주 이상 쌓인 뒤 판단한다.
- `ledger` 은퇴, `앎` 호스트 신설: 위와 같은 이유로 보류. (N-2 의 객체 서랍이 `ledger` 의
  존재 이유를 상당 부분 흡수할 수 있어, **N-2 이후에 다시 보는 것이 순서상 맞다**.)

## 3. 1단계 변경 (이번에 출하)

```
SUBTAB_GROUPS: ['schedule', 'alloc', 'items']  →  ['schedule', 'alloc', 'items', 'goals', 'degree']
TabMeta.role:  goals·degree = destination      →  lens
```

- 레일 도달점 **14 → 12**(상단 그룹 11→9 · 하단 설정 3은 불변). 계획 세그먼트는 **3 → 5**.
  ⚠ 이 숫자는 **실 셸 스크린샷에서 센 것**이다(2026-07-26). 처음엔 "9→7"로 적었는데 그건
  어느 집합의 수도 아니었다 — 코드에서 세지 않고 눈대중으로 쓴 값이었다.
- `goals`·`degree` 는 `role:'lens'` 가 되어 레일·`[ ]` 링에서 빠지고 계획 세그먼트로 들어간다.
  ⚠ 불변식 ③-b 가 "lens 는 반드시 어느 세그먼트 그룹에 속한다"를 잠그므로, 두 변경은
  **함께여야 한다**(하나만 하면 테스트가 즉시 빨개진다 — 그게 이 규약의 값이다).
- `g d`(졸업 계획)·`g` 시퀀스·딥링크·⌘K 는 **무변경**. 도달성 손실 0.
